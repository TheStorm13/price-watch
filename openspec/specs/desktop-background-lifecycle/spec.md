# desktop-background-lifecycle Specification

## Purpose

Управляет работой desktop-приложения при закрытом окне и после входа пользователя в графическую сессию, сохраняя доступ к интерфейсу и результатам сбора.

## Requirements

### Requirement: Пользователь управляет фоновым режимом
Приложение SHALL предоставлять в desktop-интерфейсе переключатель фонового режима и сохранять выбранное состояние между запусками. Изначально режим SHALL быть выключен.

#### Scenario: Включение режима
- **WHEN** пользователь включает фоновый режим
- **THEN** приложение сохраняет выбор и регистрирует запуск после следующего входа в графическую сессию

#### Scenario: Отключение режима
- **WHEN** пользователь отключает фоновый режим
- **THEN** приложение сохраняет выбор и убирает регистрацию запуска при входе в систему

### Requirement: Фоновый запуск поднимает службы без видимого окна
При включённом режиме приложение SHALL запускаться после входа пользователя в графическую сессию без видимого окна и запускать службы, необходимые для автоматического сбора.

#### Scenario: Вход в графическую сессию
- **WHEN** пользователь входит в графическую сессию с включённым фоновым режимом
- **THEN** локальные службы и worker запускаются без открытия окна интерфейса

#### Scenario: Сбой запуска служб
- **WHEN** локальные службы не удалось запустить в фоне
- **THEN** ошибка сохраняется в диагностике и отображается при следующем открытии интерфейса с возможностью повторить запуск

### Requirement: Окно можно закрывать независимо от фонового процесса
При включённом фоновом режиме закрытие окна SHALL оставлять приложение и службы работающими; при выключенном режиме закрытие окна SHALL завершать приложение по текущему правилу.

#### Scenario: Закрытие окна при включённом режиме
- **WHEN** пользователь закрывает окно при включённом фоновом режиме
- **THEN** окно скрывается, а автоматический сбор продолжает работать

#### Scenario: Закрытие окна при выключённом режиме
- **WHEN** пользователь закрывает окно при выключённом фоновом режиме
- **THEN** приложение завершает работу и останавливает принадлежащие ему службы

### Requirement: Повторный запуск открывает существующее окно
Приложение SHALL допускать не более одного владельца локальных служб для одного пользователя и SHALL показывать существующее окно при повторном запуске ярлыка.

#### Scenario: Ярлык запущен при работающем фоне
- **WHEN** пользователь запускает price-watch через ярлык при уже работающем фоновом экземпляре
- **THEN** существующее окно показывается и получает фокус без запуска второго комплекта служб

### Requirement: Доступен явный полный выход
Приложение SHALL предоставлять действие полного выхода, которое останавливает его службы, не стирает сохранённые данные и не меняет настройку фонового режима.

#### Scenario: Выход при скрытом или открытом окне
- **WHEN** пользователь выбирает полный выход
- **THEN** приложение останавливает worker и локальные службы и завершает процесс

### Requirement: Фоновые службы восстанавливаются после сбоя worker
Приложение SHALL обнаруживать неожиданное завершение worker во время фоновой работы и повторять попытки запуска с ограниченной частотой, сообщая о продолжающемся сбое в диагностике.

#### Scenario: Worker неожиданно завершился
- **WHEN** worker завершается, а приложение продолжает работать в фоне
- **THEN** приложение пытается восстановить worker и не создаёт второй одновременно работающий worker

#### Scenario: Worker не удаётся восстановить
- **WHEN** повторные попытки восстановления не удаются
- **THEN** причина доступна в диагностике и видна при открытии интерфейса

### Requirement: Интерфейс восстанавливает подключение после перезапуска служб
Приложение SHALL обновлять подключение интерфейса к локальному API после перезапуска служб, даже если адрес или токен API изменился, и SHALL повторно получать актуальные данные.

#### Scenario: Службы перезапущены при открытом окне
- **WHEN** локальный API перезапускается при открытом окне
- **THEN** интерфейс получает новое подключение и обновляет данные без полного перезапуска приложения

#### Scenario: Службы перезапущены при скрытом окне
- **WHEN** локальный API перезапускается при скрытом окне, а затем пользователь открывает интерфейс
- **THEN** интерфейс использует новое подключение и показывает актуальные данные

### Requirement: Сбой локальной службы обрабатывается без потери сохранённой истории
Приложение SHALL обнаруживать остановку локального API, PostgreSQL или Xvfb, восстанавливать работоспособность с ограниченной частотой попыток и сохранять уже записанные наблюдения цен.

#### Scenario: Служба остановилась без активного сбора
- **WHEN** локальный API, PostgreSQL или Xvfb неожиданно останавливается
- **THEN** приложение пытается восстановить службы и сообщает о продолжающемся сбое в диагностике

#### Scenario: Служба остановилась во время сбора
- **WHEN** локальная служба останавливается во время активного сбора
- **THEN** приложение не запускает параллельный worker, сохраняет уже записанные наблюдения и после восстановления помечает прерванный запуск ошибкой, доступной для просмотра и повторения
