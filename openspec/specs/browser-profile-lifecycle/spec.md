# browser-profile-lifecycle Specification

## Purpose

Определяет сохранность пользовательского профиля Chrome при переходах между ручным браузером, сбором цен и полным выходом из приложения.

## Requirements

### Requirement: Управляемый Chrome закрывается штатно
Приложение SHALL перед сбором, после сбора и при полном выходе штатно закрывать управляемый Chrome и ожидать освобождения профиля. Если браузер не отвечает, приложение SHALL ограничить ожидание, сообщить об ошибке или применить диагностируемое аварийное завершение без удаления профиля.

#### Scenario: Пользователь запустил сбор при открытом Chrome приложения
- **WHEN** Chrome приложения использует профиль price-watch
- **THEN** Chrome штатно завершается до запуска Chrome worker с тем же профилем

#### Scenario: Сбор завершился
- **WHEN** worker больше не использует Chrome
- **THEN** Chrome штатно завершён, а сохранённые данные профиля доступны следующему запуску

#### Scenario: Пользователь завершил приложение перед обновлением
- **WHEN** приложение закрывает запущенный им Chrome и выходит
- **THEN** каталог профиля остаётся на месте, а Chrome завершён штатно

### Requirement: Профиль не используется двумя Chrome одновременно
Приложение SHALL удостовериться, что предыдущий Chrome освободил профиль, до открытия следующего Chrome. Завершение SHALL затрагивать только браузер, запущенный с управляемым профилем.

#### Scenario: Профиль остался занят
- **WHEN** Chrome не закрылся в отведённое время
- **THEN** второй Chrome с тем же профилем не запускается, а причина доступна пользователю или в журнале

### Requirement: Коннекторы одного запуска совместно используют Chrome
Смешанный сбор Ozon, AliExpress и Wildberries SHALL использовать один процесс Chrome и один управляемый профиль с отдельной страницей каждой площадки. Завершение работы одного коннектора SHALL NOT закрывать браузер или запросы другого. Последний потребитель SHALL штатно закрывать принадлежащий сбору Chrome с сохранением профиля.

#### Scenario: Смешанный запуск
- **WHEN** один запуск собирает любую комбинацию Ozon, AliExpress и Wildberries
- **THEN** открывается один Chrome, запросы площадок используют свои страницы, а лимит пяти одновременно собираемых карточек сохраняется

#### Scenario: Один коннектор завершился раньше
- **WHEN** у одного коннектора закончились запросы, а у другого ещё есть активные
- **THEN** общая сессия остаётся доступной до завершения второго

#### Scenario: Отмена или ошибка запуска
- **WHEN** запуск отменён или завершился с ошибкой
- **THEN** принадлежащие запуску запросы отменяются и Chrome закрывается штатно; профиль и уже сохранённая история остаются

### Requirement: Проверку площадки выполняет пользователь
CAPTCHA SHALL выполняться пользователем. В видимом Chrome сбор SHALL ожидать подтверждения и затем проверять доступ повторно. Скрытый сбор SHALL сообщать необходимость открыть Chrome приложения и повторить сбор после проверки. Одновременные проверки SHALL согласовываться без перезаписи активного ожидания; UI SHALL называть площадку, запросившую проверку.

#### Scenario: Видимая проверка AliExpress
- **WHEN** AliExpress запрашивает CAPTCHA в видимом браузере
- **THEN** пользователь проходит её вручную, подтверждает продолжение, и сбор повторно проверяет ответ в том же профиле

#### Scenario: Проверка в скрытом режиме
- **WHEN** AliExpress или Wildberries запрашивает CAPTCHA при сборе на скрытом дисплее
- **THEN** цель завершается ошибкой доступа с инструкцией пройти проверку в Chrome приложения и повторить сбор, без записи фиктивной цены

#### Scenario: Подтверждение не помогло
- **WHEN** пользователь подтвердил проверку, но повторная проверка доступа всё ещё заблокирована
- **THEN** сбор сообщает ошибку без бесконечного цикла повторов

#### Scenario: Обе площадки требуют проверки
- **WHEN** две площадки из Ozon, AliExpress и Wildberries одновременно требуют ручного участия
- **THEN** ожидания обслуживаются последовательно, текущее сообщение не подменяется соседним, а отмена запуска прекращает ожидание

#### Scenario: Видимая проверка Wildberries
- **WHEN** Wildberries требует ручной проверки в видимом Chrome
- **THEN** пользователь проходит её и подтверждает продолжение; сбор повторно проверяет готовность данных WB в том же профиле
