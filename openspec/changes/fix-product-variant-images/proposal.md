# Proposal

## Why

Wildberries сейчас возвращает карточки без фотографии. У вариантов товара нет собственного изображения в общем контракте, БД и интерфейсе, а термин SKU в пользовательских подписях непонятен.

## What Changes

- Получать главное фото WB через действующую витрину и передавать его товару и его размерным вариантам.
- Добавить необязательный URL изображения каждого варианта в коннекторный JSON, сохранение, API и перенос данных. Для AliExpress использовать фото соответствующей комбинации свойств, когда оно доступно.
- Показывать миниатюры вариантов на странице товара; корректно обрабатывать отсутствие и ошибку загрузки фото.
- Использовать «Варианты товара», «вариант» и «код варианта» в пользовательских подписях, поиске, графике и сообщениях форм.
- Сохранять существующие идентичности, цены, историю и выбор главного варианта.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `marketplace-product-contract`: необязательные фото вариантов и получение изображения WB.
- `product-variants`: сохранение, обновление и перенос изображений вариантов.
- `desktop-ui-layout`: миниатюры вариантов и понятная терминология.

## Impact

Затрагиваются модели и сериализация коннекторов, WB runtime/mapper, мапперы других площадок по доступным данным, PostgreSQL/Alembic, сохранение результатов, чтение карточек, API, transfer, frontend и demo API. Новых зависимостей не требуется.

Нужна добавочная nullable-колонка фото варианта. Миграция не переписывает исторические snapshot и не создаёт наблюдения цен. Существующее общее фото сохраняется; неизвестные фото вариантов заполняются повторным сбором. Потребители новых полей обновляются вместе; существующие экспорты должны оставаться импортируемыми без потери накопленных данных.

Приёмка: после сбора у WB есть фото; все варианты показывают соответствующие изображения при наличии у источника; одинаковое фото допустимо для размеров одного артикула; разные фото не смешиваются. Изменение только фото сохраняется без дубликата истории. UI не показывает термин SKU. Проверяются браузерный runtime, контракты, БД на отдельной тестовой базе, перенос, UI и оба CLI-импорта/числовой Ozon без DATABASE_URL.
