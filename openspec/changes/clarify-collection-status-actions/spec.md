# Task: Понятный этап обновления цен и приоритет кнопок

## Goal and acceptance criteria

В плашке обновления показывать текущую площадку: «Обработка товаров Ozon»,
затем «Обработка товаров AliExpress», «Обработка товаров Wildberries» или
«Обработка товаров Яндекс Маркет» по фактическому этапу запуска.
Пока площадка ещё неизвестна, использовать «Обработка товаров», без догадки Ozon.
В боковой панели первой расположить синюю кнопку «Обновить все цены»,
второй — обычную outline «Добавить товар». Названия, обработчики и блокировка
обновления при активном сборе сохраняются.

Проверки: frontend component tests для текста, перехода площадки и отсутствия
текста «Подготавливаем запуск»; существующие тесты действий AppShell; визуальная
проверка порядка/цветов; backend regression для этапа до первого результата.
Статусы проверки Chrome, завершения, ошибки, счётчики и прогресс сохраняются.

## Agreed solution

Предложение подготовлено по запросу пользователя 2026-11-12; согласование этой
спецификации до реализации ещё ожидается.

1. Переставить две кнопки AppShell и обменять default/outline, не меняя подписи.
2. В CollectionService отметить первую карточку группы через существующий
   set_run_current перед входом в marketplace collection_session. Убрать прежний
   вызов только для одноэлементной пачки: одну отметку делать на фактический этап.
   Это представитель активной площадки, а не обещание последовательного сбора
   конкретного SKU. Контракты и схема БД не расширяются.
3. В ActiveCollectionPanel показывать название площадки из run.current в строке
   «Обработка товаров …». Не выводить ID как якобы единственный текущий запрос.
   До известного этапа писать «Обработка товаров». При смене площадки строка
   обновляется существующим опросом. Не определять этап по наличию Ozon в каталоге:
   каталог и состав конкретного запуска могут отличаться.
4. Mock должен передавать реальную для своего сценария площадку, не вычислять её
   из прогресса в компоненте. Проверить, нужен ли точечный перенос отметки в mock.

Нет миграций, изменений сохранения цен, порядка площадок или параллелизма.
Общий CollectionService используется queued desktop/API/worker и direct CLI;
проверить эти пути существующими тестами. DB-free numeric JSON mode не использует
эту плашку/запуск, его импорты и поведение сохранить. Native build не запускать.
Обновить соответствующие положения openspec/specs/catalog-sidebar/spec.md и
collection-run-execution/spec.md, а также CURRENT_NUANCES, если описан этот UI.
