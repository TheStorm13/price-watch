# Task: Сохранять настройки отображения каталога

## Goal and acceptance criteria

После полного закрытия и повторного запуска приложения каталог восстанавливает последние настройки отображения. Предлагаемая область — каталог товаров: сортировка (включая колонку и направление), поиск, фильтры наличия, выгодности, маркетплейсов и тегов, флаг приоритета участия, список/сетка и свёрнутые группы.

Критерии и проверки:

1. Изменённые параметры восстанавливаются после нового запуска страницы и нового браузерного контекста с тем же постоянным хранилищем: компонентные тесты и E2E восстановления.
2. Сохраняются сочетания фильтров, несколько площадок/тегов и особое значение «Без тегов»; сортировка по заголовкам восстанавливает направление: тесты сериализации и UI.
3. «Сбросить» сохраняет сброшенные условия после следующего запуска, оставляя выбранный вид и свёрнутые группы: компонентный тест/E2E.
4. Явные настройки ссылки имеют приоритет над сохранёнными; переход в детали и обратно не теряет настройки; кнопки назад/вперёд продолжают работать: тесты маршрутизации.
5. Повреждённое/недоступное хранилище не мешает открыть каталог и пользоваться настройками в текущем сеансе: тесты ошибок чтения/записи и валидации.
6. Постоянное состояние отделено от выделения товаров для массовых действий и открытых диалогов: проверка повторного монтирования.

Период графика, выбор варианта и страница измерений в деталях, временный поиск внутри диалогов, положение прокрутки и восстановление последней открытой страницы в предлагаемую область не входят. Флаги участия товаров в выгодных предложениях — данные товаров, они уже сохраняются через API; их контракт не меняется.

## Agreed solution

Согласовано пользователем ответом «Да» 2026-11-07: область каталога и предложенное локальное хранение, приоритет явной ссылки, сохранение сброса и свёрнутых групп.

Рекомендуется локальное постоянное хранилище фронтенда (`localStorage`) без новых зависимостей, API и миграций базы. Это настройки данного профиля приложения; между устройствами они не синхронизируются и при очистке данных приложения исчезают. Demo и рабочий режим используют разные ключи, чтобы тестовые идентификаторы групп не попадали в рабочие настройки. Хранение на сервере добавило бы контракт и смешало персональное представление с данными каталога без необходимости.

Один версионированный документ, например `{ version: 1, catalogSearch: string, collapsedGroupIds: number[] }`. В `catalogSearch` входят только `q`, `markets`, `tags`, `stock`, `deals`, `participationFirst`, `sort`, `view`. Повторяющиеся значения и пустой выбор тегов сохраняются корректно; регистр и введённый текст поиска не изменяются. Неизвестные поля и недопустимые значения не восстанавливаются; ID групп — уникальные положительные безопасные целые числа.

URL остаётся источником текущих параметров и истории навигации. При первом входе в каталог без явных параметров отображения подставляются сохранённые параметры через replace до показа каталога. Если ссылка содержит хотя бы один известный параметр отображения, весь набор этой ссылки имеет приоритет, отсутствующие параметры принимают значения по умолчанию. Служебные параметры demo/E2E не сохраняются и не теряются при восстановлении. Изменения и сброс сохраняются сразу, без зависимости от обработчика закрытия окна. Восстановление не выполняется повторно после пользовательского сброса и не создаёт цикл URL ↔ storage.

Свёрнутые группы сохраняются отдельно от URL, переживают переход в детали и перезапуск. Удалённые группы игнорируются; не очищать ID по временному пустому каталогу при загрузке/ошибке. Массовое выделение и диалоги остаются временным состоянием.

Обработка ошибок localStorage: безопасное чтение с валидацией, значения по умолчанию при повреждении/неизвестной версии; исключения записи не ломают интерфейс. Гарантия сохранения действует при доступном постоянном хранилище. Изменения документов: `docs/UI_SPECIFICATION.md` — перечень сохраняемых настроек, приоритет ссылки, сброс и границы хранения.
