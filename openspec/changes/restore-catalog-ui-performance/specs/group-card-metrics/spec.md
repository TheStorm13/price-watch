# Spec Delta

## MODIFIED Requirements

### Requirement: Единый представитель группы
API SHALL сохранять выбор представителя по минимальной известной текущей цене полного состава группы с разрешением равенства меньшим ID. Каталог UI SHALL выбирать своего представителя как первого подходящего участника по текущей сортировке после применения всей комбинации фильтров. При равенстве всех ключей выбранного порядка UI SHALL разрешать равенство стабильным ID. Группа без подходящих участников SHALL не показываться в каталоге.

#### Scenario: Разные цены и наличие
- **WHEN** у A цена 80 и unknown, у B цена 100 и in_stock, включён «Только в наличии»
- **THEN** UI показывает группу по B, не меняя сохранённый состав и серверные поля снимка

#### Scenario: Явная сортировка
- **WHEN** пользователь выбирает «Сначала дорогие» и отключает приоритет участвующих
- **THEN** представитель UI — самый дорогой подходящий участник с известной ценой, а неизвестные цены идут в конце

#### Scenario: Равные или отсутствующие цены
- **WHEN** выбрана сортировка по цене, подходящие участники имеют одинаковый статус участия и равные цены либо все их цены отсутствуют
- **THEN** UI разрешает равенство стабильным ID, а API сохраняет выбор меньшего ID

### Requirement: Выгодность представителя и приоритет участников
UI SHALL применять карточечную выгодность к каждому участнику. Фильтр «Выгодные» SHALL оставлять только подходящих выгодных участников, «Невыгодные» — остальных, «Участвуют в выгодных предложениях» — всех включённых в расчёт выгодных независимо от текущей выгодности. Приоритет группы в стандартной сортировке SHALL определяться первым подходящим участником. При явной сортировке столбца SHALL NOT применяться дополнительный приоритет выгодности. Поля серверного снимка SHALL сохранять существующий API-контракт.

#### Scenario: Только более дорогой участник выгоден
- **WHEN** дешёвый участник невыгоден, дорогой выгоден и включён фильтр «Выгодные»
- **THEN** группа видна с дорогим участником и его выгодой, дешёвый участник скрыт

#### Scenario: Представитель исключён из выгодных
- **WHEN** прежний представитель исключён и включён фильтр «Выгодные»
- **THEN** UI выбирает подходящего выгодного участника или скрывает группу, если таких нет

### Requirement: Общие фильтры для объектов каталога
Каталог SHALL проверять каждый отдельный товар и каждого участника группы на всю комбинацию поиска по названию/внешнему артикулу, маркетплейсов, наличия, тегов, участия в выгодных и выгодности. Совпадения разных участников SHALL NOT складываться. Группа SHALL показываться только при наличии совпадений и раскрывать только совпавших участников; подпись SHALL показывать n из m товаров. Доступные теги SHALL собираться из всех карточек, а собственные метаданные группы SHALL не участвовать в товарном фильтре.

#### Scenario: Другой участник совпал с маркетплейсом
- **WHEN** представитель API — Ozon, другой участник Wildberries, выбран только Wildberries
- **THEN** UI показывает группу с участником Wildberries и его товарными полями

#### Scenario: Условия распределены между участниками
- **WHEN** ни один участник не соответствует всей комбинации условий
- **THEN** группа скрыта

#### Scenario: Фильтр по тегу
- **WHEN** товарный тег есть у одного участника, а собственный тег группы не встречается у товаров
- **THEN** первый тег оставляет этого участника, собственный тег не даёт совпадения

#### Scenario: Раскрытие группы
- **WHEN** группа имеет совпадения и пользователь её раскрыл
- **THEN** видны только совпавшие участники с исходными товарными полями

### Requirement: Общая сортировка списка и плитки
UI SHALL сортировать отдельные карточки, группы по текущему представителю и вложенных участников общим компаратором. По умолчанию SHALL сравниваться сначала участие в выгодных, затем выгода по убыванию, затем наличие и цена. Чекбокс приоритета участия SHALL быть включён по умолчанию и ставить участвующих первыми перед выбранной сортировкой; при отключении SHALL применяться только выбранная сортировка. При явной сортировке столбца SHALL сравниваться все товары без приоритета выгодности; null SHALL идти в конце в обоих направлениях внутри каждого блока участия либо общего списка при отключённом приоритете. Порядок SHALL быть стабильным с ключами типа и ID. Сортировка по обновлению SHALL быть удалена. Заголовки колонок SHALL переключать направление сортировки с сохранением порядка в URL и отображением в панели.

#### Scenario: Чередование карточек и групп
- **WHEN** цены отдельной карточки и представителей двух групп равны 80, 70 и 90, выбрана цена по возрастанию и отключён приоритет участия
- **THEN** порядок в списке и сетке — группа 70, карточка 80, группа 90 вне зависимости от их выгодности

#### Scenario: Сортировка по выгоде
- **WHEN** выбрана стандартная сортировка «Сначала выгодные»
- **THEN** подходящие участники сначала упорядочиваются по участию, затем по убыванию выгоды; первый становится представителем UI; заголовок «Выгода» меняет направление внутри блоков участия, а при отключении чекбокса — для всех товаров вместе
