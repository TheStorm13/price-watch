# Task: Ускорить колесико мыши без повторной отправки событий

## Goal and acceptance criteria

Вертикальное колесико мыши прокручивает вдвое дальше за одинаковое число шагов. Нативная прокрутка WebKit сохраняется, включая вложенные области и границы. Тачпад, горизонтальная прокрутка и Ctrl/Shift/Alt/Super/Meta не ускоряются. Обработчик не создаёт дополнительных событий и не порождает поток wheel у границ страницы/вложенной области. Изменение ограничено Linux desktop, данные/API/worker/CLI/JSON mode не затрагиваются.

## Current system and evidence

Единственный потребитель accelerate_mouse_wheel — создание главного WebView в frontend/src-tauri/src/lib.rs. cdc9db5 копирует событие дважды через gtk::main_do_event и останавливает исходное; Cell защищает лишь синхронный повторный вход. В пользовательском прогоне зарегистрированы 1 227 873 записи trusted input (почти все wheel) и timer gap 31280 ms. Подробности и ограничения измерений: ../simplify-interface-copy/spec.md, раздел «Пассивное наблюдение». Исходный logger сам увеличивал нагрузку и заменён числовыми счётчиками.

В WebKit GTK3 webkitWebViewBasePropagateWheelEvent выставляет shouldForwardNextWheelEvent и снова вызывает gtk_main_do_event после асинхронного ответа renderer. shouldForwardWheelEvent снимает этот флаг в стандартном обработчике. Прежний пользовательский перехват останавливает первоначальную доставку, размножая события и нарушая этот путь. Источник: https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/gtk/WebKitWebViewBase.cpp. Контролируемый регрессионный прогон должен подтвердить механизм на установленном WebKitGTK; пользовательский исходный подвисший процесс не является стендом для исправления.

## Agreed solution

В существующем GTK scroll-event сохранить фильтры физического вертикального колеса и модификаторов. Изменять смещение самого входного GdkEventScroll и возвращать Propagation::Proceed: smooth Mouse delta_y ×2, дискретное Up/Down представить smooth с delta_y −2/+2 и delta_x 0. Источник Mouse сохраняет расчёт штатного WebKit шага колеса. Не вызывать gtk_main_do_event, не копировать/генерировать события, не перехватывать DOM scrolling. WebKit самостоятельно обрабатывает hit-testing, вложенный скролл и возврат непрокрученного события в GTK. Для записи полей события нужен минимальный документированный unsafe-мост к mutable GDK C event; время жизни остаётся у GTK, обработка на UI thread, указатель не сохраняется. Удалить Cell и прежнюю реализацию полностью.

Альтернативы: повторная отправка даже одной копии оставляет вмешательство в GTK/WebKit возврат; DOM scrollBy требует собственного выбора скролл-контейнера и меняет native поведение. Выбрано увеличение delta одного входного события. Новых зависимостей и миграций нет. Обновить docs/guide/NATIVE_DESKTOP.md.

Авторизация замены: после конкретного плана одного события с delta ×2 и изолированными проверками пользователь ответил «Давай просто сделаем, а я проверю в реальности на приложении». Реализация разрешена; desktop-сборку/пакет/установку агент не выполняет. Финальную проверку в установленном приложении и приёмку выполняет пользователь.

## Execution state

Замена реализована: один изменённый GdkEventScroll проходит стандартный WebKit handler с Propagation::Proceed; Cell/clone/main_do_event из production удалены. Обновлены NATIVE_DESKTOP.md и TESTING_AND_TROUBLESHOOTING.md. Данные и backend не менялись.

Проверки прошли: cargo check --offline (основной target и --test native_wheel), cargo fmt --check, git diff --check. Новый ignored GTK/WebKit integration test frontend/src-tauri/tests/native_wheel.rs скомпилирован отдельно rustc --test с уже установленными локальными dependencies и запущен под частным Xvfb (desktop app не собиралась). Последний прогон: 1 passed; дискретная дистанция 71 px → 142 px, smooth Mouse delta ×2; вложенная дистанция ×2 без движения родительской страницы. Shift/Ctrl/Alt/Super/Meta и горизонтальное колесо сохраняют baseline delta. На нижней/верхней границе страницы и нижней границе вложенной области: по 20 входных событий дали 20 DOM и 40 GTK доставок (вход + штатный возврат), затем очередь затихла. FFI-тестовый observer останавливает доставку после 500 событий для безопасного провала при регрессии. MESA/DRI3 warning относится к software rendering частного Xvfb.

Для проверки причины тот же стенд отдельно запущен с прежним HEAD-обработчиком в /tmp/pw-wheel-old.rs. Временная копия теста пропускала ранние assert одного DOM wheel (прежняя версия намеренно давала два), чтобы дойти до границ. Прежний обработчик упал на «no DOM event multiplication at boundary»; исправленная production-функция проходит. Таким образом, асинхронное размножение wheel в старой реализации воспроизведено контролируемо, а не только предположено по пользовательским логам. Артефакты /tmp/pw-wheel-regression.log, /tmp/pw-wheel-old-regression.log, /tmp/pw-wheel-fix-check.log, /tmp/pw-wheel-fix-test-check.log. Стенд использует только synthetic HTML, ephemeral WebKit contexts, без БД и пользовательского профиля.

Repowise live change risk: новых production-проблем нет; замечания о длине сценария и unwrap/expect относятся к тесту, где ошибка должна завершать проверку. Широкий E2E run-all предложен из-за отсутствия native-связей в графе; mock E2E не исполняет GTK callback, поэтому вместо него выполнен непосредственный WebKit regression test. Физический тачпад и последний Wayland desktop после замены агентом не проверялись: сборку, установку и реальную проверку пользователь берёт на себя. Не считать исходное пользовательское зависание окончательно закрытым до его проверки новой сборки.

Перед представлением результата: commit task-файлов и обязательное обновление CodeGraph/Repowise/настроенных страниц. После обновления пользователь должен полностью завершить прежний процесс приложения (включая фон/трей) и запустить новую сборку: уже открытое окно остаётся со старым native-кодом. Финальная приёмка не получена, change не архивировать.
