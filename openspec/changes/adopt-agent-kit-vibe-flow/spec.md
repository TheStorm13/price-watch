# Внедрение vibe-flow из agent-kit в price-watch

## Цель и критерии приёмки

Подключить согласованный flow с двумя пользовательскими согласованиями и одной
технической spec.md для новых задач. Коммиты обязательны до предъявления результата
на приёмку и после проверенных исправлений. docs/BACKLOG.md остаётся проектным
списком будущих работ: читать относящиеся пункты, не считать их разрешением на
реализацию, после приёмки актуализировать только связанный пункт; новые идеи —
по запросу пользователя.

Существующие планы и отчёты считаются корректными. Перенести их с вложениями без
переписывания содержания, ревизии состояния и обозначения legacy. Разрешены только
механические исправления ссылок. Действующие руководства, ADR, спецификации и
три существующие задачи OpenSpec сохраняются. Код приложения и данные не меняются.

Приёмка: установленный skill и схема разрешаются настоящими загрузчиками;
повторный agent-kit init не предлагает изменений; глобальный RTK наследуется без
дублирования; сохранность перенесённых материалов подтверждена сравнением байтов
с учётом только преобразований ссылок; пользовательская правка backlog не включена
в коммит; индексы и настроенные страницы обновлены после коммита.

## Текущее устройство и подтверждения

До миграции .agents/skills/vibe-flow содержал локальный SKILL.md. В проекте и HOME
было по одному RTK hook, из-за чего agent-kit отклонял setup. Проектные MCP уже
соответствовали agent-kit; OpenSpec config и generated skills присутствовали.
Оба индекса существуют; Repowise настроен на deterministic pages, mock embedder,
без model/provider и без редакторных AGENTS.md/CLAUDE.md интеграций.

В docs/workflow-runs находятся 84 отслеживаемых материала, включая отчёты,
планы, скриншоты, JSON и логи. Отдельные планы: docs/IMPLEMENTATION_PLAN.md и
чеклист docs/guide/SIDEBAR_IMPLEMENTATION_CHECKLIST.md. Постоянные docs/guide,
docs/adr, docs/architecture и openspec/specs не переформатируются. Прежние
OpenSpec changes demo-sidebar-layouts, cleanup-notifications-and-tests и
edit-card-fields используют spec-driven и остаются в исходной структуре.

## Согласованное решение

Пользователь согласовал внедрение нового flow, коммиты перед приёмкой, перенос
документации без повторной проверки планов и проектные правила backlog. Финальное
разрешение: «Да. ПРиступай» в текущем разговоре (2026-11-07).

Подключить skill и схему ссылками на каталоги в agent-kit; собственные копии не
дублировать. Удалить только дублирующую проектную RTK-интеграцию её родным CLI;
глобальную конфигурацию не менять. Сохранить проектные MCP. Default schema новых
задач — vibe-flow; явная metadata старых задач продолжает выбирать spec-driven.
Добавить правила task к openspec/config.yaml, сохранив контекст и правила старых
артефактов для существующих изменений.

Старые отчёты переместить docs/workflow-runs → docs/tasks с сохранением вложенной
структуры; первоначальный план — в docs/tasks/initial-implementation/plan.md,
чеклист боковой панели — в docs/tasks/adopt-catalog-sidebar/implementation-checklist.md.
Исправить ссылки и добавить навигацию по задачам. Новый flow использует
openspec/changes/<name>/spec.md; после приёмки — OpenSpec archive. Не переводить
старые материалы в этот формат и не менять их утверждения.

Backlog не участвует в жизненном цикле spec/archive. При этой миграции в нём
исправляется только ссылка на перенесённый отчёт; уже существующая пользовательская
правка сохраняется в working tree и не включается в коммит. Семантических изменений
backlog в этой задаче нет.

  ошибок загрузки нет. Запросы к модели не запускались.

Код приложения и данные не менялись, прикладные тесты не запускались.
