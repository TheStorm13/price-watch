## ADDED Requirements

### Requirement: Диагностика загружается только по запросу
Чтение списка запусков и запуска с includeErrors=false SHALL NOT загружать содержимое ошибок из хранилища. Запрос с includeErrors=true SHALL возвращать полную диагностику в сохранённом порядке с прежними полями, включая traceback. Значение includeErrors по умолчанию и HTTP-представление ошибок SHALL сохраняться.

#### Scenario: Массовый сбой и опрос прогресса
- **WHEN** запуск содержит 5000 ошибок и UI запрашивает компактный прогресс
- **THEN** чтение не выбирает диагностические payload, а ответ содержит прежние счётчики и сведения о повторе

#### Scenario: Открытие диагностики
- **WHEN** пользователь запрашивает полный список ошибок запуска
- **THEN** доступны все сохранённые ошибки в исходном порядке, включая общие ошибки без cardId

### Requirement: Ошибка цели записывается один раз и атомарно
Сохранение ошибки SHALL атомарно проверять владельца, завершать pending-цель, обновлять счётчики и добавлять диагностическую запись. Повторная доставка SHALL NOT дублировать ошибку; стоимость добавления SHALL NOT включать переписывание прежних диагностических payload.

#### Scenario: Повторная доставка и потеря lease
- **WHEN** ошибка одной цели доставлена повторно либо прежний исполнитель потерял владение
- **THEN** повторная диагностика и лишнее увеличение failureCount не сохраняются

### Requirement: Перенос диагностики сохраняет существующие запуски
Миграция SHALL переносить все сохранённые ошибки с исходным порядком и содержимым, сохранять запуски, цели, карточки и историю цен. Несоответствие переноса SHALL прерывать транзакцию. Прежнее хранилище SHALL удаляться только после проверки переноса; параллельные старые writers SHALL быть исключены.

#### Scenario: Исторический запуск с общей ошибкой
- **WHEN** мигрирует запуск с несколькими ошибками карточек и общей ошибкой без cardId
- **THEN** полное чтение после миграции возвращает тот же порядок и содержимое, а повтор использует прежний состав целей
