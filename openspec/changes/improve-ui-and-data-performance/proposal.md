# Proposal

## Why

Каталог и редактор групп создают DOM для всех карточек, а изменения прогресса сбора затрагивают весь UI через общий контекст. При росте данных увеличиваются также стоимость чтения ошибок, память экспорта и журналы процессов. Пользователь разрешил взять все найденные задачи производительности, исключив ускорение Ozon.

## What Changes

- PERF-02 и связанная часть ARCH-02: выделить модель каталога и компоненты представления; ограничить DOM списка, сетки и раскрытых групп виртуализацией. Сохранить единый согласованный снимок `/api/catalog`, фильтры, сортировку, выделение и массовые действия.
- Разделить команды сбора и подписки на прогресс, стабилизировать обработчики; мемоизировать дорогие границы UI. Повторно использовать форматтеры дат. Оптимизировать редактор групп и вычисления графика без прореживания сохранённой истории.
- PERF-03: перенести диагностику запусков в отдельные строки, читать её только по запросу. **BREAKING (внутренняя схема):** после проверенного переноса удалить `collection_runs.errors`; перевести все внутренние потребители. Сохранить HTTP-контракт `includeErrors`, lease и атомарность результата.
- PERF-04: ограничить журналы API, PostgreSQL, worker, Xvfb и Chrome при непрерывной работе и после перезапуска; определить одинаковые размер и срок хранения.
- PERF-05: выбирать только экспортируемые столбцы истории и заранее группировать карточки. Сохранить формат и единый REPEATABLE READ снимок; решение о потоковом контракте не включать без доказанной необходимости.
- Добавить воспроизводимые замеры UI/API/ошибок/экспорта и проверки на изолированных данных.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `catalog-snapshot`: проверяемая отзывчивость большого согласованного каталога.
- `desktop-ui-layout`: ограниченная отрисовка списка и сетки, сохранение доступа к карточкам и фокуса.
- `group-member-selection`: отзывчивый выбор большого состава с сохранением скрытого выбора.
- `collection-run-execution`: компактное чтение прогресса и сохранение диагностики при миграции.
- `desktop-runtime-delivery`: ограниченное хранение журналов работающих служб.

## Impact

React features/cards, collection, card-details, общие format helpers; PostgreSQL runs/history/transfer adapters, ports/application/API, Alembic; Rust runtime и общий Chrome session. Добавляется только необходимый headless virtualizer, без замены UI primitives. Ускорение Ozon, частота запросов и параллелизм сборщиков исключены. ARCH-01/04/05 не включены как самостоятельные архитектурные проекты: из обсуждения одобрена только связанная с производительностью часть ARCH-02.

Критерии: bounded DOM при 5000 карточек и в одной большой группе; прогресс не перерисовывает каталог; p95 взаимодействий ≤200 мс на согласованном release-окружении; снижение UI p95 не менее 30% там, где baseline выше 200 мс; полный каталог не регрессирует сверх существующего порога; экспорт идентичен, чтение прогресса не читает диагностику, журналы остаются в заданном бюджете. Числа являются порогами приёмки, не результатами уже выполненных замеров.

Значимые архитектурные решения и альтернативы вынесены в предложенный ADR 0010. Миграция переносит ошибки без удаления диагностических записей, карточек и истории. Проверки БД выполняются только на отдельном disposable TEST_DATABASE_URL.
