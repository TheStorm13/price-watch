# Исправление обнаружения вариантов и владения SKU Ozon

Принято пользователем 2026-11-07: «все ок».
Реализация: `c915611761cb27860d557effb965f2fa96dee430`;
проверки и результат переноса: `0f3d1b6`.

В запуске 255 все 11 ошибок были `VariantDiscoveryIncomplete`: семь из-за
неподдержанного модального продолжения списка, четыре из-за семейств,
разделённых между карточками, созданными до поддержки вариантов Ozon.

Нормализованное получение загружает `aspectModalInfo.link` через тот же транспорт,
проверяет товар, аспект, количество и идентичность SKU, дополняет список без
подмены цены и параметров текущего товара. Объект только с trackingInfo не является
продолжением. Неполный список остаётся видимой ошибкой с сохранением валидной цены.
Raw CLI возвращает неизменённый ответ страницы. Ручной retry не менялся.

Миграция `0021_ozon_sku_ownership` заполняет marketplace вариантов, добавляет
составной FK к площадке владельца и уникальный индекс SKU Ozon. При существующих
дубликатах миграция останавливается без удаления данных. Проверки приложения
сохранены. Уникальность известных SKU не определяет ещё неизвестные связи Ozon;
конфликт обнаружения остаётся защитой, автоматического объединения нет.

По отдельному разрешению пользователя локальные карточки 33 и 68 перенесены
в 32 и 67; затем пустые контейнеры удалены. Сохранены 945 вариантов и 2124
наблюдения, ID, snapshot и время истории; SHA256 неизменяемых полей и всех
исторических run targets до/после совпали. Прежние главные SKU сохранены как
отслеживаемые. Backup: `~/.local/share/price-watch/backups/before-ozon-family-repair-20261107T183517Z.dump`
(1956296 bytes; `pg_restore --list` прошёл).

Проверено: полный Python unittest suite — 302 passed без пропусков на отдельном
UTF-8 PostgreSQL; после финального разбора кода ещё 29 focused tests passed.
Покрыты modal, tracking-only, ошибки продолжения, прямой SQL/конкурентность,
миграция, перенос истории, queued/direct и numeric/raw режимы без БД.
OpenSpec validation, compileall и diff checks прошли. Семь проблемных товаров
проверены live без записи БД: 10/23/8/8/12/15/20 SKU, discovery errors отсутствуют.
Четыре SKU исправленных семейств проверены без конфликтов владельцев.

На момент передачи результата установленный backend оставался старым: локальная
БД получила только DEFERRABLE history FK для переноса, миграция 0021 предназначена
для старта новой сборки. Установка приложения и полный пользовательский сбор не
выполнялись агентом; native UI не проверялся. Пользователь принял результат.
