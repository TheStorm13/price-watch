# Proposal

## Why

Одна карточка должна представлять товар, а не единственный SKU. Пользователю нужны все варианты WB/AliExpress с независимой историей, главный SKU для каталога и общий график.

## What Changes

- **BREAKING**: товар уникален по площадке и артикулу; варианты и наблюдения имеют собственные ключи.
- Автоматическое обнаружение и сбор всех вариантов WB/AliExpress; частичные ошибки и повтор по варианту.
- Выбор главного SKU для каталога, выгодности и групп без смешивания историй.
- Удобные детали с вариантами, редактированием метаданных и цветными линиями истории.
- Миграция существующих записей и новый transfer v3 с сохранением исторических данных.

## Capabilities

### New Capabilities

- `product-variants`: владение вариантами, выбор главного, независимые истории и перенос данных.

### Modified Capabilities

- `marketplace-product-contract`: одна товарная карточка содержит отслеживаемые варианты AliExpress/WB.
- `collection-run-execution`: фиксированный товарный состав и расширение SKU внутри него при обнаружении.
- `desktop-ui-layout`: панель изменения общих полей, список вариантов и многосерийный график.

## Impact

Domain, PostgreSQL/Alembic, API, worker/direct collect, retry/schedule, catalog/groups/deals, transfer, React/mock и тесты. Числовой Ozon JSON остаётся без DATABASE_URL. Миграция объединяет карточки одного артикула только после preflight общих настроек; не удаляет историю и не переписывает snapshot JSON. ADR 0011 и план согласованы пользователем 2026-11-02 («Да, приступай»). Новые зависимости не требуются.
