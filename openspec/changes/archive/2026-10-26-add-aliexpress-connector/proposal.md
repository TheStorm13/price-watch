# Proposal

## Why

Карточки AliExpress можно добавлять, но нельзя собирать. Live probe подтвердил
получение товарного JSON с главной страницы aliexpress.ru после ручной CAPTCHA;
пользователь выбрал отслеживание конкретного SKU и единственную цену по
приоритету купонная → акционная → обычная.

## What Changes

- Добавить AliExpress.ru adapter: JSON transport → специфическая модель/parser
  → mapper → существующий MarketplaceCard, без открытия карточек при сборе.
- Для выбранного SKU возвращать только одну Decimal-цену:
  priceWithCoupon.amount → activityAmount → amount. Купон не получать и не
  применять; isCouponAssigned=false не исключает цену с купоном.
- **BREAKING:** идентичность AliExpress — `productId:skuId`, вместо одного
  числового productId. Добавление через UI поддерживает полную ссылку с sku_id
  либо два числовых поля; API/CLI/импорт используют каноническую пару.
- Вынести Chrome lifecycle из Ozon в общий слой. Один процесс Chrome и профиль
  на смешанный запуск, отдельная storefront page и транспорт на площадку.
- Подключить AliExpress к direct collect, API/desktop worker, расписанию и
  retry; убрать статус отсутствующего коннектора и тексты «только Ozon».
- CAPTCHA проходит пользователь. В видимом режиме сбор ожидает подтверждения;
  в скрытом режиме сообщает открыть Chrome приложения и повторить сбор.
- Безопасно перевести существующие AliExpress-записи, если SKU однозначно
  указан в сохранённой ссылке. Не выбирать SKU автоматически; не терять историю.
- Старую AliExpress-карточку без SKU оставить без изменений. При сборе записать
  ошибку «Не указан SKU» только для этой цели; остальные карточки собирать дальше.

## Capabilities

### New Capabilities

Нет: используются существующие границы спецификаций.

### Modified Capabilities

- `marketplace-product-contract`: идентичность AliExpress SKU, единственная цена,
  получение JSON, ошибки, доступность сбора, перенос существующих записей.
- `browser-profile-lifecycle`: совместное владение Chrome несколькими
  коннекторами и согласованные ручные проверки.

## Impact

Python connector/browser, фабрики CLI/worker, API-валидация, persistence/миграция,
импорт/экспорт, форма добавления и challenge panel, Rust-import profile closer,
проверки упаковки и связанные руководства. ADR 0008 предлагается на согласование.
Новые зависимости не планируются. JSON 2.0 сохраняет одну цену и строковый
external_id; отдельные колонки цен/SKU и новая версия transfer не нужны.

Критерии приёмки: конкретный SKU не подменяется; probe даёт 77648.00 RUB;
отсутствующая купонная/акционная цена приводит к следующему источнику;
два SKU одного товара имеют раздельную историю; смешанный сбор запускает один
Chrome; ошибки/CAPTCHA не затирают успешные цены; Ozon numeric/raw CLI без БД
сохраняет поведение; профиль, история, ID и настройки сохраняются.

Риски: недокументированная схема AliExpress, CAPTCHA/региональные цены,
refactor lifecycle и неоднозначные старые AliExpress-записи. До применения
миграции нужен preflight конфликтов идентичностей. Карточки без однозначного
SKU пропускаются без изменений и не блокируют переход; при сборе получают
индивидуальную ошибку без изменения карточки, цены или истории.
Тесты и probe не обращаются к пользовательской БД; миграция готовится и
проверяется на disposable БД.
