# Proposal

## Why

Карточки Wildberries уже можно хранить, но собирать их цены нельзя. Пользователь
запросил коннектор с конкретным размером и единственной ценой: с WB Кошельком,
а при подтверждённом отсутствии такой цены — без кошелька.

## What Changes

- Адаптер WB через существующий профиль и общий ChromeSession, без открытия
  страницы каждой карточки. Использовать товарный JSON и расчёт витрины WB,
  включая актуальную скидку, ограничения и округление; 3% не фиксировать.
- Единственное нормализованное поле price для UI/API/history/snapshot:
  кошелёчная цена → обычная цена. Не добавлять второй цены в extensions.
- **BREAKING**: идентичность WB `nmId:optionId`; один размер — одна карточка.
  Новые добавление/импорт требуют конкретный размер, ссылки `?size=` разбираются.
  Сбор не выбирает самый дешёвый или соседний размер.
- Подключить WB в builder, direct collect, очередные desktop/API/worker,
  расписание, retry и frontend-действия обновления.
- Перенести существующие numeric WB идентичности только при однозначном size
  в сохранённой ссылке; остальные оставить без изменений с индивидуальной
  ошибкой сбора. Сохранить ID, историю, группы, теги, настройки и цели запусков.
- Политика доступа и ошибок не заменяет успешную историю фиктивной ценой.

## Capabilities

### New Capabilities

Нет: используем существующие границы общего товарного контракта и Chrome.

### Modified Capabilities

- `marketplace-product-contract`: WB size identity, одна цена с приоритетом
  кошелька, наличие выбранного размера, транспорт, ошибки и перенос данных.
- `browser-profile-lifecycle`: добавить WB к совместному Chrome и ручным проверкам.

## Impact

`marketplace_connector/connectors/wildberries/`, общий builder и входная
валидация идентичностей; API schemas, cards/transfer repositories, data-only
Alembic revision; AddCardDrawer, ссылки/идентичности и разрешения сбора UI/mock;
tests/fixtures, документация затронутых контрактов. Новых зависимостей,
публичных полей цены, отдельных browser-профилей и нового standalone CLI нет.
Числовой database-free Ozon CLI сохраняется; WB доступен без БД через коннектор
и ProductService. Пользовательская БД при планировании не открывалась.

Приёмка: подтверждённые 105600 копеек минус 32 ₽ дают только 1024.00 RUB;
при неприменимости кошелька — только обычная цена того же размера. Недоступный
размер даёт null; сетевой сбой/неинициализированная скидка — ошибку, не переход
к обычной цене. Два размера сохраняют независимую историю. Смешанный запуск
использует один Chrome, отмена запроса не повреждает соседей и профиль.

Основные риски: внутренние функции/JSON WB могут измениться; готовность скидки
нужно проверять отдельно; авторизованный профиль live пока не проверен.
Миграция не угадывает размер и не объединяет карточки. Архитектурный выбор
и альтернативы — Proposed ADR 0009; реализация только после review плана.
