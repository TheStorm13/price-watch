# Design

## Findings

Desktop задаёт профиль в `$XDG_DATA_HOME/price-watch/chrome-profile`, передаёт его worker и открывает с ним ручной Chrome. `PKGBUILD` кладёт файлы только в `/usr`; обновление пакета не содержит операции над профилем. В текущем пользовательском профиле есть cookie Ozon, а Chrome записал `profile.exit_type=Crashed`. Это подтверждает аварийное завершение хотя бы одного запуска, но само по себе не доказывает, какой именно выход Ozon из аккаунта вызвало.

`RuntimeState::stop_manual_browser` посылает `SIGTERM` и через 3 секунды применяет `SIGKILL`. `_close_async_context` у worker сначала отключает Playwright от Chrome, затем посылает `SIGTERM` и при задержке `SIGKILL`. Проверка на отдельном временном профиле показала `Normal` после CDP `Browser.close` и `SessionEnded` после `SIGTERM`; `browser.close()` после `connect_over_cdp` оставляет процесс Chrome работающим. CDP определяет `Browser.close` как штатное закрытие браузера.

## Approach

Выделить в Python небольшой модуль для проверки `DevToolsActivePort`, сопоставления CDP endpoint с текущим профилем, отправки `Browser.close` и ожидания выхода. Worker вызывает его перед использованием занятого профиля и для завершения собственного Chrome. Rust вызывает тот же модуль отдельной командой установленного Python для остановки ручного Chrome; затем ожидает выход своего дочернего процесса. Сохранять ограниченный fallback для зависшего Chrome с диагностикой и не удалять содержимое профиля.

Модуль должен принимать путь профиля явно и работать без `DATABASE_URL`. Desktop передаёт тот же путь, что и worker; CLI `collect` и числовой JSON-режим не меняют выбор профиля. Перед запуском нового Chrome профиль должен быть свободен, иначе операция завершается ошибкой. При выходе закрывается только Chrome, запущенный приложением; чужие процессы и пользовательский обычный профиль Chrome не затрагиваются.

## Alternatives

- Оставить `SIGTERM`: на тестовом Chrome оно помечает сеанс `SessionEnded`, а принудительный fallback остаётся потенциальным источником повреждения состояния. Не устраняет требование штатного закрытия.
- Держать Chrome запущенным между сборами: убирает часть перезапусков, но усложняет работу скрытого дисплея и конкуренцию за профиль. Не требуется для сохранения данных.
- Добавить WebSocket-клиент в Rust: позволяет закрывать браузер без вызова Python, но дублирует уже используемый Python/CDP-код и добавляет зависимость. Общий модуль предпочтительнее.

## Compatibility and data

Формат профиля, база данных, API и пакетные пути не меняются. Миграции нет. Тесты используют только временные профили и отдельную тестовую БД лишь если потребуется проверить существующий сбор; пользовательский профиль и его cookie не изменяются.
