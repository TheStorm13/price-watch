# Proposal

## Why

Сейчас общий результат коннектора `ProductSnapshot`, старый `ProductCard` и
локальный `MarketplaceCard` обозначают разные роли, но имеют пересекающиеся
названия и поля. Цена при преобразованиях проходит через float/int, хотя история
хранится в NUMERIC; нужен единый товарный контракт всех площадок с точными ценами.

## What Changes

- Общий товар — `marketplace_connector.domain.models.MarketplaceCard`:
  идентичность площадки, данные товара и время получения, без локального ID
  и настроек отслеживания. Локальная запись — `price_watch.domain.models.TrackedCard`.
- Путь Ozon: исходный ответ → специфический `OzonProductData` → `OzonMapper`
  → общий `MarketplaceCard`. Контракт коннектора одинаков для всех площадок;
  реальные коннекторы остальных площадок в эту работу не входят.
- Денежные значения — Decimal в Python, NUMERIC в PostgreSQL и десятичные
  строки в JSON/TypeScript. Округление цены — до двух знаков ROUND_HALF_UP;
  средние и выгода рассчитываются без предварительного округления для показа.
- **BREAKING**: заменить Python-импорты ProductSnapshot/старого ProductCard
  и прежний смысл имени MarketplaceCard. Удалить заменённые модели и обёртки.
- **BREAKING**: цены HTTP API, числового JSON CLI и CLI истории/списка становятся
  строками вместо чисел. Обновить всех потребителей, mock API и localStorage
  уведомлений; нормализованный JSON товара получает schema_version 2.0.
- Перенести действующий одиночный CLI из ozon_article_json в Ozon-коннектор,
  затем удалить заменённый пакет и обновить упаковку. Команды и raw-режим сохраняются.

## Capabilities

### New Capabilities

- `marketplace-product-contract`: единый результат коннекторов, преобразование
  специфических данных площадок и отделение локальной записи отслеживания.
- `decimal-money-contract`: точность денежных значений от декодирования ответа
  до хранения, JSON, сортировки, уведомлений и отображения.

### Modified Capabilities

Нет. Требования collection-run-execution, catalog-snapshot, group-card-metrics
и deal-selection сохраняются; новые спецификации определяют типы и денежное
представление, не меняя их продуктовые правила.

## Impact

Затронуты marketplace_connector, ozon_article_json, домен и сбор price_watch,
репозитории и API, оба CLI, frontend DTO/форматирование/сортировка/график,
mock API, уведомления, тесты, упаковка и актуальная документация.
Новые внешние зависимости не планируются.

Новая таблица для TrackedCard не нужна: используется marketplace_cards.
Сохраняются ID, связи, NUMERIC(14,2), история и результаты запусков. Старые
snapshot JSONB остаются историческими документами своей версии, без переписи
и без добавления старого runtime-декодера. Экспорт/импорт v2 уже использует
десятичные строки и сохраняет контракт.

Приёмка: один тип результата для любого коннектора, независимый от БД;
настройки отслеживания не поступают из коннектора; Decimal не проходит через
float/int в денежных путях; сохранены атомарность, lease, dedup истории,
retry, правила групп и выгодности. Проверены queued API/worker, direct collect
и числовой JSON без DATABASE_URL, включая raw/output и импорт обоих CLI.

Полный план и сравнение вариантов: design.md и проект ADR 0005.
Выбор двух сущностей согласован 2026-10-25. Полный план, включая изменения
денежного JSON, одобрен пользователем («Хорошо, действуй»). Реализация
принята запросом пользователя зафиксировать все изменения и очистить дерево.
