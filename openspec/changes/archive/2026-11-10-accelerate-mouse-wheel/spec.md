# Результат: ускорение колесика без размножения событий

Принято пользователем 2026-11-10: «Все ок» после проверки новой версии приложения. Исправление: `b7458ca` (первоначальная реализация ускорения: `cdc9db5`).

В Linux desktop сохранено ускорение вертикального физического колесика ×2. Обработчик изменяет delta исходного GdkEventScroll и передаёт его штатному WebKit handler. Тачпад, горизонтальное колесо и Ctrl/Shift/Alt/Super/Meta сохраняют обычное поведение; выбор вложенной области выполняет WebKit. Данные и серверные контракты не менялись.

Прежняя отправка двух копий через gtk_main_do_event нарушала возврат непрокрученного события из WebKit в GTK. Синхронный Cell не защищал от позднего возврата, поэтому у границ возникало размножение wheel и блокировка UI. В пользовательском наблюдении зарегистрированы пауза 31.28 s и более миллиона записей wheel; первоначальная подробная диагностика дополнительно увеличивала нагрузку. Повторная отправка и Cell удалены. Минимальный unsafe-мост меняет только scroll payload GTK-события на UI thread, не сохраняя указатель.

Проверено: cargo check --offline для приложения и integration target, cargo fmt --check, diff check, строгая OpenSpec validation. Изолированный GTK/WebKit regression test под Xvfb: дистанция 71 → 142 px, smooth Mouse ×2, вложенная прокрутка и исключения; у верхней/нижней границ страницы и границы вложенной области 20 входных wheel дают 20 DOM и 40 GTK доставок (включая штатный возврат), очередь затихает. Прежний обработчик на том же стенде провалил проверку размножения у границы. Тест использует synthetic HTML и ephemeral context без пользовательских данных. Физический тачпад отдельно не проверялся; реальную desktop-проверку выполнил и принял пользователь. Сборку/установку агент не выполнял.
