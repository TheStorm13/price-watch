# Design

## Context

См. `proposal.md` о цели. Сейчас `frontend/src/app/App.tsx` вызывает `ensure_services` после загрузки WebView; `frontend/src-tauri/src/lib.rs` владеет PostgreSQL, Xvfb, API и worker и закрывает их при выходе. `NativeServices` держит эксклюзивный `native.lock`. `CollectionWorker.run_once` раз в минуту вызывает `create_due_run`; репозиторий сравнивает начало последнего полного запуска с 12 часами. Очередь, защита от дубликатов и сохранение истории уже существуют. Коннектор Ozon при работе worker на виртуальном дисплее закрывает вручную открытый браузер с тем же профилем или возвращает ошибку.

## Goals / Non-Goals

**Goals:**

- Связать владение службами с одним desktop-процессом, который может работать со скрытым окном.
- Обеспечить наблюдаемое восстановление worker и службы после сбоя при закрытом окне.
- Применить 6-часовое правило ко всем полным запускам без изменения схемы хранения.

**Non-Goals:**

- Запуск до входа пользователя в графическую сессию, работа при выключенном ПК, системные уведомления и настраиваемый интервал.
- Переделка прямого CLI-сбора или JSON-режима одного товара.

## Decisions

### Один постоянно работающий Tauri-процесс

Оставить `RuntimeState` и `NativeServices` владельцами локальных дочерних процессов. Добавить фоновый запуск с аргументом `--background`, скрытие основного окна при закрытии с включённым режимом, системный tray с действиями «Открыть» и «Выход» и явный выход в UI. При обычном ручном запуске окно видно. Повторный запуск ярлыка передаёт команду показать и сфокусировать окно существующему экземпляру через официальный Tauri single-instance plugin; зарегистрировать его первым. Скрытый процесс продолжает опрос очереди и доступен из tray.

Альтернатива — отдельная systemd user service и UI-клиент. Она позволила бы завершать desktop-процесс, но потребовала бы перенести владение PostgreSQL/Xvfb/API, адрес и токен API из Tauri и организовать надёжное подключение UI. Timer, запускающий прямой CLI-сбор, также не решает владение локальной БД и конкуренцию за профиль. В рамках этой задачи оба варианта дают больший риск для данных и упаковки.

### Настройка через регистрацию автозапуска

Использовать официальный Tauri autostart plugin в Rust с аргументом `--background`. Состояние регистрации автозапуска — сохраняемое состояние фонового режима; включение/отключение и чтение идут через команды Tauri из UI. Это избегает рассинхронизации отдельного файла настроек с записью автозапуска. Ошибку регистрации показывать в UI, не объявлять включение успешным. Изначально регистрация отсутствует. Действие «Выход» завершает текущий процесс, сохраняя включённый автозапуск для следующего входа. При выключении режима уже открытый процесс остаётся видимым и закрывается обычным способом.

Альтернатива — собственный XDG `.desktop`-файл и отдельный флаг в конфигурации. Это добавляет две записи состояния и потребует синхронизировать их при обновлении пути бинарника. Для установленного Linux-пакета использовать стабильный launcher `price-watch`; при запуске из репозитория проверить путь и корректную регистрацию в ручном smoke-тесте.

### Службы запускаются и проверяются в Rust

Инициализировать службы при старте процесса независимо от WebView; `ensure_services` оставить идемпотентным способом получить адрес/токен API и повторить запуск после ошибки. В `RuntimeState` хранить последнюю ошибку запуска и отдавать её интерфейсу. Периодическая проверка готовности служб и состояния worker в Rust вызывает существующий защищённый `ensure_services` с ограниченной частотой повторов и верхней границей задержки, чтобы восстановить неожиданно завершившийся worker и не запускать параллельные копии. При полном выходе остановить монитор перед остановкой дочерних процессов; не считать штатное завершение поводом для восстановления. Логи остаются в каталоге состояния XDG.

При перезапуске `NativeServices` API получает новый порт и токен. Rust уведомляет открытый WebView о новой конфигурации через Tauri event. React заменяет конфигурацию API-клиента и инвалидирует запросы; кэшированный `startupPromise` не должен препятствовать повторному `ensure_services`. При показе скрытого окна React дополнительно запрашивает актуальную конфигурацию, если событие не было обработано во время скрытия. Секрет API передавать только через существующий Tauri IPC, не писать в логи.

Если проверка `NativeServices::is_ready` обнаруживает остановку PostgreSQL, API или Xvfb, сначала остановить worker, затем пересоздать службы под существующим `startup` lock. Нынешний `child.kill()` прерывает Python без очистки Chrome: заменить его на штатное завершение worker с ограниченным ожиданием, затем принудительно завершать только при превышении таймаута. Перед следующим сбором проверять профиль и закрывать только относящийся к нему оставшийся Chrome по существующему механизму CDP; не удалять профиль. Прерванный запуск после восстановления БД должен пройти существующее обнаружение устаревшего heartbeat и получить статус `failed`; уже зафиксированные наблюдения цен не удаляются. Не возобновлять его параллельно вторым worker и не создавать вне расписания новый полный запуск. Диагностировать как исходный сбой службы, так и неудачу восстановления.

Альтернатива — продлевать жизнь служб из периодических вызовов React. Она не работает при скрытом или не загруженном окне и не соответствует фоновому режиму.

### Шестичасовое расписание в существующем репозитории

Заменить сравнение `timedelta(hours=12)` на 6 часов в `create_due_run`, сохранив отсчёт от `started_at` последнего полного запуска, блокировку создания и проверку активных запусков. Первый полный сбор ставится в очередь при наличии поддерживаемых карточек, даже если истории запусков нет. После простоя создаётся один просроченный запуск. Ошибочный полный запуск также переносит срок на шесть часов, а ошибка остаётся в истории; немедленное ручное повторение доступно. UI и API не получают нового контракта для расписания. Проверку влияния на `main.py collect` провести тестом: прямой полный сбор пишет запуск в ту же таблицу и переносит срок; сбор одной карточки не переносит.

## Risks / Trade-offs

- [Нет графической сессии или выключен ПК] → явно описать границу; после входа worker поставит один просроченный запуск.
- [Tray отсутствует или скрыт в окружении рабочего стола] → повторный запуск ярлыка всегда открывает существующее окно; явный выход доступен также в UI.
- [Сбой служб при скрытом окне] → Rust-монитор с задержкой между попытками, запись ошибки в лог и показ её при открытии UI.
- [Сбой службы во время сбора] → остановить прежний worker до перезапуска служб, сохранить зафиксированные строки истории, пометить прерванный запуск ошибкой через существующий stale-run механизм и проверить это в интеграционном тесте.
- [Конфликт профиля Chrome] → сохранить существующее освобождение профиля в `AsyncOzonClient` и проверить сценарий открытого ручного браузера; не удалять профиль при ошибке.
- [Больше сетевых запросов и нагрузка на Ozon] → интервал 6 часов выбран пользователем; сохранить ограничение параллелизма и видимые ошибки сбора.
- [Код приложения обновлён, пока старый процесс работает] → при обновлении пакета требуется полный выход/перезапуск, чтобы новый бинарник и Python-код совпадали.

## Migration Plan

Миграция PostgreSQL и изменение API-контракта не требуются. Новый автозапуск не регистрируется без явного включения; прежние данные, очередь и история остаются на месте. После обновления первый сбор может стать просроченным сразу по 6-часовому правилу. Откат требует отключить регистрацию автозапуска перед возвратом к прежнему бинарнику; история цен сохраняется. Проверить корректность установки и удаления автозапуска для пакетного и локального запуска.

Локальный launcher `price-watch` должен передавать аргументы бинарнику, чтобы `--background` работал при запуске из репозитория; пакетный `/usr/bin/price-watch` уже является бинарником.

## Open Questions

Нет вопросов, меняющих выбранную архитектуру или поведение. Доступность tray в конкретной среде Linux проверяется при реализации; повторный запуск ярлыка предусмотрен как резервный способ открыть окно.
