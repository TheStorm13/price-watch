# Design

## Context

Мотивация и семь критериев — в proposal.md и specs/desktop-ui-layout/spec.md.
Текущие источники проверены через CodeGraph и CSS. ActiveCollectionPanel собран из Card с overflow-hidden и gap-0; нужно проверить итоговую flex-геометрию для всех состояний. У detail-tags align-items:end, но Field включает подсказку, поэтому кнопка привязана к ней. В AppShell уведомление содержит соседние span/Link без layout/gap. В списке высоты строки, ячейки, изображения и блока текста зафиксированы на 84 px; название/ID/теги/статус конкурируют за это место. В Badge warning задано 10 px, success/muted — 11 px. В ToggleGroup остались group-data-horizontal/vertical при реальном data-orientation; это вероятная причина пропавших наружных скруглений, требующая проверки computed styles. Плитка начинается с области изображения без отступа.

Существующий E2E ограничивает строку 85 px и статус 18 px, проверяет только горизонтальные границы. Это не доказывает отсутствие вертикального выхода плашки.

## Goals / Non-Goals

**Goals:** восстановить согласованную геометрию, читаемость, фокус и доступность без изменения бизнес-операций.

**Non-Goals:** изменение дизайна всего приложения, группировки, API, worker, CLI, хранения и оптимизация bundle. Серые группы с отступами по 8 px и новый Select сохраняются.

## Decisions

- **Панель:** естественная высота, явные промежутки и несжимаемые заголовок/действия/прогресс; предел по доступному viewport с прокруткой длинного содержимого. Проверить обычный сбор, проверку, завершение и раскрытые ошибки. Фиксированная высота или увеличение padding без проверки состояний не подходят.
- **Теги:** поле и Button составляют общую строку; label, description и error занимают отдельные области. На узкой доступной ширине строка переносится. Не компенсировать подсказку магическим margin у кнопки.
- **Скругления:** исправить привязку селекторов к data-orientation/spacing у ToggleGroup и проверить наружные границы затронутых панелей, полей и кнопок. Внутренние стыки не скруглять. Не применять глобальный border-radius ко всем элементам.
- **Уведомление:** отдельные области для сообщения и действий с gap; ссылка использует установленный вариант Button asChild, закрытие — именованная кнопка. Переход и dismiss остаются прежними.
- **Строка списка:** высота от содержимого с минимальной базовой высотой. Убрать жёсткую высоту/overflow, мешающие метаданным; сохранить обрезание длинного названия и тегов по ширине. Статус целиком внутри строки с вертикальными промежутками. Разрешено увеличение строки при дополнительных метаданных; тест не должен принуждать к 84 px ценой обрезания.
- **Типографика:** цены списка — 14 px, наличие — 13 px, читабельный line-height и padding статусов. Ограничить увеличение контекстом списка/истории при необходимости, чтобы не сломать сетку. Другие значения цены и порядок сортировки не меняются.
- **Плитка:** 8 px внутреннего отступа над областью фото; согласовать высоты строк плитки без растяжения фото. Вертикальные/горизонтальные изображения и fallback остаются object-fit:contain, названия/теги/статусы не перекрываются.

## Risks / Trade-offs

- CSS legacy/utilities и shared Badge → проверять computed styles и всех затронутых потребителей, избегать !important и компенсирующих offsets.
- Высота строк вырастет при дополнительных данных → это осознанная замена прежней фиксированной высоты; сохранить компактность обычных строк и ровное выравнивание колонок.
- Mock E2E не проверяет реальный сбор → UI-состояния воспроизводить на mock, WebView smoke проводить изолированно, без пользовательской БД/профиля.
- Указание «не везде скругления» не называет все элементы → минимум проверить составные переключатели вида/периода, фильтры, карточки, панель обновления и уведомление; расширять только на обнаруженные дефекты тех же контролов.

## Migration Plan

Миграций нет; frontend-пересборка. Откат — обратный коммит правок UI. Старый change migrate-ui-to-shadcn не архивировать автоматически и не менять его статус приёмки.
