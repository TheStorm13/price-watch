# Proposal

## Why

Сейчас price-watch использует собственные React-компоненты и большой общий CSS. Переход на shadcn/ui даст общую основу для элементов управления и предсказуемые правила для последующей работы через Codex.

## What Changes

- Поэтапно подключить Tailwind CSS 4 и shadcn/ui к существующему Vite/React desktop-приложению; сохранить маршруты, сценарии, данные и плотность каталога.
- Предлагаемая база: официальный реестр `@shadcn`, Radix, светлая нейтральная тема с нынешним синим акцентом, Lucide, существующий системный стек шрифтов без внешних запросов. Это предложение для согласования, а не уже принятое решение.
- Перенести кнопки, поля, выбор, статусы, загрузку, меню, подтверждения, боковую панель добавления, диалог группы и элементы остальных экранов на общие компоненты. Предметные компоненты и существующие Recharts-графики сохранить.
- Зафиксировать правила для Codex в `frontend/AGENTS.md`: установленные компоненты прежде собственной реализации, CLI для добавления, семантические токены, одна библиотека примитивов, проверка документации и браузерная проверка после изменений.
- Использовать установленный project skill `.agents/skills/shadcn` и официальный shadcn MCP для поиска и примеров; Context7 — для актуальной документации. Подключить MCP на уровне проекта, если он ещё недоступен; глобальную конфигурацию не менять.

## Capabilities

### New Capabilities

Нет. Это миграция реализации UI с сохранением пользовательских возможностей.

### Modified Capabilities

Нет. `card-list-selection`, `group-member-selection` и остальные существующие требования сохраняются. В `.openspec.yaml` установлен `skip_specs: true`; дельты спецификаций не нужны.

## Impact

- Конфигурация и зависимости: `frontend/package.json`, lockfile, Vite, TypeScript aliases, новый `frontend/components.json`, утилита `cn`, существующие файлы темы и глобальных стилей.
- UI: `frontend/src/components`, карточки и группы, детали карточки, настройки фонового сбора, отображение процесса сбора. Python API, worker, БД, CLI, numeric JSON mode, Tauri commands и упаковочные скрипты не меняются.
- Приёмка: соответствующие существующие unit/E2E проходят; выбор и частичные ошибки массовых действий сохранены; удаления требуют подтверждения; фильтры, сортировка, группы, импорт/экспорт, график и история доступны; каталог при 1024 px без горизонтального переполнения; диалоги и меню управляются клавиатурой, восстанавливают фокус и не запускают действия строки.
- Риски: CSS reset и порядок слоёв могут изменить старые экраны; порталы меняют DOM и распространение событий; новые компоненты отличаются API от текущего `Button`; Tailwind и примитивы требуют проверки в Tauri WebView. Нет миграции данных. Подробности, проверки и откат — в design.md.
