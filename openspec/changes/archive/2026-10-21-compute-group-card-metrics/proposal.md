# Proposal

## Why

Группа должна быть полноценным объектом общего каталога: иметь поля обычной карточки и участвовать в тех же фильтрах и сортировке. По уточнению пользователя источником всех товарных показателей служит одна карточка с минимальной текущей ценой, а не агрегаты всего состава.

## What Changes

- Выбирать карточку-представителя с минимальной известной текущей ценой среди полного состава группы; остальные показатели брать у неё целиком.
- **BREAKING (семантика поля):** `minimumPrice` группы теперь равен историческому минимуму выбранной карточки, а не минимуму историй всей группы. Это прямо заменяет первоначальное пожелание по уточнению пользователя. Средняя, выгода, наличие, даты, маркетплейс и остальные товарные поля также берутся у представителя.
- Группы и отдельные карточки фильтровать и сортировать одним алгоритмом как равноправные объекты. Фильтрация не выбирает другого представителя и не вычисляет поля по оставшимся видимым участникам.
- Сохранить название, ID, состав и редактируемые теги группы как её собственные данные. Товарные поля для фильтров берутся у представителя; поиск дополнительно учитывает название группы.
- Сохранить исходное требование о приоритете за выгодного участника: группа поднимается при выгодности представителя или любого вложенного товара. Это отдельный признак приоритета; численная выгода группы остаётся выгодой представителя.
- Использовать один общий порядок в списке и плитке; убрать принудительное размещение групп впереди карточек. Переключатель группировки не входит в задачу.

## Capabilities

### New Capabilities

- `group-card-metrics`: выбор карточки-представителя, поля группы и равноправная фильтрация/сортировка каталога.

### Modified Capabilities

Нет. Правила `deal-selection` для отдельных карточек сохраняются и применяются к представителю без новой групповой формулы.

## Impact

- Backend: `groups_repository.py`, `GroupResponse`, переиспользование метрик обычных карточек и действующей оценки выгодности. Добавить ID/проекцию представителя; сохранить входные запросы групп и карточечный `/api/deals`.
- Frontend: `ProductGroup`, mock-проекция, нормализация объекта каталога, общий фильтр/компаратор, отображение списка/плитки и корректная инвалидация после mutations.
- Приёмка: все товарные поля взяты из одной выбранной карточки; смена минимальной цены переключает их вместе; пустая группа, равные и отсутствующие цены определены; фильтры не подбирают удобного участника; список и плитка имеют один порядок; выгодность вложенного товара влияет на приоритет.
- Проверки: API, PostgreSQL только с disposable TEST_DATABASE_URL, frontend unit и demo E2E, регрессии массового выбора и групп.
- Миграций, изменения историй и формата импорта/экспорта нет. Desktop/API/worker collection, `main.py collect`, numeric Ozon JSON mode и Tauri команды сохраняются.
- Существующие чужие изменения frontend и документации сохранить. Код приложения на этапе пересмотра плана не меняется.
