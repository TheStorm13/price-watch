# Task: Оценить репрезентативность средней цены

## Goal and acceptance criteria

Запрос — исследовать, насколько текущая средняя отражает обычную цену товара,
и сравнить альтернативы. Изменение алгоритма пользователем не запрошено и не
согласовано. Критерии исследования: установить формулу и её потребителей по
текущему исходному коду; объяснить искажения на числовом примере; сопоставить
альтернативы с фактическим способом сохранения истории; обозначить ограничения
выводов без анализа пользовательской базы.

Следствия: один старый максимум может завысить базу на неопределённый срок;
длительность обычной цены не учитывается. Если 29 дней цена была 1000, один
день 3000, середина диапазона 2000, средняя по времени 1066.67, медиана по
времени 1000. Это синтетический пример, не результат измерений рабочей базы.
При двух точках 100 и 80 текущая база 90, выгода 10; относительно предыдущей
цены снижение составляет 20. Метрики отвечают на разные вопросы.

## Agreed solution

Согласованного изменения нет. Рекомендация для обсуждения: для понятия обычной
цены рассмотреть медиану, взвешенную по длительности доступных цен, в скользящем
окне 30 дней; 90 дней можно сравнить как более медленную альтернативу. Размер
окна — гипотеза для проверки, не установленный оптимум. Для настоящей средней
цены использовать среднее по времени `sum(price * duration) / sum(duration)`.
Медиана по времени устойчива к кратким экстремумам, но меняется скачком после
перехода половины временного веса к новому уровню; среднее реагирует плавнее,
но чувствительнее к выбросам. Среднее/медиана строк истории не рекомендуются:
строки являются изменениями состояния, а не равномерными измерениями.
Экспоненциальное взвешивание возможно, но добавляет параметр скорости забывания
и усложняет объяснение, не устраняя проблему пропусков.

Для будущего решения нужны правила: перенос состояния из точки перед началом
окна; исключение интервалов отсутствия/неизвестной цены; ограничение переноса
старой цены через длительные пробелы; подтверждение свежести без записи каждого
повтора; минимальная длительность/полнота базы; включение текущего ценового
интервала. Состояние между проверками является моделью, а не известной фактической
ценой. Нельзя выдавать длительный перерыв в сборе за подтверждённую стабильность.
Реализуемость и точность оценки покрытия по существующим полям отдельно не
исследованы. По одной формуле нельзя оценить процент ошибочных выгодных покупок
на реальных товарах.

В случае продолжения изменение затронет каталог, статистику истории, правила
выгоды, demo API, отображение и сортировку выгоды, соответствующие тесты,
`DATA_AND_API.md` и `deal-selection/spec.md`. Минимум за всё время можно
сохранить как отдельную метрику. Удаление истории не требуется; необходимость
новых полей зависит от согласованных правил свежести. Связанный backlog
«Относительно выгодная покупка» не является разрешением на реализацию.
