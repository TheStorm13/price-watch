# Task: Упрощение текстов, компоновки и прокрутки интерфейса

## Goal and acceptance criteria

Снизить объём постоянно видимого текста, исправить компоновку каталога, групп и страницы товара, прокрутку и организацию настроек. Пользователь согласовал план и разрешил реализацию 10 ноября 2026 года: «Можешь приступать к реализации».

Критерии предлагаемой реализации:
1. Повторяющиеся объяснения в формах, вариантах, группах и настройках заменены краткими подписями и локальной справкой «?». Проверка: просмотр соответствующих экранов и диалогов.
2. Справка открывается кликом, Enter/Space; закрывается Escape и кликом снаружи, возвращает фокус. Кнопка имеет доступное имя, заметный фокус и удобную область нажатия вокруг небольшого кружка. Проверка: компонентный тест и браузерная проверка.
3. Предупреждения об удалении истории, переносе между группами, последствиях импорта, неполном повторе и необходимости проверки в Chrome остаются видимыми в момент принятия решения. Проверка: существующие тесты и целевые сценарии.
4. Подписи не обещают изменить главный вариант при отключении дополнительных и не фиксируют лимит параллельного сбора. Цены, формулы, фильтры, порядок сортировки и бизнес-логика не меняются. Проверка: исходный diff, существующие тесты.
5. Применён единый пользовательский словарь: товар, вариант, история цен, обновление цен. API-имена и технические диагностические данные сохраняются. Проверка: аудит изменённых строк.
6. Все правки U01–U15 ниже выполняются на поддерживаемой ширине desktop; на более узком окне допустима адаптация без наложения элементов и потери действий. Проверка: браузерная проверка геометрии и целевые E2E.
7. Нет пустой области размером с экран после последней строки; скролл внутри выпадающего списка не передаётся каталогу; панель выбранного остаётся доступной. Проверка: воспроизведение на длинном каталоге и браузерные регрессии.
8. Обычный запуск показывает готовый интерфейс без заставки и белого мигания; фоновый запуск остаётся скрытым, восстановление служб не раскрывает закрытое окно самопроизвольно. Ошибка запуска имеет видимый путь восстановления. Проверка: изолированный desktop smoke и тесты управления видимостью.

## Agreed solution

Статус: пользователь одобрил исходное направление с поправками («ост окей»), затем явно ограничил работу составлением списка и плана. Ниже учтены все последующие уточнения. Итоговый расширенный план согласован 10 ноября 2026 года; реализация разрешена.

Общий принцип: убрать дублирование; короткие ограничения перенести в подпись поля; объяснения правил — под «?» рядом с соответствующим заголовком/полем; последствия действий и текущие ошибки — оставить рядом с действием. Не добавлять «?» к очевидным кнопкам и каждой строке товара.

### Предлагаемый список правок

| Область | Предложение |
| --- | --- |
| Каталог и навигация | «Карточки товаров» → «Товары», «Добавить карточку» → «Добавить товар», «К карточкам» → «К товарам», заголовок колонки «Карточка» → «Товар». «Обновить все цены» сохранить: явно задаёт область действия. |
| Счётчики | «Показано N из M товаров» → «N из M», без фильтров — «N товаров»; «Выбрано карточек: N» → «Выбрано: N». |
| Форма | Заголовки «Добавить товар» / «Изменить товар». Убрать видимое описание, повторяющее заголовок; сохранить доступное описание Sheet при необходимости через sr-only. |
| Добавление и ID | Для добавления две кнопки «Артикул» / «Ссылка» и одно поле способа ввода. Режим ссылки отложен в backlog; в текущем предложении кнопка «Ссылка» недоступна с пояснением причины. Отдельного поля URL при добавлении нет. Один «?» у артикула/ID вместо двух повторяющихся абзацев. Справка: «При первом обновлении найдём варианты и начальные цены. Затем обновляется главный вариант. Остальные можно включить на странице товара». Сохранить различия ID товара и варианта для площадок. |
| Редактирование | Пояснение «Маркетплейс и артикул изменить нельзя» в справке у заблокированного идентификатора. Никаких изменений правил редактирования. |
| Главный вариант | «?» у поля: «Этот вариант определяет название, фото и цену товара в каталоге». Действующие поля и данные главного варианта не менять. |
| Название и теги | После поля выбранного способа ввода идут «Название (необязательно)» и «Теги (до двух, через запятую)». У названия «?»: «Можно оставить пустым — название появится после обновления цен». Пример тегов — «кухня, подарок». Убрать повторяющиеся подписи под полями. Селектор маркетплейса сохранить перед выбором способа. |
| Ошибки ввода | «Используйте абсолютный HTTP(S) URL» → «Введите полную ссылку с https:// или http://»; «Введите корректный абсолютный URL» → «Проверьте ссылку на товар»; ошибку диапазона WB сформулировать «Артикул WB должен быть целым числом от 1 до 9007199254740991». Остальные ошибки сократить без потери указания несовпадающего товара/варианта. Лимиты и валидацию не менять. |
| Участие в выгодных | Фильтр «Участие в выгодных», вариант «Все товары», «Участвуют в выгодных», «Выгодные», «Невыгодные»; переключатель «Сначала товары, участвующие в выгодных предложениях». Рядом один «?»: участие разрешает показывать товар среди выгодных, но само по себе не делает цену выгодной. Не объединять эти состояния. |
| Действия с участием | «Учитывать в выгодных» / «Исключить из выгодных», массовые — те же термины; значок состояния «Исключён из выгодных». Выбор не влияет на обновление цен: пояснить в общей справке участия. |
| Выгода | Заголовок «Выгода / макс.» и один «?» вне кнопки сортировки. Справка: текущая выгода — средняя цена минус текущая при доступном товаре и положительной разнице; максимальная — средняя минус минимальная. Сохранить обе суммы и сортировку. «Сейчас не выгодно» → «Нет выгоды», но не объединять это состояние с отсутствием данных. |
| Группы | Общий абзац → «?» у заголовка: «Объединяйте товары для сравнения. Цены каждого товара обновляются отдельно». «Есть выгодный товар внутри» → «Есть выгодный товар». Счётчик состава сохранить; при фильтрации показывать N из M. |
| Перенос в группу | Сохранить явное предупреждение «Товары из других групп перейдут сюда. История цен сохранится». Удаление группы: «Товары и история цен сохранятся». |
| Детали товара | «Обновить эту карточку» → «Обновить цены»; «История цены» → «История цен»; Заголовок «Измерения» сохранить по прямому указанию пользователя; «Вариант для измерений» → «Вариант». Сообщения отсутствия данных и пагинацию сократить, сохранив термин «измерения». |
| Статистика | Не переименовывать середину диапазона в среднюю цену. Один «?» у блока: показатели главного варианта за выбранный период; середина — (минимум + максимум) / 2; разница — максимум − минимум. |
| Варианты | Убрать абзац под заголовком; «?» со справкой «Главный вариант обновляется всегда. Включите другие варианты для обновления их цен. При отключении история сохраняется». Кнопки «Включить остальные» / «Выключить остальные»; историческую строку «Общая история» сохранить. |
| График | Легенду и названия вариантов сохранить. В пустом состоянии оставить одно понятное сообщение и существующее полезное действие; не советовать включить линии, если для них нет данных. |
| Фоновое обновление | Заголовок «Фоновое обновление», короткая строка «Каждые 6 часов» и «?»: «Цены обновляются, пока приложение работает». Переключатель «Запускать при входе в систему». При включённом режиме видимая короткая строка «После закрытия окна обновление продолжится»; инструкцию повторного открытия — под «?». «Полностью выйти» → «Завершить работу», такую же подпись в меню tray. |
| Импорт/экспорт | «Импорт товаров», короткое видимое «Товары и история будут объединены». Под «?» — источник файла и сохранение настроек существующих товаров. Предварительные количества добавлений, объединений, пропусков и удаления одинаковых соседних цен оставить видимыми, сгруппировать компактно. Итог «Добавлено: N · Объединено: M · Записей истории: K · Групп: G». |
| Пустые состояния | «Товаров пока нет» + «Добавить товар» без повторяющего объяснения; «Ничего не найдено» + «Сбросить фильтры». При поиске по группе — сохранить полезную короткую подсказку изменения запроса. |
| Запуск приложения | Последнее рассматриваемое решение: главное окно создаётся скрытым и показывается после готовности локальных служб и отрисовки интерфейса, без отдельного стартового экрана. При сбое запуска показать ошибку и повтор. Подробный контракт ниже; вариант с увеличенным логотипом и названием заменён этим предложением. |
| Обновление цен | Убрать фразу с фиксированным числом параллельных вариантов. Оставить статус, прогресс N из M, текущий товар при его наличии. «Повторить ошибки и оставшиеся» → «Повторить неудавшиеся и оставшиеся». |
| Диагностика | Технические подробности уже раскрываются отдельно — сохранить. Короткие сообщения «Показаны примеры ошибок», «Подробности прошлого запуска удалены» со справкой о сроке хранения. Ограничение неполного повтора оставить видимым: «Повторятся только известные варианты». |
| CAPTCHA и удаление | Указание пройти проверку в Chrome и кнопку продолжения сохранить на виду. Подтверждение удаления: «Товар и вся история цен будут удалены безвозвратно»; для нескольких — указать количество. |
| Остальные подписи | Цены, даты, наличие, названия площадок, поиск, сортировку по цене, «Изменить», «Отмена», «Сохранить», «Повторить», «Открыть Chrome», «Открыть Price watch» сохранить. Они краткие и задают понятное действие/значение. |

### Справка и границы

Применить проектный shadcn skill при реализации. Использовать существующий Popover, Button и Lucide для небольшого кружка с вопросом; зависимостей не добавлять. Одна небольшая общая компонента в `components/product` с текстом/доступным именем. В заголовках таблицы справка — сосед кнопки сортировки, не вложенная кнопка. В label не вкладывать интерактивную кнопку, чтобы открытие справки не переключало поле. Внутри настроек/диалогов проверить вложенные Popover и восстановление фокуса.

Не превращать каждое объяснение в отдельный значок: одна справка на правило/блок. Не скрывать предупреждения в sr-only; sr-only допустим для обязательных доступных описаний, повторяющих заголовок. Содержимое справки — короткие фразы, без технических названий внутренних служб.

Worker, сбор, CLI, numeric JSON mode, БД, миграции, данные, расчёты, ограничения ввода и фоновые интервалы не меняются. API path/параметры сохраняются; размеры thumbnail-профилей обновляются по последнему запросу пользователя. Технические тексты динамических ошибок сохраняют причину/пути; массовый рефакторинг ошибок Rust/Python исключён. Значительного архитектурного изменения нет, ADR не требуется.

### Поправки пользователя при оценке реализации

Пользователь явно запросил следующие исправления; они заменяют прежнюю трактовку соответствующих U-пунктов:
- Единая голубая поверхность всей шапки группы в списке и плитке; убрать только отдельную заливку непосредственно под подписями. Отступ от блока названия до цен в плитке уменьшить вдвое: 28 → 14 px (24 → 12 на компактной ширине).
- Настройки — компактный отдельный Dialog справа от нижней части sidebar, с нижним отступом 16 px и отступом от меню 12 px. Убрать полноэкранную высоту и центрирующие/масштабирующие transform/animation; содержимое (импорт/экспорт и desktop background controls) остаётся видимым, диалоги сохраняют фокус и Escape.
- Восстановить «Сначала товары, участвующие в выгодных предложениях»; в списке участия — «Участвуют в выгодных».
- На странице товара фото слева от информации/кнопок/цен, нижний край совпадает с нижним краем панели цен. Портретная рамка сохраняет 3:4; при более высоком тексте фото выравнивается по низу, правая панель занимает доступную высоту.
- Все фото и их заглушки — 3:4, включая каталог, плитки, детали и варианты. Без обрезки и искажения исходника. Обновить реальные подготовленные PNG: list 51×68, tile 276×368, detail 384×512 CSS px; DPR и API shape неизменны. Максимальная сторона подготовленного изображения 4096 (detail при DPR 8). Ключ существующего кэша содержит размер, поэтому новые варианты получаются автоматически без удаления данных; исходные URL/фото/история не меняются.
- Из-за увеличения фото плитка становится выше; синхронно обновить сетку, оценку виртуальных строк и относящиеся к геометрии проверки.

План исправлений: правки CSS/разметки и подписей → размеры PNG/mock и затронутые API/image tests → целевые автоматизированные проверки → обновление постоянных контрактов → коммит и индексы. Desktop-сборку и ручную/native проверку выполняет пользователь; их не запускать.

### Окно настроек и форма

Панель настроек реализовать существующим Dialog/Sheet с семантикой диалога, явными заголовком и закрытием. На desktop её левая граница отстоит на 12 px от правой границы sidebar, низ находится в 16 px от низа окна; высота по содержимому, ширина до 420 px с ограничением по свободной области окна. Не открывать панель от правой границы всего приложения. На узком экране допустима адаптация. Доступна из каталога и деталей; в demo импорт/экспорт работают через mock, а нативные настройки не должны вызывать Tauri. Фоновые настройки использовать как содержимое новой панели, удалить старый самостоятельный Popover. Импорт/экспорт — явные действия внутри настроек; убрать старый пункт меню, а не дублировать. Проверить переход к диалогу импорта, системному выбору файла и возвращение фокуса.

Новая схема одного поля относится к добавлению. При редактировании не терять сохранённый URL и выбор главного варианта; идентификатор/площадка остаются неизменяемыми. Существующие frontend-парсеры URL умеют извлекать ID для известных форматов ссылок, но это не новый надёжный backend-контракт получения товара по произвольной ссылке. Последний остаётся будущей задачей; не удалять сохраняемые ссылки товара и используемые парсеры как будто URL полностью отменён. Если перенос существующего редактирования URL потребует изменения согласованного поведения, согласовать это отдельно до реализации.

### Скрытый запуск и восстановление

Согласованное решение — штатный скрытый main, без splashscreen.

- Начальная visible=false задаётся до создания main, чтобы исключить мигание. Сохранить существующий запуск служб, сериализацию ensure_services и события services-changed/services-error; не дублировать контроллер служб.
- При обычном запуске показать main один раз, когда получена конфигурация готовых служб и frontend смонтировал основной интерфейс. Не ждать сбора цен, загрузки всех картинок или завершения фонового обновления. Первое получение каталога может иметь обычное состояние загрузки в самом каталоге.
- До конфигурации API сохранить gate запросов и операций; скрытый WebView может загружаться заранее. Простой показ из monitor после ensure_services недостаточен: нужен сигнал готовности frontend, согласованный с native состоянием. Проверить порядок событий и случай, когда службы готовы раньше подписки WebView.
- Обычный запрос открытия через ярлык, second instance и tray во время запуска запоминается и выполняется после готовности. Все пути должны использовать одно правило открытия.
- При --background после готовности не показывать окно и не забирать фокус. Явный запрос пользователя через ярлык/tray разрешает показ после готовности.
- Ошибка запуска не должна оставлять обычный запуск невидимым навсегда: показать в существующем main компактное состояние ошибки с повтором и выходом. Это экран ошибки, а не постоянная заставка. Для фонового старта сохранить скрытый режим и доступ к ошибке при явном открытии.
- Повтор запуска не создаёт новый экземпляр/окно; восстановление служб после работы не должно самопроизвольно раскрывать закрытое окно. Начальное решение о показе отделено от регулярных событий восстановления.
- Если не загрузился сам WebView и frontend не может отрисовать ошибку, предусмотреть native сообщение средствами уже подключённого dialog, а не бесконечное скрытое ожидание. Предел ожидания привязать к существующим таймаутам запуска; конкретное значение определить по текущим службам без изменения их политики.

Это локальная правка desktop lifecycle, не перенос управления службами в новую архитектуру. Миграций данных и нового процесса нет. Затрагивает Rust↔frontend IPC: будущую команду готовности окна зарегистрировать в invoke_handler и проверить реальный путь; граф не доказывает такую связь автоматически.
