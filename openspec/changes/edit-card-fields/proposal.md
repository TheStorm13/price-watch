# Proposal

## Why

В деталях карточки можно отдельно сохранить теги, но нельзя изменить название и ссылку. Нужна заполненная панель редактирования по образцу создания, сохраняющая идентичность товара и историю.

## What Changes

- Кнопка «Изменить» в шапке деталей открывает боковую панель с текущими значениями.
- Редактируются название, URL и до двух тегов. Пустые название и URL очищают соответствующие значения, пустые теги сохраняются как пустой список.
- Маркетплейс, артикул, SKU AliExpress и код размера WB доступны только для чтения; изменение ссылки не меняет идентификаторы.
- Сохранение обновляет существующую карточку через действующий PATCH; отмена не сохраняет черновик. Ошибка сохраняет введённые значения и позволяет повторить запрос.
- Отдельная встроенная форма тегов заменяется общей панелью.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `desktop-ui-layout`: панель редактирования карточки и замена отдельной формы тегов.

## Impact

Форма карточки, страница деталей, тесты компонентов и браузерные сценарии. Используются существующие useUpdateCard и API. Проверить соответствие mock API действующему PATCH, особенно очистку полей. Создание карточки сохраняет прежнее поведение. Новые зависимости, миграции БД и изменения контрактов CLI/worker/числового JSON-режима не требуются. История, цены, группа и настройка выгодных предложений не изменяются редактированием этих полей.

Критерии приёмки: предзаполнение; сохранение и очистка трёх полей; фиксированная идентичность для всех площадок; ошибки и отмена; обновлённые детали и каталог; отсутствие регрессии создания.
