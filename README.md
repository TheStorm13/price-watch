# price-watch

Приложение хранит карточки маркетплейсов в PostgreSQL, получает актуальное
состояние через унифицированные коннекторы и накапливает историю цен. Сейчас
реализован интерактивный коннектор Ozon; цена Ozon берётся только из
`cardPrice`.

Подробности: [спецификация](docs/SPECIFICATION.md) и
[план реализации](docs/IMPLEMENTATION_PLAN.md). Найденные задачи для следующих
версий записаны в [backlog](docs/BACKLOG.md).

Руководство по текущему коду, запуску и известным ограничениям находится в
[docs/guide](docs/guide/README.md).
Общая схема процессов и контрактов — в [обзоре архитектуры](docs/architecture/overview.md).

Интерфейс находится в каталоге `frontend` и работает с реальным API через
Tauri desktop. Команда `npm --prefix frontend run dev:e2e` запускает
тестовый стенд с mock API для браузерных E2E без PostgreSQL.
В карточке доступны разница между минимумом и максимумом и график с масштабом
по видимым ценам. Пока worker работает, он автоматически ставит полный сбор
в очередь через 6 часов после начала последнего полного запуска. Ошибочные карточки можно
повторить со страницы запуска; фильтр «Выгодные предложения» на странице карточек сравнивает
последнюю цену с исторической средней и показывает новые предложения после сбора.
Карточки, исключённые из выгодных предложений, сохраняют историю и продолжают участвовать в ручном и автоматическом сборе.
На странице «Карточки» кнопки «Экспорт» и «Импорт» переносят карточки со всей
сохранённой историей цен. Перед импортом приложение показывает число новых и
объединяемых карточек; повторный импорт не дублирует наблюдения.

Имя проекта, desktop-приложения и исполняемого файла — `price-watch`.
Python-пакет называется `price_watch`; для переопределения каталога проекта
используется `PRICE_WATCH_PROJECT_DIR`. После обновления пересоберите desktop.

### Desktop-запуск

Основной режим для одного ПК — Tauri-приложение. Запуск из корня проекта:

```bash
./price-watch
```

Приложение запускает локальные PostgreSQL, API, Xvfb и Playwright
worker. Для этого нужны системные `postgresql`, `xorg-server-xvfb`,
`xorg-xauth` и Google Chrome; подробности — в [инструкции](docs/guide/NATIVE_DESKTOP.md).
При старте приложения Chrome не открывается. Кнопка «Открыть Chrome»
запускает видимый браузер с профилем приложения и вкладками Ozon,
Wildberries, AliExpress и Яндекс Маркета для входа на сайты. При ручном
обновлении приложение закрывает этот браузер, а worker запускает Chrome с тем
же профилем на скрытом
дисплее. Перед автоматическим сбором worker также закрывает видимый Chrome
приложения. В настройках desktop можно включить запуск в фоне после входа
в графическую сессию. При включённом режиме закрытие окна скрывает интерфейс,
но службы продолжают сбор; повторный запуск ярлыка или значок приложения
открывает окно. Действие «Полностью выйти» останавливает службы. При выключенном
режиме закрытие окна завершает приложение. Пропущенный срок проверяется при
следующем запуске worker; при выключенном ПК сбор не выполняется.

Пересобрать desktop-бинарник после изменения исходников:

```bash
npm --prefix frontend ci
npm --prefix frontend run desktop:build
```

Сборка создаёт исполняемый файл Tauri `frontend/src-tauri/target/release/price-watch`.
Команда использует `--no-bundle`: AppImage и другие установочные пакеты не собираются.
Готовый Linux-архив и рецепт пакета `price-watch-bin` описаны в
[руководстве по упаковке](docs/guide/PACKAGING.md).
`./price-watch` запускает именно этот файл. Для desktop worker требуется установленный
Google Chrome; скрытый дисплей Xvfb запускается локально.

Для разработки с hot reload используется:

```bash
npm --prefix frontend run desktop
```

Логи локальных служб находятся в `$XDG_STATE_HOME/price-watch/` (по умолчанию
`~/.local/state/price-watch/`).

## Локальная разработка

```bash
python -m venv .venv
source .venv/bin/activate
pip install --require-hashes -r requirements.txt
pip check
```

При локальном запуске Playwright использует установленный Google Chrome через
канал `chrome`, поэтому отдельная команда `playwright install-deps` на Arch
Linux не нужна.

Для прямых команд CLI с отдельным PostgreSQL задайте `DATABASE_URL`:

```bash
export DATABASE_URL='postgresql://user:password@localhost:5432/price_watch'
```

Подключённая база должна существовать. Примените миграции:

```bash
.venv/bin/python main.py db migrate
```

Команда повторяемая: уже применённые миграции будут пропущены.

## Работа с карточками

Одна карточка принадлежит одному маркетплейсу. Одинаковый физический товар на
разных площадках добавляется отдельными карточками.

```bash
.venv/bin/python main.py card add \
  --marketplace ozon \
  --external-id 1604900984

.venv/bin/python main.py card list
```

## Сбор цен

Собрать все карточки:

```bash
.venv/bin/python main.py collect
```

Собрать одну карточку:

```bash
.venv/bin/python main.py collect --card-id 1
```

Прямой CLI-сбор по умолчанию откроет обычный видимый Chrome с отдельным профилем
`.playwright-profile`, после чего Playwright подключится к нему по CDP. Для CLI
доступен флаг `--headless`. Desktop worker запускает свой Chrome со скрытым
дисплеем и тем же профилем. Коннектор открывает одну общую страницу
`https://www.ozon.ru/` на сеанс и получает товары через JSON-запросы `fetch`
с `credentials: "include"`. Карточки товаров не открываются. Авторизация
и регион доставки берутся из существующего профиля Chrome.
Если при desktop сборе Ozon запрашивает ручную проверку, сбор сообщает
ошибку: после него откройте Chrome кнопкой, пройдите проверку и повторите сбор.
При прямом CLI-сборе подтверждение остаётся в терминале и относится к общей
вкладке Ozon.

По умолчанию до пяти товарных запросов выполняются одновременно. Локальный
ограничитель разрешает 5 стартов в секунду с начальным запасом 5; это политика
приложения, а не официальный лимит Ozon. Каждый запрос имеет отдельный
30-секундный таймаут и может быть отменён без прерывания соседних. Для временных
ошибок предусмотрено до трёх HTTP-попыток; `Retry-After` задаёт общую паузу.
Если требуемая пауза превышает 30 секунд, запрос завершается ошибкой ограничения
частоты без раннего повтора. Один раз за сеанс возможно восстановление через
общую страницу после завершения активных запросов. Постоянный отказ доступа
останавливает новые отправки этого сеанса.

Результаты и ошибки сохраняются по карточкам; запись в PostgreSQL выполняется
последовательно. Ошибки доступа, таймауты, HTML, неверный JSON и общий HTTP 404
не означают отсутствие товара и не записываются как успешная цена.

По умолчанию Chrome запускается через X11/XWayland, поскольку нативный Wayland
может падать при старте на некоторых конфигурациях Linux. Режим можно изменить
через `--chrome-platform wayland` или `--chrome-platform auto`.

При необходимости задайте исполняемый файл Chrome:

```bash
.venv/bin/python main.py collect \
  --chrome-binary /usr/bin/google-chrome-stable
```

Ошибка одной карточки записывается в лог, увеличивает `failure_count` запуска и
не останавливает остальные карточки. Отдельной таблицы попыток нет.

## История и запуски

В каталоге можно создать группу товаров и выбрать для неё несколько карточек.
Группа выбирает представителя с минимальной известной текущей ценой независимо
от наличия; при равенстве выбирается меньший ID. Все товарные показатели, включая
исторический минимум, принадлежат этому представителю. Каждая карточка по-прежнему
собирается отдельно, включая исключённые из выгодных предложений. Удаление
группы не удаляет товары. Экспорт и импорт сохраняют состав групп; при импорте
уже существующие назначения карточек в группы не перезаписываются.

```bash
.venv/bin/python main.py history --card-id 1 --days 30
.venv/bin/python main.py run last
```

Команда `history` возвращает наблюдения и статистику. Средняя цена рассчитывается
как среднее дневных средних только для доступных товаров с известной ценой.
Интерфейс отдельно показывает середину диапазона между минимумом и максимумом.
При текущем сборе новая точка не добавляется, если цена и наличие совпадают
с последней сохранённой точкой. Миграция `0004` сохраняла первую и последнюю
точки старых участков одинакового состояния. График строится по
сохранённым изменениям выбранного периода,
а вертикальная ось охватывает видимые цены с отступом 10%.
Ошибки по товарам и полный traceback доступны в деталях запуска.

## Унифицированный контракт коннектора

Коннектор обязан реализовать асинхронные `get_product` и `collection_session`.
Каждый вызов возвращает `marketplace_connector.MarketplaceCard`. API, worker
и PostgreSQL-репозиторий также работают асинхронно.

Путь Ozon: ответ → `OzonProductData` → `OzonMapper` → `MarketplaceCard`.
Для другой площадки используются её собственные модель и mapper. Локальный
`TrackedCard` хранит ID базы, группу, теги и настройки отдельно от полученного
товара. Цены в Python — `Decimal`, в PostgreSQL — `NUMERIC`, в API/CLI JSON —
десятичные строки. Новые товарные JSON имеют версию `2.0`.

Сокращённый пример товарного JSON:

```json
{
  "schema_version": "2.0",
  "ref": {"marketplace": "ozon", "external_id": "1604900984"},
  "title": "Название товара",
  "availability": "in_stock",
  "price": "577.00",
  "collected_at": "2026-09-21T12:00:00+00:00"
}
```

Формальная схема расположена в
`marketplace_connector/serialization/product.schema.json`. Новый маркетплейс
реализует один порт:

```python
from contextlib import AbstractAsyncContextManager
from typing import Protocol
from marketplace_connector import MarketplaceCard

class MarketplaceConnector(Protocol):
    marketplace: str

    def collection_session(self) -> AbstractAsyncContextManager[None]:
        ...

    async def get_product(self, external_id: str) -> MarketplaceCard:
        ...
```

## Одиночный запуск Ozon без БД

Получение одного товара без PostgreSQL:

```bash
.venv/bin/python main.py 1604900984
.venv/bin/python main.py 1604900984 --raw > raw-ozon.json
```

## Тесты

Unit-тесты не требуют PostgreSQL или браузера:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Frontend-проверки:

```bash
cd frontend
npm test
npm run test:e2e
npm run desktop:build
```

Интеграционный тест репозитория запускается только с явно заданной отдельной
тестовой базой:

```bash
export TEST_DATABASE_URL='postgresql://user:password@localhost:5432/price_watch_test'
.venv/bin/python -m unittest tests.test_postgres_integration -v
```
