# ADR 0014: Асинхронный сбор Ozon без планового лимита частоты

- Статус: Accepted (design), выбран пользователем 2026-11-08; проверен экспериментальный стенд, внедрение в обычный сбор ещё не выполнено.
- Дата: 2026-11-08
- Уточняет [ADR 0006](0006-ozon-session-json-transport.md): заменяет выбранную политику фиксированных 5 стартов/с. Исторический ADR не переписывается.

## Решение

Выбранный подход для Ozon — асинхронный браузерный JSON-сбор через существующий
профиль Chrome, без планового ограничения стартов запросов (`starts_per_second=None`),
с конечным настраиваемым пределом N одновременно выполняемых HTTP-запросов.
Сохраняются общий Retry-After/cooldown, таймауты, ограниченные повторы,
независимая отмена и согласованное восстановление сессии.
Проверка доступа/CAPTCHA не является поводом бесконечно повторять запросы.

N=5 — измеренная рабочая точка, не установленный оптимум и не официальный лимит Ozon.
Способ выбора N (фиксированный или адаптивный), диапазон и пороги ещё не согласованы.
Это решение не распространяется на AliExpress и Wildberries.

## Основания и ограничения

На одинаковых 40 SKU проведены A/B/C/C/B/A и C/D/D/C, с паузами 30 секунд,
в видимом Chrome с существующим профилем. A=(5,5/с), B=(1,5/с),
C=(1,без плановой частоты), D=(5,без плановой частоты).
В отдельной C/D-серии среднее время C=5,919561 с, D=1,424168 с: ускорение 4,1565 раза.
Все 160 сборов этой серии успешны, HTTP 200, без 429, повторов и восстановления.
Наличие полей и их счётчики совпали во всех десяти прогонах; значения цен и
содержимое полей на равенство не сравнивались. Один SKU был не в наличии без цены.
B исключён пользователем из следующего исследования.

Это короткие серии по два прогона на режим на прогретых связанных SKU.
Длительная устойчивость, другие системы и значения N выше пяти не проверены.
Нет основания объявлять снятие планового лимита универсально более надёжным.
Headless-попытка получила отказ доступа и не смешивается с видимыми измерениями.

Доказательства и история реализации: [результат эксперимента](../../openspec/changes/experiment-ozon-serial-dispatch/spec.md),
[сырые A/B/C-метрики](../../openspec/changes/experiment-ozon-serial-dispatch/measurements.json),
[сырые C/D-метрики](../../openspec/changes/experiment-ozon-serial-dispatch/measurements-cd.json).

## Внедрение

Обычный транспорт пока сохраняет defaults concurrency=5, starts_per_second=5;
None доступен как явный параметр и используется стендом. Перед внедрением выбранной
политики нужно согласовать управление N и все вызывающие пути. Общий сборщик также
имеет предел пяти карточек: повышение только транспортного N не даёт соответствующего
параллелизма queued/CLI-сбору. Контроллер должен учитывать все product/modal-запросы
и повторы в общем бюджете, не умножать N числом клиентов, а локальные CPU/память
Chrome рассматривать как дополнительный предел. Схемы данных и история цен не менялись.
