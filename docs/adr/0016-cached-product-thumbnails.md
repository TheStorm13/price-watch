# ADR 0016: Кэшированные миниатюры списка в локальном API

- Статус: Proposed.
- Дата: 2026-11-08.
- План и критерии: [cached-product-thumbnails](../../openspec/changes/cached-product-thumbnails/spec.md).

## Контекст

Список показывает исходные фотографии в области 68 × 68 CSS px. Пользователь
выбрал предварительно уменьшенный Pillow Lanczos PNG с длинной стороной 204 px
после сравнения с исходником и вариантами 68/136. Крупный просмотр должен
сохранять исходное качество. Повторное открытие списка не должно запускать
обработку всех фотографий заново; существующие карточки должны работать без
повторного сбора и миграции данных.

## Варианты

1. Браузерный canvas/IndexedDB: не гарантирует воспроизведение принятого Lanczos,
   переносит загрузку исходников и обработку в WebView.
2. Подмена размеров в CDN URL: требует отдельных контрактов площадок и не
   гарантирует тот же алгоритм/качество для всех источников.
3. Подготовка при сборе: связывает фотографии с worker/CLI и требует отдельного
   заполнения кэша для существующих карточек.
4. **Локальный API с дисковым кэшем по первому запросу**: один рецепт обработки,
   общий кэш между открытиями, работа существующих карточек без backfill.

## Предлагаемое решение

API читает URL основного фото по cardId и выдаёт готовый PNG 204 px через
защищённый endpoint. Сервис использует httpx, Pillow вне event loop, атомарный
кэш в XDG_CACHE_HOME и ограниченную параллельность с объединением повторов.
URL, версия обработки и проверка актуальности управляют кэшем; размер кэша
ограничен. Сетевые и декодирующие операции имеют лимиты и проверяют внешние
адреса/редиректы. Клиент не передаёт произвольные URL для загрузки сервером.

Frontend загружает PNG с заголовком авторизации, использует Blob/object URL
с освобождением ресурсов и отображает миниатюру только в строках каталога.
Оригинальное imageUrl, БД, история, экспорт и сборщики сохраняют свои контракты.
Существующий mock API использует синтетическую тестовую фикстуру без живых сервисов.
Отдельный экспериментальный экран сравнения удалён и не входит в изменение.

## Последствия

Появляются runtime-зависимость Pillow и восстанавливаемый дисковый кэш.
Первое открытие ещё не подготовленного фото требует загрузки исходника и CPU;
следующие используют готовый файл. Кэш можно восстановить повторными запросами
без изменения БД. Ошибки фото приводят к заглушке, не к отказу каталога.
Измерения нагрузки выполняются отдельно; выбранный размер сам по себе не
доказывает качество всех фотографий и быстродействие всех CDN.
