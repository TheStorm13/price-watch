# ADR 0009: Вариант товара WB и цена с WB Кошельком

- Статус: Accepted — план и реализация приняты пользователем 2026-10-27.
- Дата: 2026-10-27.
- Change: [add-wildberries-connector](../../openspec/changes/archive/2026-10-27-add-wildberries-connector/proposal.md).

## Контекст

Пользователь согласовал одну цену: WB Кошелёк → обычная, и отслеживание
конкретного размера. У nmId 179224846 размер 58–60 имеет optionId 296499716.
Товарный JSON содержит product=105600 копеек, wallet=0, но витрина показывает
1024 ₽ с кошельком и 1056 ₽ без. Скидка берётся из условий текущей сессии:
при исследовании 3%, скидка после округления 32 ₽. Открытие главной само по
себе не гарантирует готовности условий: до их инициализации helper возвращает 0.
Источники и ограничения исследования — [research](../workflow-runs/add-wildberries-connector/research.md).

## Варианты идентичности

1. Только nmId: допускает смену размера и минимальной цены.
2. nmId и размер из изменяемого URL: неполная идентичность standalone lookup.
3. Новая обязательная часть общей модели/колонка: распространяет особенность
   WB на все площадки и схемы сериализации.
4. `external_id=nmId:optionId`: полный ключ в существующем строковом поле,
   как у AliExpress в ADR 0008.

Выбран вариант 4. WB URL имеет `?size=optionId`; UI разбирает ссылку и предлагает
отдельные поля артикула и кода размера. Новая numeric-only карточка WB
недопустима. Пользовательская подпись размера не заменяет стабильный optionId.

## Варианты транспорта и кошелёчной цены

1. Прямой HTTP и price.product: блокируется и не содержит кошелёчную цену.
2. Считать всегда минус 3%: неверно при изменениях условий, лимитах и запретах.
3. Парсить отображаемую цену с каждой карточки: требует навигации для каждого
   товара, затрудняет размерную идентичность и параллельный сбор.
4. Использовать runtime витрины на общей главной странице: её товарный JSON,
   актуальные условия и нормализацию размеров; ограничить и проверять этот
   путь в WB-адаптере.

Выбран вариант 4. Проверен `wb.xnm.getXnmProducts` с главной, а после инициализации
скидки — размерная `price.paymentDiscountAmount=32`. `price.wallet=0` не
означает отсутствие скидки. Цена выбранного размера вычисляется из его
priceToShow и именно кошелёчной paymentDiscountAmount. Более низкая скидка
стороннего банка не участвует. Нормализованные денежные значения передаются
как точные строки копеек и Decimal; в общий товар попадает одна price.

Недокументированный runtime — явная зависимость адаптера. Отсутствие функций,
невозможность подтвердить готовность условий и повреждённая схема завершаются
ошибкой. Код приложения не копирует и не хранит JS WB, cookie, JWT, deviceId,
баланс и персональные сведения. Фиксированных версий бандлов/процентов нет.

## Границы и последствия

Новый WB adapter переиспользует ChromeSession из ADR 0008; Ozon/Ali транспорты
не заменяются. Сайт может иметь собственные повторы: общий бюджет, rate-limit,
HTTP 429 cooldown и AbortSignal должны охватывать и их. Без этого транспорт
не проходит приёмку. Готовность скидки проверяется до результата, а не по
одному значению ноль. Доказанное отсутствие скидки допускает обычную цену;
ошибка её загрузки не допускает скрытого перехода.

Общую входную валидацию идентичностей вынести из Ali adapter в
`marketplace_connector/application/card_identity.py`; все consumers обновить,
старый общий entry point в Ali удалить. Общая модель товара и JSON/transfer
версии сохраняются. Дополнительные цены не сохраняются даже в extensions.

Data-only migration преобразует только валидные пары из старых WB-ссылок,
с preflight конфликтов. Неразрешимые записи сохраняются целиком и получают
ошибку «Не указан размер» при сборе; нет выбора первого размера, удаления,
слияния и переписи historical snapshot. Применение к пользовательской БД
не входит в исследование. Подтверждение этого ADR не является приёмкой кода.
