# ADR 0012: Семейство Ozon с самостоятельными артикулами вариантов

- Статус: Proposed — ожидает согласования пользователя.
- Дата: 2026-11-04.
- Change: track-ozon-product-variants.
- Дополняет ADR 0011 для Ozon; существующие ADR не переписываются.

## Контекст

Ozon идентифицирует каждое сочетание параметров собственным SKU. Живой обход товара 2936650207 показал 12 SKU, первый ответ — 7. Нынешние правила принадлежности WB/Ali через общий префикс непригодны; mapper уже возвращает непосредственных соседей, но сохранение не расширяет цели Ozon.

## Альтернативы

1. Раздельные карточки и ручная группа: нет единого владельца настроек и выбора главного варианта.
2. Первый webAspects как полный список: доказанно пропускает размеры второго цвета.
3. Выдуманный общий ID или группировка по названию: нет подтверждённого контракта, риск смешения разных товаров.
4. Стабильная локальная карточка, точные SKU и проверенное членство: переиспользует независимые истории и существующий цикл pending-целей.

## Предлагаемое решение

Вариант 4. Артикул первого добавленного SKU остаётся точкой входа карточки, но её варианты имеют разные артикулы. Подтверждение членства — структурные ссылки вариантов Ozon в точном ответе уже принадлежащего карточке SKU. Обычный сбор обходит связи через атомарно расширяемые цели запуска; каждый SKU получает собственные параметры, цену и историю. Неполный обход виден как ошибка. Add/discovery/import согласованно предотвращают принадлежность SKU разным карточкам; существующие конфликты не разрешаются автоматическим удалением или объединением данных.

## Последствия

Нужно заменить правило равенства корневого артикула для Ozon во всех потребителях, включая transfer. Существующие данные не группируются офлайн и история не переносится. Полный обход требует дополнительных запросов, ограниченных текущим транспортом и пределом SKU. Numeric JSON остаётся точным одиночным снимком. Реализация и применение на пользовательской БД не разрешены этим предложением до согласования плана.
