# ADR 0006: Ozon JSON через общую страницу браузерной сессии

- Статус: Accepted — план и реализация приняты пользователем
- Дата: 2026-10-26
- OpenSpec: [ozon-session-json-transport](../../openspec/changes/archive/2026-10-26-ozon-session-json-transport/proposal.md)

## Контекст

Клиент уже получает composer JSON через fetch внутри Chrome, но сначала открывает отдельную вкладку товара. Профиль Chrome хранит авторизацию и регион доставки. Реальная проверка из главной страницы Ozon в профиле price-watch вернула HTTP 200 и данные, которые существующие parser/mapper преобразовали без изменения контракта. Свежий временный профиль получил 403 с JSON блокировки.

## Варианты

1. Сохранить переходы на товары: не достигает цели убрать навигацию и загрузку страниц.
2. Выполнять fetch из общей страницы Ozon в существующем контексте: сохраняет проверенный браузерный транспорт и состояние профиля, убирает переходы к товарам.
3. Отдельный HTTP-клиент или APIRequestContext: эквивалентность браузерному fetch не подтверждена в целевой среде; перенос cookies не является доказательством работоспособности.

## Решение

Вариант 2: одна страница Ozon на сеанс, GET composer page/json/v2 с закодированным путём товара и credentials: include. По явному требованию пользователя сохраняется асинхронный параллелизм **5 по умолчанию**: до пяти fetch реально выполняются одновременно, без блокировки на всё время запроса. Независимый ограничитель частоты первоначально разрешает 5 стартов в секунду с burst 5; обязательной паузы в секунду между отдельными запросами нет. Это политика клиента, а не официальный лимит сайта.

Каждый запрос имеет свой AbortController; отмена одной задачи не закрывает общую страницу. Retry-After задаёт общую паузу для новых отправок и повторов, не прерывая начатые запросы. Восстановление сессии выполняется одной общей операцией после завершения активных запросов; одновременные ошибки доступа не вызывают несколько reload. Не более одной автоматической попытки восстановления на сеанс и трёх HTTP-попыток на товар. После исчерпания попыток ошибка видна вызывающему коду.

Источники полей, типы, cardPrice, общий рейтинг, raw, интерфейсы CLI/коннектора и правила хранения сохраняются. Старый транспорт с отдельной вкладкой каждого товара удаляется. Browser.close и штатное ожидание процесса сохраняют профиль. Очистка cookies/хранилища и перенос данных профиля не нужны.

## Последствия

Транспорт не загружает документы товаров и сохраняет текущий параллелизм. Общая страница требует согласования cooldown и восстановления, а также независимой отмены запросов. Тесты должны доказать пересечение пяти запросов во времени и ожидание шестого. Влияние на скорость проверяется при одинаковом параллелизме старого и нового транспорта. Работа остаётся зависимой от Chrome, доступа Ozon и недокументированной JSON-схемы. Схемы БД и миграции данных не затрагиваются.
