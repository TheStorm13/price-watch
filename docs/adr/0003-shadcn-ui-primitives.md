# ADR 0003: shadcn/ui как общая основа компонентов

Статус: **Accepted**. Дата: 2026-10-21. Приёмка реализации: 2026-10-26.

## Контекст

UI использует собственные компоненты и общий CSS. Пользователь хочет перейти на shadcn/ui и продолжать разработку через Codex со skills и MCP.

## Решение

Использовать shadcn/ui из официального `@shadcn`, Tailwind 4, одну базу примитивов Radix и семантическую тему. Исходники примитивов хранить в проекте, предметную логику — в feature-компонентах. Подключить профильный skill и официальный shadcn MCP для Codex. Мигрировать по этапам с сохранением сценариев, контрактов и плотности UI.

## Альтернативы

- Собственные компоненты: минимальная миграция, самостоятельное сопровождение базового поведения.
- Mantine или MUI: готовые библиотеки с иной моделью настройки, не выбранные пользователем.
- shadcn/Base UI: допустимая альтернативная база; требует другого API композиции. Предложение Radix не означает доказанного превосходства над Base UI.
- Полная одномоментная замена: проще удалить legacy CSS, труднее локализовать визуальные и поведенческие регрессии.

## Последствия

Добавляются frontend-зависимости и ответственность за локальный код компонентов. Нужны контроль CSS cascade, keyboard/focus tests и WebView smoke. Данные, backend, CLI и интерфейс Tauri invoke сохраняются. Подробный план: `openspec/changes/archive/2026-10-26-migrate-ui-to-shadcn/design.md`.

План согласован до реализации. Пользователь принял завершённую миграцию 2026-10-26: «Миграция UI на shadcn завершена, все окей». Проверки и ограничения сохранены в [отчёте](../workflow-runs/migrate-ui-to-shadcn.md).
