# ADR 0005: Общий товар, запись отслеживания и точные цены

- Статус: Accepted, план и реализация приняты пользователем 2026-10-25.
- Change: [unify-marketplace-card-model](../../openspec/changes/archive/2026-10-25-unify-marketplace-card-model/proposal.md).
- Детали: [design](../../openspec/changes/archive/2026-10-25-unify-marketplace-card-model/design.md).

## Контекст

ProductSnapshot — общий результат коннектора, MarketplaceCard — локальная
запись, старый ProductCard — дублирующее представление. Имена скрывают роли,
а Ozon mapper/нормализатор/API переводят цены между Decimal, float и int.
Нужно одинаковое представление товара для всех площадок и независимый
числовой CLI без БД, сохранив пользовательские настройки и историю.

## Предлагаемое решение

MarketplaceCard в общем домене коннекторов описывает полученное состояние
товара и содержит ProductRef, Decimal-цену, наличие и collected_at вместе
с остальными нынешними товарными полями. Он не содержит локальные настройки.

TrackedCard в домене приложения описывает существующую строку marketplace_cards:
ID, ref, отображаемые поля, группу, теги и настройки. Каталог — проекция
локальной записи и метрик истории. Дополнительная таблица или восстановление
полного товара из JSONB при каждом запросе не нужны.

Путь каждой площадки: ответ → специфическая модель → mapper → MarketplaceCard.
Для Ozon вводятся OzonProductData и parser; данные других площадок не
подгоняются под поля Ozon, реальные новые коннекторы создаются отдельно.

Цены декодируются и вычисляются как Decimal, хранятся как NUMERIC и передаются
десятичными строками в JSON. Цены наблюдений округляются до двух знаков
ROUND_HALF_UP; средние не округляются до проверки выгодности. UI использует
точные строки, number — только для координат графика. Новые товарные JSON
имеют версию 2.0. Старые snapshots не переписываются.

## Альтернативы

1. Один плоский объект товара и настроек: меньше типов, но много необязательных
   полей, разные правила владения и риск перезаписи локальных настроек.
2. Сохранить ProductSnapshot и старый ProductCard: сохраняет неоднозначность
   и лишние преобразования, включая усечение цены.
3. Float только на HTTP-границе: оставляет потерю точности для потребителей.
4. Целые копейки: удобны для наблюдений, но не выражают точные дробные средние.
5. JSON numeric Decimal с особым JS-парсером: усложняет клиент и зависимости.

## Последствия

Нужен полный перевод Python-потребителей, API/CLI, frontend и packaging.
Старые импорты, модели и адаптеры удаляются; смешанные версии не поддерживаются.
HTTP-маршруты и плоские поля каталога сохраняются, денежные JSON-типы меняются.
Импорт v2 со строковыми ценами сохраняется; ранее допускавшийся numeric-ввод
цены становится ошибкой валидации. Настройки уведомлений мигрируют однократно
с сохранением pending работ и watermark.

Не меняются таблицы, история, связи, lease, атомарность и правила выгодности,
групп и расписания. Проверки данных выполняются только на disposable БД.
Профиль Chrome, восстановление служб и ARCH-03 backlog в это решение не входят.

## Принятие

и чистое дерево. Реализация принята 2026-10-25; разрешено включить также
предшествующие изменения. [Отчёт проверок](../workflow-runs/unify-marketplace-card-model/verification.md).
