# Фоновый трекинг цен

- Связанная задача: бывший пункт «Сбор и автоматизация / Фоновый трекинг цен» в `docs/BACKLOG.md`.
- Текущая фаза: завершено; Gate 3 принят 2026-10-20.
- OpenSpec change: `openspec/changes/archive/2026-10-20-background-price-tracking/`.

## Что изучено

- Worker уже раз в минуту проверяет срок полного сбора. Через 12 часов после начала последнего полного запуска он ставит новый в очередь, если нет активного запуска. Срабатывает только пока worker работает.
- Desktop поднимает PostgreSQL, Xvfb, API и worker по вызову `ensure_services` из загруженного React-интерфейса. Выход из Tauri останавливает службы.
- Локальные службы защищены эксклюзивным lock; два независимых desktop-процесса не могут просто совместно использовать их.
- Прямой CLI-сбор и JSON-режим одного товара имеют отдельные пути запуска.
- UI при открытии получает историю запусков и выгодные предложения из API; постоянное окно для просмотра результатов не требуется. Системные уведомления о скидках не входят в текущую задачу.

## Предлагаемое направление

Для Linux: один постоянно работающий desktop-процесс с опциональным запуском после входа пользователя в графическую сессию. При фоновом старте окно скрыто, службы запускаются без загрузки React. Закрытие окна скрывает его, повторный запуск открывает существующее окно; явная команда завершает приложение. Управление фоновым режимом — в интерфейсе. Интервал полного сбора меняется с 12 на 6 часов по уточнению пользователя.

## Риски и открытые вопросы

- Нужно проверить поведение повторного запуска, tray и закрытия окна на поддерживаемом Linux-окружении.
- Запуск после входа в систему не обеспечивает сбор до входа пользователя, при выключенном ПК или без пользовательской графической сессии.
- Для ошибки запуска фоновых служб нужна наблюдаемая диагностика и способ повторить запуск из интерфейса.
- Проверить взаимодействие автоматического сбора с открытым вручную Chrome.
- Текущий срок отсчитывается от начала последнего полного запуска, включая запуск с ошибками. Это правило нужно явно закрепить или изменить в спецификации.
- Изменение жизненного цикла desktop требует Proposed ADR и OpenSpec-плана после Gate 1.
- Независимая проверка плана обнаружила, что после перезапуска API меняются порт и токен, а текущий React-клиент хранит прежние значения. Спецификация и задачи дополнены обновлением подключения при открытом и скрытом окне.
- Независимая проверка плана обнаружила, что принудительная остановка worker во время сбора может оставить Chrome с занятым профилем. Дизайн и задачи дополнены штатным завершением с таймаутом, восстановлением профиля и проверкой сохранённой истории.

## Проверка фонового запуска и окна, 2026-10-20

- В отдельном временном каталоге данных и состояния запущен собранный release-бинарник с `--background`. До взаимодействия через AT-SPI у приложения не было видимого окна; PostgreSQL и worker работали.
- Повторный `./price-watch` завершился с кодом 0 и открыл окно существующего PID. Второй desktop-процесс и второй worker не появились.
- Tray зарегистрировался в GNOME StatusNotifierWatcher с пунктами «Открыть Price Watch» и «Выход». Закрытие окна при включённом режиме скрыло его, сохранив процессы; пункт «Открыть» вернул видимое окно. «Выход» завершил процесс и службы. При выключенном режиме закрытие окна завершило приложение.
- Переключатель UI создал `~/.config/autostart/Price Watch.desktop` с `Exec=.../price-watch-desktop --background`; отключение удалило запись. Зависимость `auto-launch 0.6.0` игнорирует `XDG_CONFIG_HOME` и использует `~/.config/autostart`, поэтому регистрация не была изолирована временным XDG-каталогом. Запись после проверки удалена через UI.
- `cargo test --locked recognizes_only_explicit_background_flag` прошёл. `desktop-file-validate packaging/aur/price-watch.desktop` завершился с кодом 0 и подсказкой о двух основных категориях меню.
- Настоящий выход из графической сессии и вход обратно не выполнялись.

## Тесты без реального сбора, 2026-10-20

- Добавлен Rust-тест переходов конфигурации: одинаковая конфигурация не публикуется повторно, ошибка очищает старое подключение, восстановление публикует новый порт и токен и снимает ошибку.
- Расширен нативный Rust smoke-тест на временной пустой базе: повторный вызов сохраняет одного worker, после штатной остановки worker перезапускается; после остановки API, Xvfb и PostgreSQL службы и worker восстанавливаются с новым токеном. Тест запущен отдельно с `PRICE_WATCH_NATIVE_SMOKE_ROOT`; реальных карточек и сборов не было.
- Тест отдельной `TEST_DATABASE_URL` теперь проверяет, что после устаревшего heartbeat запуск становится `failed`, получает диагностику `WorkerStopped`, а уже записанная цена остаётся в истории. Полный PostgreSQL-набор: 20 тестов прошли на новой временной базе.
- Новый браузерный E2E на mock API проверяет, что после перезагрузки интерфейса видны сохранённое выгодное предложение и ошибка завершённого запуска; 1 тест прошёл. Это не проверка живого backend.
- Прошли `cargo test --locked` (8 тестов, 2 инфраструктурных теста по умолчанию ignored), целевой ignored smoke-тест, 32 релевантных Python-теста без сети, `npm --prefix frontend test` (19 тестов) и `npm --prefix frontend run desktop:build`.
- Пункт 2.4 выполнен. Пункты 2.2, 2.3, 2.5, 3.3 и 4.2 остаются открытыми до завершения всех проверок, указанных в их формулировках. По запросу пользователя реальные сборы не выполнялись.
- Финальная проверка `packaging/build-local-aur.sh`: `bash -n` прошёл. Прямой запуск в рабочем дереве до коммита штатно отказал из-за незакоммиченных изменений. В отдельном временном чистом worktree со снимком текущих файлов скрипт завершился успешно: `npm ci`, сборка Tauri, релизный архив, проверка SHA-256 и `makepkg` для `price-watch-bin 0.1.5-1`. В пакете подтверждены бинарник, ярлык, `main.py`, `requirements.in` и `requirements.txt`. Временный worktree и пакет удалены.
