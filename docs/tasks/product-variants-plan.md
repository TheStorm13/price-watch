## Реализованный план

- Товар → варианты → независимые наблюдения; `primary_variant_id` для каталога, групп и выгодных предложений.
- Forward-only миграция 0018 сохраняет старые ID вариантов, историю и снимки; preflight останавливает объединение при конфликтах общих настроек.
- Discovery WB/Ali внутри выбранного товара, точная цена каждого SKU, одна браузерная сессия, пакетное добавление целей, отдельные ошибки/повторы без повторения успешных SKU.
- API вариантов/фильтра истории, transfer v3, согласованные CLI add/list; числовой Ozon JSON-режим без БД.
- Общая панель изменения, таблица вариантов с поиском/главным, цветные линии и переключатели видимости, отдельный вариант таблицы измерений.

### Результат исправления

- Форма, API и CLI принимают артикул без SKU; товарные ссылки с необязательным size/sku_id валидируются, чужой товар и конфликт точного варианта отклоняются.
- Product-only ответ содержит метаданные вариантов без цены и выбранного SKU. Lease-защищённое обнаружение добавляет точные цели в тот же запуск; каждая цена поступает через точный parser. Повтор обнаружения расширяет цели, повтор SKU остаётся точным. Следующий обычный/очередной/плановый запуск исключает уже завершённую цель обнаружения.
- История без известного SKU и прежний ID варианта не переписываются; записи без наблюдений скрыты после обнаружения точных SKU. Начальный главный назначается из ответа, точный существующий главный не меняется.
- Дополнительной миграции нет. Пользовательская БД и профиль Chrome не использовались; live-запросы к площадкам не выполнялись.
