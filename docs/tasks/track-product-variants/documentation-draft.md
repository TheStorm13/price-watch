# Изменения документации после приёмки

Этот текст подготовлен для применения после явной приёмки реализации по vibe-flow. Основные guides пока не изменены.

## DATA_AND_API.md

Карточка идентифицирует товар по marketplace + external_id (productId AliExpress или nmId WB). card_variants хранит точную идентичность productId:skuId / nmId:optionId, параметры, ссылку и время успешного сбора. marketplace_cards.primary_variant_id выбирает главный вариант. price_history.variant_id и collection_run_targets.variant_id различают истории и результаты SKU; card_id указывает товар. Удаление товара по-прежнему удаляет его варианты и историю.

GET /api/cards/{id}/variants возвращает все известные варианты, их цены, наличие и время обновления. PATCH /api/cards/{id} меняет title/url/tags/primaryVariantId и прежние настройки группы/выгодных; артикул и marketplace не редактируются. Главный вариант должен принадлежать товару. Ссылки WB/Ali должны соответствовать выбранному варианту.

GET /api/cards/{id}/chart содержит все SKU; каждая точка имеет variantId. GET /api/cards/{id}/history?variantId=... фильтрует историю и статистику; без variantId выбран главный. Каталог, сортировка, выгодность и представитель группы используют только главный SKU. lastCollectedAt — последнее успешное получение главного варианта, в отличие от даты изменения общих полей и последней точки изменения цены.

Export/import использует version:3. У товара есть primaryExternalId и массив variants; внутри каждого — externalId, title, url, options, updatedAt и history. Истории сливаются только в пределах одного SKU. Старый v2 отклоняется, скрытого преобразования нет. Импорт имеет preview и по-прежнему может компактировать одинаковые соседние наблюдения.

## ALIEXPRESS.md / WILDBERRIES.md / CURRENT_NUANCES.md

Добавляйте товар по полной ссылке с выбранным sku_id/size или укажите артикул и начальный вариант. Новая ссылка другого SKU того же артикула добавляет вариант в существующий товар. Во время обновления автоматически обнаруживаются и собираются остальные варианты этого артикула. У каждого SKU своя цена и история; исчезнувшие варианты не удаляются. Ошибка запроса не означает отсутствие товара.

В деталях «Варианты товара» показывает параметры, цену, наличие и время последнего успешного сбора. Кнопка «Сделать главным» выбирает SKU для каталога и его метрик, не перемещая историю. Поиск помогает найти размер/цвет/SKU в длинном списке. Разные линии графика соответствуют разным SKU; выключение линии в легенде не меняет главный вариант. Таблица измерений имеет отдельный фильтр вариантов.

Кнопка «Изменить» открывает боковую панель названия, ссылки, тегов и главного варианта. Артикул и площадка фиксированы. Отмена отбрасывает черновик, ошибка сохранения оставляет его для повтора. Пустые общие поля очищаются; название снова может заполниться при сборе по прежним правилам.

## ARCHITECTURE.md / architecture/overview.md

Добавить связь товар → варианты → наблюдения и variant_id целей. Состав товаров заморожен при создании запуска; новые SKU этих товаров расширяют обычный запуск атомарно с totalCount. Retry сохраняет только прежние неуспешные/необработанные SKU. Браузерный сеанс один на запуск, конкурентность по-прежнему ограничена пятью запросами. Цены берутся из проверенного ответа конкретного SKU; список метаданных вариантов сам по себе цены не доказывает.

Каталог не загружает истории/снимки всех SKU: текущая проекция и агрегации относятся к главному, варианты загружаются в деталях. Снимки JSON не читаются для current-price проекций и экспортируемой истории.

## Миграция 0018 и TESTING_AND_TROUBLESHOOTING.md

Перед upgrade остановить старые writers и завершить активные запуски. Миграция сохраняет ID вариантов, точки и старые snapshot JSON. Карточки разных SKU одного артикула становятся одним товаром; общий конфликт названия/тегов/группы/выгодных прерывает миграцию с ID карточек до изменений. Неоднозначные старые SKU сохраняются как требующие уточнения, без выдуманной цены. Downgrade не поддерживается.

Новые проверки: TEST_DATABASE_URL=<отдельная disposable БД> .venv/bin/python -m unittest tests.test_product_variants -v. Frontend: npm --prefix frontend test; npm --prefix frontend run lint; npm --prefix frontend run test:e2e; npm --prefix frontend run test:visual. PostgreSQL-проверки не запускать на рабочей БД. Native smoke остаётся отдельным и использует синтетические коннекторы; браузерный E2E проверяет mock UI.
