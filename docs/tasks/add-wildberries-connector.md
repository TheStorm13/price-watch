## Текущее устройство

Исходный HEAD: `a0157e14bdb58dcfa6081e7b1882df2bb4c34ddb`, рабочее дерево
до исследования чистое. Source получен CodeGraph с явным projectPath price-watch.

- `marketplace_connector/ports/connector.py`: `get_product(external_id)` возвращает
  общую `MarketplaceCard`, `collection_session` управляет ресурсами сбора.
- Ozon: `connector.py` вызывает async client → parser → mapper. Client использует
  `ChromeSession` и `OzonJsonTransport`: storefront session, браузерный fetch,
  ограничения частоты, cooldown, восстановление доступа, отмена запросов.
- Ozon mapper проверяет идентификатор ответа, берёт `cardPrice`, нормализует
  Decimal, наличие, продавца, рейтинг, характеристики, изображение и варианты.
- `marketplace_connector/connectors/builder.py` уже строит Ozon и AliExpress с
  одним владельцем Chrome. Новый адаптер должен учитывать этот lifecycle.
- `price_watch/cli.py`: direct collect и worker используют общий builder;
  worker передаёт DatabaseChallengeHandler. Это пути очередного сбора UI/API
  и прямого CLI. При реализации отдельно проверить database-free Ozon numeric
  mode и оба CLI imports.
- Общая модель обнуляет цену для OUT_OF_STOCK и требует уникальных ref вариантов.
- `price_watch/domain/marketplaces.py`: WB пока входит в
  PENDING_CONNECTOR_MARKETPLACES; UI уже имеет обозначение Wildberries.

JSON URL — исследовательская гипотеза, не подтверждённый контракт витрины.
Параметр dest также не согласован как регион приложения. Доступность товара,
актуальная JSON-схема, поля цены, размеры/варианты и остатки не подтверждены.
Не интерпретировать блокировку как отсутствие товара.

Ответы сохранены только во временных `/tmp/wb-probe-*`, `/tmp/wb-api-*`;
полные защитные заголовки и персональные сетевые метаданные в репозиторий
не копировались. `cua.getState()` показал apps=[], browsers=[]. Пользователю
запрошено подключить Chrome и при необходимости вручную пройти проверку WB.
После получения пользовательской ссылки повторная проверка `cua.getState()`
снова вернула apps=[], browsers=[]. Указание ссылки не подключило браузер.

## Согласование политики и готовность плана

Пользователь согласовал: «цена бралась именно с WB Кошельком как единственная,
или без если такоговой с кошельком нет. То есть приоритет, но цена всегда одна».
На отдельный вопрос о размерах выбран ответ: «Конкретный размер: каждая
карточка отслеживает выбранный размер». Это согласование требований,
не разрешение реализации ещё не представленного полного плана.

Подтверждён источник расчёта: storefront user grade (`/v6/grade?curr=RUB`),
в данном неавторизованном контексте discount_value=3; discount calculator
округляет 31.68 ₽ до 32 ₽, выбранная size.price.paymentDiscountAmount=32,
priceToShow=105600 копеек. После штатной инициализации условий runtime WB
на новой главной странице возвращает эти значения без product goto.
До инициализации тот же runtime возвращает ложный ноль даже при свежем cache.
Поэтому ошибка/неготовность условий не означает отсутствие кошелёчной цены.
Проверены также вычислительные запреты кошелька по флагу/слишком большой цене;
это не live-тест недоступного товара. Details — research.md и home-bootstrap.json.
Авторизованный WB-контекст не проверен live; production bootstrap обязан
учитывать авторизацию, а не всегда вызывать unauth initializer.

Создан OpenSpec `add-wildberries-connector`: proposal, два delta specs,
design, tasks (12 задач). Proposed ADR 0009 обосновывает размерный ключ
и использование актуального storefront runtime для расчёта вместо 3%/DOM.
Изменяются только planning/research документы, application code прежний.
Полный план ещё не одобрен; следующий шаг — первый review плана и ADR 0009.

Repowise: локальный index-only update завершился без model calls, но CLI risk
всё равно вернул старый indexed_commit 9f3876d9ba3f и no_such_path для новых
builder/session. Оценку риска не считать полученной; критичные consumers
валидатора, UI refresh и direct/worker проверены CodeGraph/current source.
Конфигурация MCP не исправлялась в рамках задачи.

Проверки планирования: `openspec validate add-wildberries-connector --strict`
прошёл. JSON и whitespace проверяются отдельно. Application tests не запускались,
пользовательская БД не открывалась. Профиль после live probes штатно освобождён.
Коммиты ещё не создавались: implementation review и acceptance впереди.
