# Wildberries: размер и цена с WB Кошельком

Исследование 2026-10-27, до реализации. Использованы существующий ChromeSession,
системный Chrome, CDP/no_defaults и desktop profile price-watch. БД не открывалась.
Первый 498 после навигации автоматически сменился успешной страницей; CAPTCHA
вручную или автоматически агентом не решалась. Chrome штатно закрывался.

## Источники

- Пользовательская карточка: https://www.wildberries.ru/catalog/179224846/detail.aspx?targetUrl=SN
- Наблюдаемый товарный JSON: `https://www.wildberries.ru/__internal/u-card/cards/v4/detail`.
  В query были appType, curr, dest, spp, hide_vflags, mtype, lang, ab_testing, nm.
- Статика: `https://basket-12.wbbasket.ru/vol1792/part179224/179224846/info/ru/card.json`.
- Условия неавторизованного кошелька: `https://ug-bt.wildberries.ru/user-grade-proxy/api/v6/grade?curr=RUB`.
- Публичные бандлы витрины на `static-basket-01.wbbasket.ru/vol2/site/app/c/`:
  `46130.ee781a05600fb228.js`, `84718.0977cbc80b1c2e1b.js`;
  product bundles `5858.499c0577d61b679c.js`, `9235.47161e41d74452b2.js`.
  Это observed версии для evidence, не версии, которые нужно зашивать в код.

Код витрины содержит `wb.xnm.getXnmProducts`, `proceedPrices`,
`getProductColorsByNmIdsAsync`, `wb.priceHelper.calcWalletDiscount` и user
grade initialization. Detail helper принимает AbortSignal, а его HTTP-клиент
имеет собственные повторы. Пустой результат может скрывать ошибку, поэтому
adapter должен проверять HTTP и идентичность отдельно.

## Товар

nmId 179224846, root 207853989, размер 58–60 (универсальный), optionId 296499716.
Идентичность для проекта — `179224846:296499716`. Код витрины читает размер из
query `size` и сопоставляет его с выбранной characteristic/option identity.
Связанный root объединяет несколько nmId и не является размерным ключом.

Название: «Шапка зимняя бини с отворотом двойная», ALDINI. supplierId 44721,
supplierRating 4.8, reviewRating 4.8, feedbacks 6470. При первом probe запас
выбранного размера — 10. card.json содержит 15 характеристик, описание,
16 фото и 17 связанных артикулов. Probe не доказывает работу произвольных
basket-хостов, всех товаров и отсутствующих размеров.

## Цена и проверка на главной

Сырой размерный price содержит product=105600, basic=710000, wallet=0,
нулевые logistics/return/cashback. UI детализация подтверждает 1024 ₽ с WB
Кошельком, 1056 ₽ без него. Нулевой raw wallet не равен отсутствию скидки.

Валидный свежий публичный cache `wbx_default_discounts` содержит wctype_id=1,
discount_value=3. Сайт получает этот процент из grade и обновляет с ограниченным
TTL, затем normalizer рассчитывает per-size paymentDiscountAmount в рублях.
Для текущих условий 3% от 1056 ₽ = 31.68 ₽, округлённая сумма скидки = 32 ₽;
цена с кошельком = 1024 ₽. Постоянный процент не является контрактом.
Helper учитывает saleConditions, лимиты, locale, currency и специальные
правила округления авторизованной сессии. Банковская скидка VTB — отдельное
поле: общий priceWithDiscount может выбирать её и не подходит для политики WB.

Live на новой странице главной без product goto:

- Повтор ранее наблюдаемого JSON URL с заголовками витрины вернул 200 два раза.
- Обычный fetch и попытки только с X-Requested-With/X-SPA-Version вернули 403.
- Штатный `wb.xnm.getXnmProducts` на главной получает товар в текущем профиле.
- Без явной готовности user grade helper/normalizer дал paymentDiscountAmount=0,
  несмотря на свежий cache со значением 3. Это ложное отсутствие скидки.
- После штатной инициализации условий неавторизованной витрины тот же helper
  дал per-size paymentDiscountAmount=32. В production нельзя применять unauth
  initializer к авторизованному пользователю; необходимо выбрать штатную
  ветку текущего auth-состояния и подтвердить готовность.
- Синтетические вызовы helper с запрещающим флагом и очень высокой суммой дали
  отсутствие кошелёчной скидки. Это проверка вычислителя, не live отсутствующего
  товара и не доказательство всех правил лимитов.

Последний homepage-only результат сохраняется в home-bootstrap.json после
повторной успешной проверки. Из него намеренно исключены payload/cookies/JWT,
deviceId/баланс/личные сведения. Параметр dest probe не фиксирует регион продукта:
реальный connector должен использовать выбор текущего профиля.

## Согласованные решения

Пользователь: «цена бралась именно с WB Кошельком как единственная, или без
если такоговой с кошельком нет». Также выбран конкретный размер для каждой
карточки, без минимальной цены по размерам. Политика согласована; полный
OpenSpec-план и ADR ещё требуют первого review до application changes.

Сбой запроса условий/неинициализированный runtime не доказывает отсутствие
кошелёчной цены. В таком случае план требует ошибку без записи новой цены.

## Ограничения

Live исследован один товар с одним размером в неавторизованном WB-контексте.
Не проверены live авторизация, разные размеры, другой регион, платная доставка,
восстановление, ограничения частоты, независимая отмена и mixed collection.
Эти случаи входят в implementation tests и приёмку, а не объявлены готовыми.
Рабочая БД не использовалась; application tests ещё не запускались.

## Metadata при реализации

`getProductColorsByNmIdsAsync` фактически возвращает компактную запись с
`nmId`, `n`, `c`, `dims`, `specs`; полного `options`/description в ней нет.
Коннектор переносит предоставленный `c` как характеристику «Цвет»; изображение
и описание остаются пустыми. Basket-хост не вычисляется.

## Итоговая живая сверка

После ожидания готовности `user.getXinfo()` перед grade/Xnm новый коннектор
вернул 1015.00 RUB для 179224846:296499716. Отдельная вкладка товара в том же
профиле показала детализацию: 1015 ₽ с WB Кошельком, 1047 ₽ без него.
Ранее в ходе реализации получено 1024.00 (1056−32); цена изменилась на WB.
Live mixed Ozon/Ali/WB успешен. Авторизованный WB-профиль live не проверялся;
auth-aware grade lifecycle покрыт synthetic Chrome тестом.
