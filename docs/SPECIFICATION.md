# Спецификация анализатора цен

## 1. Назначение

Приложение хранит карточки товаров маркетплейсов, запускает подходящие
коннекторы и сохраняет историю наблюдений в PostgreSQL. Одна карточка всегда
принадлежит ровно одному маркетплейсу. Одинаковый физический товар на Ozon,
Wildberries и AliExpress представлен тремя независимыми карточками.

Уведомления, правила снижения цены и автоматическое сопоставление товаров между
маркетплейсами не входят в текущую версию.

## 2. Основные сценарии

1. Пользователь добавляет карточку по имени маркетплейса и внешнему ID.
2. Пользователь запускает сбор для всех активных карточек или одной карточки.
3. Приложение выбирает коннектор по полю `marketplace`.
4. Коннектор возвращает унифицированный `ProductSnapshot`.
5. Приложение обновляет название и URL карточки и добавляет запись истории.
6. Ошибка одной карточки записывается в лог и не останавливает остальные.
7. Пользователь запрашивает текущую цену, историю и статистику за период.

## 3. Доменная модель

### MarketplaceCard

Карточка, добавленная для отслеживания:

- `id` — внутренний идентификатор;
- `marketplace` — идентификатор коннектора (`ozon`, `wildberries`, `aliexpress`);
- `external_id` — ID карточки на маркетплейсе;
- `title` и `url` — последние известные метаданные;
- `is_active` — участвует ли карточка в общем сборе;
- `created_at`, `updated_at`.

Пара `(marketplace, external_id)` уникальна.

### PriceHistory

Неизменяемое наблюдение состояния карточки:

- `card_id` — обязательный внешний ключ на `marketplace_cards`;
- `collection_run_id` — запуск, во время которого получено наблюдение;
- `price` — текущая числовая цена или `null`;
- `availability` — `in_stock`, `out_of_stock` или `unknown`;
- `observed_at` — время наблюдения с часовым поясом;
- `snapshot` — полный унифицированный объект в `jsonb`.

Для Ozon `price` берётся только из `cardPrice`. Обычная и зачёркнутая цены не
используются. История является append-only: новые измерения добавляются, старые
не перезаписываются.

### CollectionRun

Сводная информация о запуске:

- `status` — `queued`, `running`, `waiting_for_user`, `completed`,
  `completed_with_errors` или `failed`;
- `started_at`, `finished_at`;
- `total_count`, `success_count`, `failure_count`.

Отдельной таблицы попыток нет. Детальные ошибки находятся в структурированных
логах. Если коннектор завершился ошибкой, запись истории не создаётся, а счётчик
`failure_count` увеличивается.

## 4. Схема связей

```text
marketplace_cards 1 ────── N price_history N ────── 1 collection_runs
```

Удаление карточки каскадно удаляет её историю. Удаление запуска сохраняет
историю и устанавливает `collection_run_id = null`.

## 5. Сбор данных

Сетевой вызов коннектора выполняется вне транзакции PostgreSQL. Для каждого
успешного результата одна короткая транзакция:

1. обновляет `title`, `url`, `updated_at` карточки;
2. добавляет строку в `price_history`.

После обхода карточек отдельная транзакция завершает `collection_run` и
записывает итоговые счётчики. Ошибка одной карточки не откатывает уже сохранённые
результаты.

Параллельный сбор в первой версии не используется: карточки обрабатываются
последовательно. Это упрощает работу интерактивного Ozon-коннектора и исключает
конкуренцию за Chrome-профиль.

## 6. Аналитика

Для карточки доступны:

- последнее наблюдение;
- история за указанное число дней;
- минимальная и максимальная цена;
- средняя дневная цена за период;
- количество наблюдений и дней с данными.

Среднее считается в два этапа: сначала среднее всех доступных измерений каждого
дня, затем среднее дневных значений. В расчёт входят только строки с
`availability = 'in_stock'` и ненулевой ценой. Это не даёт дням с большим числом
запусков непропорциональный вес.

## 7. Интерфейс CLI

```bash
python main.py db migrate
python main.py card add --marketplace ozon --external-id 1604900984
python main.py card list
python main.py collect
python main.py collect --card-id 1
python main.py history --card-id 1 --days 30
python main.py run last
python main.py api
python main.py worker
```

Строка подключения берётся из `DATABASE_URL` или аргумента
`--database-url`. Старый вызов одного артикула Ozon остаётся доступным:

```bash
python main.py 1604900984
```

## 8. PostgreSQL

- локальная PostgreSQL 18 запускается через `compose.yaml`;
- параметры контейнера задаются через `.env`;
- данные сохраняются в именованном Docker volume `postgres_data`;
- готовность проверяется командой `pg_isready`;
- идентификаторы: `bigint generated always as identity`;
- цена: `numeric(14, 2)`, не `float`;
- время: `timestamptz`;
- полный снимок: `jsonb`;
- внешний ключ `price_history.card_id` индексируется составным индексом
  `(card_id, observed_at desc)`;
- активные карточки имеют частичный индекс;
- приложение использует небольшой пул SQLAlchemy-соединений через Psycopg 3;
- внешние HTTP/браузерные вызовы никогда не выполняются внутри транзакции.

Партиционирование истории в MVP не применяется. Оно потребуется только после
подтверждения большого объёма данных измерениями и `EXPLAIN ANALYZE`.

## 9. Web-приложение и worker

- FastAPI предоставляет карточки, историю и управление запусками;
- React UI обращается к API через Vite proxy;
- отдельный worker атомарно забирает `queued`-строки через
  `FOR UPDATE SKIP LOCKED`;
- браузерные вызовы выполняются через Playwright вне транзакций PostgreSQL;
- при проверке Ozon запуск переходит в `waiting_for_user` и продолжается через
  endpoint `/api/runs/{id}/continue`.

## 10. Границы текущей версии

- реализован коннектор Ozon;
- карточки неизвестных маркетплейсов можно хранить, но сбор завершится ошибкой
  до появления соответствующего коннектора;
- автоматического расписания нет — сбор запускается из UI или командой;
- уведомлений нет;
- ошибки отдельных карточек доступны только в логах и сводных счётчиках запуска.
