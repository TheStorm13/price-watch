# Аудит UI и план исправлений

Дата: 2026-10-29. Change: `openspec/changes/archive/2026-10-29-improve-desktop-ui-usability`.
Стадия: завершено. План и результат приняты пользователем 2026-10-29.

после обсуждения Browser/testing попросил продолжить. Это продолжение аудита.

## Среда и границы

- Chromium через установленный Playwright, `http://127.0.0.1:5175`, mock API.
- Проверены 1440×900 и 1024×768, панель также при 1024×700. Проверки 1920×1080 включены в план реализации, в аудите не выполнялись.
- Нет Browser skill/plugin, ожидаемого frontend-testing-debugging; использован его Playwright fallback. Другой инструмент CUA доступен, но не использовался.
- В формах дождались завершения анимаций; ранние снимки `add.png`/`group.png` попали на переход и не используются как доказательство дефекта прозрачности.
- Пользовательская база, реальные маркетплейсы, Rust-команды и native WebView на стадии аудита не запускались. До одобрения изменений приложения не было.
- CodeGraph возвращал текущий исходник. Repowise был старым (9f3876d); index-only update выполнен без модельной генерации, однако MCP продолжил возвращать старые метаданные. Его оценки не считаются подтверждением текущего состояния.

Поиск/фильтрация только по представителю группы, полный раскрытый состав и приоритет выгодных явно закреплены в group-card-metrics и существующих E2E. Не объявлять это багами и не менять без отдельного решения. «Сейчас не выгодно» при отсутствии цены — спорная формулировка; причины выгодности не расширяются в этом change, чтобы не придумывать контракт.

## Уточнение пользователя: выравнивание и артикулы

Пользователь попросил проверить названия, подписи и теги и убрать артикулы из списка/плиток. Уточнение включено в существующие proposal/design/tasks и delta desktop-ui-layout; на момент этого уточнения основной план ещё не был одобрен к реализации.

Дополнительная браузерная проверка выполнена при 1024×900 и 1440×900 на mock-данных с коротким/длинным названием, 0/1/2 тегами и статусом исключения. Подмена только в памяти браузера; пользовательские данные не использовались.

- В списке начало названия относительно строки: 22 px без тегов, 11 px с одним тегом и 9 px с двумя тегами/статусом. Это результат вертикального центрирования блока переменной высоты. План: общий верхний отступ названия, теги и статус ниже него.
- В сетке исходное выравнивание уже согласовано: начало названия 209 px, тегов при их наличии 270 px и цен 327 px во всех плитках; высота 461 px. После удаления ID требуется сохранить совпадение координат зон, уменьшив избыточный резерв.
- В обоих видах длинные теги обрезаются контейнером: от второй плашки остаётся край. План: ограничивать ширину каждой плашки, сокращать текст внутри и сохранять полный текст доступным.
- Артикулы удаляются только из каталога, включая вложенные товары групп; сохраняются поиск, детали, формы и данные. Удаляется также отдельная строка/стиль ID, чтобы не осталось пустой полосы.
- Снимки: `/tmp/pw-align-list-1024.png`, `/tmp/pw-align-grid-1024.png`, `/tmp/pw-align-list-1440.png`, `/tmp/pw-align-grid-1440.png`.

Полный E2E повторно не запускался: приложение не менялось. После уточнения strict OpenSpec и whitespace прошли. `card-list-selection` не требует изменений, поскольку правила выбора не затронуты.

## Реализация

2026-10-29: пользователь явно одобрил весь уточнённый план словами «Хорошо, приступай к изменениям». Начата реализация; приёмка результата ещё не получена.


### Выполненные изменения

- Каталог: удалены видимые артикулы и строка ID плитки; поиск по номеру и ID в деталях сохранены. Название строки — ссылка с клавиатурным доступом; переходы передают внутренний returnTo, смена периода/страницы его сохраняет.
- Выравнивание: общий верх названий списка, общие зоны плиток, читаемые цены/подписи, ограниченная ширина и общий выбор с чекбоксами. Длинные теги сокращаются внутри каждой целой плашки с полным текстом в title/доступном содержимом.
- Наличие и меню закреплены справа, фоны закреплённых ячеек соответствуют группам, вложенным и выбранным строкам. Фильтры и статистика адаптированы; действия деталей переносятся блоком.
- График и измерения имеют отдельные loading/error/retry, успешные разделы остаются видимыми. Продолжение сбора показывает pending/error, прогресс и aria-valuenow соответствуют обработанному числу целей.
- Диалог группы: компактные строки, прокрутка содержимого, закреплённые действия и сохранение фокуса.
- Добавлены 8 E2E для поведения/геометрии и 5 unit-сценариев; существующие проверки артикулов перенесены в детали. 13 PNG-эталонов проверяются отдельно через test:visual; npm-зависимости и lockfile не менялись, добавлен только script.

### Проверки реализации

- Lint: прошёл. Unit: 71/71 прошёл (18 файлов).
- Целевой usability E2E: 8/8 прошёл. Проверены DOM-координаты с допуском 1 px, целостность тегов, выбор/группы, клавиатура, контекст, частичные сбои/повтор, 404, длинные заголовки/крупные цены и footer формы.
- Visual: 5/5 тестов, 13 эталонов, повторное сравнение без update прошло, в том числе документированная команда `npm --prefix frontend run test:visual` (5/5, 21.2s). Время/locale/timezone и изображения фиксированы. Все 13 снимков просмотрены; найденные переполнение тегов и скрытый footer исправлены до финального сравнения.
- Desktop release build прошёл. Native smoke финальной сборки прошёл в `/tmp/pw-rel-native-rlmwtclk`: виден повтор общей ошибки, повтор сохраняет цену в настоящем WebView, перезапуск частного API восстанавливает каталог. Только синтетический connector и disposable XDG/БД, без пользовательских данных.
- Промежуточные браузерные прогоны выявили устаревшие ожидания видимого ID, HMR-влияние на подмены модулей и конфликт артефактов двух запусков в одном outputDir. Исправлены ожидания и fixtures до загрузки страницы; финальные прогоны используют отдельные outputDir и неизменяемый исходник. Эти промежуточные запуски не считаются успешной полной проверкой.
- Финальный общий E2E на чистом Vite без HMR во время тестов: **49/49 passed (4.4m)**. Включены обновлённые Ozon/Ali/WB, группы, decimal prices, layout и новые usability-сценарии.
- Repowise get_change_risk проверил live git diff: отметил небольшое увеличение уже высокой сложности CardDetailsPage/ActiveCollectionPanel (health 7.80→7.78), CSS не анализирует. Ветви loading/error/progress/continue проверены unit/E2E и просмотрены вручную; большой рефакторинг вне одобренного плана не добавлялся. Исторические метаданные MCP остаются устаревшими.
