# Фото Wildberries и вариантов товара

## План

- Симптом: у карточек WB не появляется изображение.
- Текущий исходный код: `wildberries/runtime.js` не передаёт изображение, а
  `WildberriesMapper.to_card` не заполняет `MarketplaceCard.image_url`.
  Сериализация и сохранение уже поддерживают это поле; UI использует `imageUrl`.
- Получать адрес главного фото средствами витрины WB в существующей браузерной
  сессии и передавать его через runtime в маппер. Проверить фактический механизм
  витрины; не зашивать таблицу basket-хостов и не подменять фото соседнего артикула.
- Отсутствие фотографии не должно мешать сбору цены и размеров.
- Проверить передачу фото для товара и точного размера, сериализацию,
  отсутствие фото и изоляцию соседних товаров. Запустить релевантные тесты
  маппера, браузерного runtime, транспорта и интеграции WB.
- Критерий приёмки: после нового сбора WB возвращается URL главного фото,
  который проходит существующий путь сохранения и отображения карточки.
- Дополнение пользователя: получать и показывать фото всех вариантов на странице
  товара; заменить пользовательский термин SKU на «Варианты товара»/«вариант».
- После расширения области нужна nullable-колонка изображения варианта, обновление
  общего контракта, API, transfer, demo и UI. История и существующие данные
  сохраняются. Для получения неизвестных фото потребуется повторный сбор.
- Актуальный полный план, design, три delta-spec и задачи находятся в
  `openspec/changes/fix-product-variant-images/`; они заменяют первоначальный
  план локального исправления. Варианты — уже обнаруживаемые размеры/комбинации;
  объединение отдельных артикулов WB по цветам не входит в изменение.

## Состояние

- Расширенный план подготовлен; явное согласование пользователя ожидается.
- Код приложения не изменён. Проверки исправления ещё не запускались.
- После согласования: проверить механизм получения фото WB, реализовать,
  проверить и создать коммит до передачи результата на пользовательскую оценку.
