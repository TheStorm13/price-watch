# Единая геометрия карточек

- Фаза: завершено; результат принят пользователем 2026-10-21.
- Область: каталог карточек в desktop UI, виды «Сетка» и «Список».

## Текущее поведение

- В сетке реальное изображение снимает квадратное соотношение сторон контейнера; высота плитки зависит от пропорций картинки.
- Название уже ограничено двумя строками, но теги переносятся, а статус исключения из выгодных предложений добавляется только некоторым карточкам и меняет высоту.
- В списке строка рассчитана на 84 px, однако длинный статус в ячейке названия может переноситься.

## План

1. Сохранить адаптивное заполнение ширины сетки: в одном контейнере плитки имеют одинаковую ширину, независимо от содержимого. Выделить квадратную область изображения по ширине плитки. Картинка целиком вписывается через `object-fit: contain` и не меняет геометрию.
2. Зафиксировать вертикальные зоны плитки: название (до двух строк с многоточием), ID, одна строка тегов, маркетплейс, четыре строки цен, дата и наличие, одна строка статуса. Для отсутствующих тегов и статуса сохранить место. Длинные значения обрезать внутри своей зоны без увеличения плитки; полный заголовок оставить доступным через `title`.
3. В строке списка удержать статус исключения в одну строку с многоточием внутри ячейки и сохранить высоту строки 84 px.
4. Добавить браузерный E2E с mock API: изображения разных пропорций, короткий и длинный заголовки, теги и исключённая карточка дают равные высоты плиток и одинаковую область изображения; статус списка остаётся однострочным и не выступает за ячейку. Проверить обычную и узкую ширину окна. Запустить релевантный E2E и `npm --prefix frontend run lint`.

## Совместимость и риски

- API, данные и упаковка не меняются. Полный текст длинных тегов и статуса может быть визуально обрезан в сетке/списке; он должен оставаться доступным через подсказку или в деталях карточки.
- Реальный сбор цен для проверки не нужен.

## Следующее действие

План одобрен пользователем 2026-10-21. Изменить разметку и CSS, выполнить проверки и представить результат на приёмку до завершения workflow.

При проверке существующий E2E показал, что фиксированные 190 px оставляют незаполненное место справа. Ширина возвращена к адаптивной сетке; требование одинакового размера плиток при одинаковом контейнере и фиксированные зоны содержимого сохраняются.

## Проверка реализации

- Browser plugin в сессии отсутствует; использован проектный Playwright с mock API.
- Новый E2E проверяет на ширине 1024 и 1536 px карточки с вертикальным и горизонтальным фото, длинным заголовком и тегами, а также статус списка. Размеры плиток различаются менее чем на 1 px (округление сетки), область фото квадратная, строка списка остаётся высотой 85 px с границей.
- Полный браузерный набор после исправления заполнения сетки: 23/23 теста прошли. После косметической однострочной обрезки тегов списка целевой E2E повторно прошёл.
- `npm --prefix frontend run lint` прошёл. Реальный backend и сбор цен не запускались.
- Скриншоты проверки: `/tmp/price-watch-grid-uniform.png`, `/tmp/price-watch-list-uniform.png`.
