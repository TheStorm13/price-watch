# Метаданные недоступной карточки Ozon

Дата: 2026-11-05. Workflow: vibe-flow. Этап: исследование завершено,
план ожидает явного согласования. Код приложения не изменён.

## Запрос и подтверждённая причина

Для SKU 2056350478 нужны фото и связанные SKU при отсутствии товара;
цену отсутствующего товара получать/записывать как текущую не нужно.

Живые запросы выполнены штатным AsyncOzonClient через Chrome с профилем
приложения, без подключения к БД. Обычный composer-запрос `/product/2056350478/`
возвращает search с точным product_id и webOutOfStock. Parser выдаёт
ProductNotFound, CollectionService создаёт пустой out_of_stock snapshot;
название/фото/связи поэтому не доходят до сохранения.

Сама витрина возвращает ссылку `/product/2056350478/?oos_search=false`.
Проверенный composer-запрос с этим параметром возвращает точный SKU,
название «Поло Galala базовая коллекция», webGallery и webAspects.
Текущие parser/mapper без изменений дают out_of_stock, price=null,
фото `https://ir.ozone.ru/s3/multimedia-1-j/12632755375.jpg` и 21 уникальную
ссылку SKU, включая исходный. Это один ответ, не полный обход всей семьи.
Показанная витриной старая цена 1563 ₽ не становится текущей ценой.

## План для согласования

1. В общем OzonJsonTransport запрашивать точный товар с `oos_search=false`
   сразу, используя существующие кодирование URL, лимиты и обработку ошибок.
   Не добавлять повторный старый способ запроса. Parser/mapper и контракт
   наличия/цены сохраняются.
2. Добавить регрессионное покрытие недоступного точного товара: фото,
   аспекты/SKU сохраняются; наличие out_of_stock, цена null, даже если
   ответ содержит старую отображаемую цену. Проверить запрос параметра и
   защиту от чужого SKU/поисковых рекомендаций.
3. Проверить общий connector → collection → persistence путь и numeric
   JSON/raw без БД, direct CLI collect и queued API/worker. Начальное
   обнаружение обходит связи по действующей политике; обычный сбор
   сохраняет существующие настройки отслеживания дополнительных вариантов.
4. Выполнить адресные Python/браузерные тесты; сохранение метаданных и
   истории проверять только с disposable TEST_DATABASE_URL. Повторить
   живой read-only запрос точного SKU после исправления. Проверить diff,
   закоммитить реализацию и передать на пользовательскую приёмку.

Это изолированное исправление формирования URL в существующем коннекторе;
OpenSpec и ADR не требуются. UI, API-контракты и схема БД не меняются,
миграции не нужны. Пользовательские карточки/история не изменялись.
Существующая карточка должна получить доступные метаданные при следующем
сборе; сбор всех вариантов подчиняется текущей политике initial/tracking.

tests.test_normalizer tests.test_ozon_json_transport -q` — 32 теста passed.
Это проверка текущего поведения; регрессионный тест исправления ещё не написан.

CodeGraph использован с явным projectPath, текущие source snippets без
предупреждения stale. Repowise MCP указывает индекс 9f3876d возрастом 11 дней
и не разрешает текущий json_transport.py. Локальный index-only update
не завершился и остановлен SIGINT; актуальный risk не получен. Поэтому
план опирается на текущий исходник и живые ответы, а не старый risk.

Временные ответы только с выбранными товарными полями находятся в
`/tmp/pw_unavailable_response.json` и `/tmp/pw_unavailable_response_detail.json`.
Полные ответы с данными профиля не выгружались. Эти диагностические файлы
не включаются в Git; при создании fixture убрать trackingInfo и SEO поиска.
