## Реализация и проверки

- Общий расчёт для исключённых товаров и общий компонент двух строк; денежные вычисления используют точные десятичные строки.
- Сортировка использует отображаемую выгоду; фильтр отдельно проверяет участие в выгодных предложениях.
- Добавлены проверки отключения участия, десятичной разницы, сортировки и фильтра, отсутствующих цен, наличия, нулевого максимума и отсутствующей базы.
- `npm --prefix frontend test`: 94 теста прошли.
- `npm --prefix frontend run lint`: прошло.
- `npm --prefix frontend run test:e2e -- app.spec.ts layout.spec.ts usability.spec.ts`: 45 тестов прошли.
- Финальный `npm --prefix frontend run test:e2e -- group-metrics.spec.ts`: 6 тестов прошли.
- После уточнения ширины заголовка повторно прошли E2E заголовков и компактного desktop.
- При добавлении проверки нулевого максимума исправлена фикстура: импорт объединяет одинаковые цены, поэтому `[100, 100]` не оставляет базы средней. Используется `[100, 110]`.
- Ручной Playwright QA: страница `/cards`, размеры 1440×900 и 1024×768, заголовок и две строки читаемы; на 1024 px таблица прокручивается с закреплёнными столбцами, страница без горизонтального overflow. Нет Vite overlay или ошибок страницы; отключение участия сохраняет показанные суммы.
- Browser plugin отсутствует; используется установленный Playwright. Снимки и временный QA-скрипт сохраняются в `/tmp`.
- На ширине 390 px остаётся предусмотренный существующей вёрсткой минимум страницы 1024 px; мобильная адаптация не входит в задачу.
- CLI Repowise успешно обновил локальный индекс; работающий MCP продолжает возвращать старый снимок и не используется как доказательство актуальных зависимостей.
