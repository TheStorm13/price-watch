# Будущие доработки

Здесь перечислены задачи, которые ещё не реализованы или требуют проверки.
Реализованные возможности описаны в [руководстве](guide/README.md).

## Предлагаемый порядок работ

| Приоритет | Раздел | Доработка |
| --- | --- | --- |
| Важно | Каталог товаров | Отличать давно не проверявшиеся товары и последние известные цены от актуальных данных. |
| На оценку | Каталог товаров | Импорт товаров из избранного в личном кабинете маркетплейса без дубликатов. |
| На оценку | Данные и настройки | Автоматический экспорт в выбранную папку. |
| 2 | Сбор и автоматизация | Адаптивное число вкладок и проверка устойчивости сбора при нескольких антибот-проверках и сбое Chrome. |
| 3 | Архитектура и качество кода | Общая фабрика коннекторов, упорядочение запуска desktop-служб и ревизия зависимостей. |
| 4 | Сборка и развёртывание | Проверка обновлений PostgreSQL и Python-зависимостей; оценка необходимости web режима. |
| 5 | Маркетплейсы | Коннекторы других площадок. |

Порядок предварительный. Лимит в пять вкладок остаётся базой для замеров перед
введением адаптивного числа вкладок.

## Данные и настройки

### Автоматический экспорт данных

**Состояние:** предложение, не реализовано.

Дать возможность выбрать папку, в которую приложение будет автоматически
сохранять экспорт карточек и истории. Перед реализацией определить момент
выгрузки, правила обработки существующих файлов и ошибок записи.

## Каталог товаров

### Импорт из избранного

**Состояние:** предложение, не реализовано.

Добавить кнопку «Импорт из избранного». По нажатию анализировать список избранных
товаров в личном кабинете маркетплейса и добавлять найденные товары как карточки
для отслеживания. Сопоставлять товары по маркетплейсу и артикулу: не создавать
дубликаты ни среди найденных товаров, ни для карточек, уже имеющихся в каталоге.
Повторный импорт не должен добавлять те же карточки снова. Перед добавлением
показывать, сколько найдено новых и сколько уже отслеживается.

### Видимость товаров при длительном отсутствии в продаже

**Состояние:** предложение, реализовано частично.

Карточки отсутствующих товаров уже остаются в каталоге, а Ozon распознаёт
подтверждённое перенаправление на поиск как отсутствие товара в продаже.
Осталось явно отличать устаревшие сведения от актуальных: показывать дату
последней достоверной проверки и обозначать старую цену как последнюю известную,
а не текущую.

## Сбор и автоматизация

### Адаптивное число вкладок

**Состояние:** предложение, не реализовано; сейчас лимит равен пяти.

Определять число одновременных вкладок перед запуском по доступным CPU, памяти
и числу карточек. Начать с диапазона от одной до пяти вкладок; повышать верхнюю
границу только после замеров. Сравнить время полного сбора, память Chrome,
ошибки и частоту проверок Ozon на разных системах. Предусмотреть ручной лимит
на случай неудачного автоматического выбора.

### Устойчивость параллельного сбора

**Состояние:** требуется проверка.

Проверить несколько одновременных антибот-проверок и сбой самого Chrome во
время сбора. Измерить время, частоту ошибок и запросов ручной проверки на
реальных карточках. Если после измерений потребуется менять параллельность,
сохранять результаты и ошибки отдельных карточек независимо друг от друга.

## Архитектура и качество кода

### Общая фабрика коннекторов

**Состояние:** предложение, не реализовано.

В `price_analyzer/cli.py` параметры `AsyncOzonClient` отдельно собираются для
прямого сбора и worker. Вынести создание коннекторов в одну фабрику с
параметрами браузера и обработчиком проверки. Сохранить асинхронный контракт
коннектора.

### Упорядочение запуска desktop-служб

**Состояние:** предложение, реализовано частично.

Локальные службы вынесены в `native_services.rs`, но `lib.rs` по-прежнему
управляет worker и браузером. Проверить границы этих частей перед следующими
изменениями упаковки и запуска desktop-приложения.

### Очистка кода и зависимостей

**Состояние:** предложение, не реализовано.

Проверить зависимости Python, Rust и frontend, убрать неиспользуемые,
закрепить совместимые версии и оценить размер сборки. В `frontend/package.json`
много версий `latest`, а в `requirements.txt` несколько широких диапазонов:
определить политику фиксации версий и воспроизводимой установки. Для
оптимизации производительности сначала измерить узкие места. После каждого
этапа проверять тесты и desktop режим.

## Сборка и развёртывание

### Проверка обновлений и web режима

**Состояние:** предложение, не реализовано.

Проверить обновление системной версии PostgreSQL и выпускать пакет вместе с
проверенными обновлениями Python-зависимостей. Оценить, нужен ли отдельный web
режим. Текущие ограничения desktop описаны в
[нюансах реализации](guide/CURRENT_NUANCES.md).

## Маркетплейсы

### Коннекторы других маркетплейсов

**Состояние:** предложение, не реализовано.

Подключить дополнительные площадки через `MarketplaceConnector` и общий
`ProductSnapshot`. Карточки Wildberries, AliExpress и Яндекс Маркета можно
добавлять через UI и API, но сбор для них отсутствует. Для каждой площадки
отдельно определить источник цены, наличие товара, авторизацию и обработку
антибот-проверки.
