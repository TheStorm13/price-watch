# Данные, очередь и API

[К содержанию](README.md)

## Таблицы PostgreSQL

| Таблица | Что хранит |
| --- | --- |
| `marketplace_cards` | Маркетплейс, внешний артикул, название, ссылку и флаг активности |
| `collection_runs` | Очередь и результат запуска, зафиксированные ID карточек, счётчики, ошибки с traceback и состояние проверки |
| `price_history` | Первую и последнюю точки каждого плато цены и наличия: цену, доступность, время и полный снимок в `JSONB` |

Пара `(marketplace, external_id)` уникальна. Удаление карточки удаляет и её
историю. Ссылки запуска на удалённую карточку обнуляются. Приостановленная
карточка остаётся в базе и истории, но не попадает в новый сбор. Состав уже
созданного запуска не меняется. Удаление карточки из незавершённого запуска
возвращает `409`.

Миграции выполняются Alembic. Сейчас есть ревизии `0001_initial`,
`0002_web_runs`, `0003_run_targets_errors` и `0004_compact_price_plateaus`. Последняя удаляет внутренние точки ранее накопленных плато. Сервис `migrate` применяет миграции при запуске Compose; API также
проверяет миграции при старте.

## Статусы запуска

| Статус | Значение |
| --- | --- |
| `queued` | Запрос записан, worker ещё его не взял |
| `running` | Worker обрабатывает карточки |
| `waiting_for_user` | Ozon требует проверки в Chrome |
| `completed` | Все карточки обработаны без ошибок |
| `completed_with_errors` | Хотя бы одна карточка не обработана |
| `failed` | Выполнить сам запуск не удалось |

Работа через UI использует очередь БД. Прямой `main.py collect` создаёт запуск
сразу в состоянии `running` и не ждёт worker. Ошибки отдельных карточек
отражаются в `failure_count`, логах и поле `errors` запуска. Каждый элемент
содержит товар, сообщение и полный traceback. Список запусков не передаёт
traceback; подробности загружаются через `GET /api/runs/{id}`. При частом опросе
UI использует `includeErrors=false`, чтобы не передавать traceback каждую секунду. Отдельной таблицы
попыток нет. Worker обновляет heartbeat каждые пять секунд. Если он исчезает,
запуск переводится в `failed` после `RUN_STALE_SECONDS` (по умолчанию 30 секунд)
при работающем worker.

## История и статистика

«Текущая» цена и доступность на карточке берутся из самого нового по времени
наблюдения. История возвращается с новейшего наблюдения и ограничена периодом.
API истории принимает `days` только `7`, `30` или `90`, а `pageSize` — от 1 до
200. CLI `history` использует положительное число дней без этого ограничения.

Средняя цена за период вычисляется как среднее дневных средних. В расчёт
входят только наблюдения с `availability = in_stock` и ненулевой ценой.
`minimumPrice` и `maximumPrice` также относятся к таким наблюдениям.
Интерфейс показывает между ними середину диапазона `(minimumPrice +
maximumPrice) / 2`, а не среднее дневных средних.

При сохранении наблюдения подряд идущие одинаковые пары `(цена, наличие)`
сжимаются до первой и последней точек плато. Обычное обновление читает только
три последние записи карточки и удаляет не более одной внутренней точки.
Запоздавшее наблюдение или старый несжатый хвост вызывает сжатие истории
только этой карточки. График получает крайние точки за весь период через
отдельный маршрут; вертикальная ось начинается с нуля. Таблица измерений
остаётся постраничной, по 50 строк. Счётчик измерений и средняя дневная цена
рассчитываются по сохранённым точкам, а число успешных запусков сохраняет
число фактических успешных запросов.

## HTTP API

Все маршруты имеют префикс `/api`. Поля JSON используют `camelCase`:
`externalId`, `currentPrice`, `cardId`, `pageSize` и так далее. Интерактивная
схема находится на `http://127.0.0.1:8000/docs`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Готовность API |
| `GET /api/cards` | Все карточки, включая приостановленные |
| `POST /api/cards` | Добавить карточку Ozon |
| `GET /api/cards/{id}` | Одна карточка с последним наблюдением |
| `PATCH /api/cards/{id}` | Изменить название, ссылку или активность |
| `DELETE /api/cards/{id}` | Удалить карточку и её историю |
| `GET /api/cards/{id}/history` | История и статистика |
| `GET /api/cards/{id}/chart?days=30` | Крайние точки всех плато цены за период |
| `GET /api/runs` | Список запусков |
| `POST /api/runs` | Поставить сбор в очередь; `{}` — все активные, `{"cardId": 1}` — одна |
| `GET /api/runs/{id}` | Статус, счётчики, текущая карточка и ошибки запуска |
| `POST /api/runs/{id}/continue` | Продолжить после проверки Ozon |

Создание запуска возвращает HTTP `202`, создание карточки — `201`, удаление —
`204`. Если активных карточек нет, `POST /api/runs` возвращает `409`.
Ошибки API имеют структурированный объект `error` с кодом и сообщением.
Сейчас публичное создание карточки разрешает только `marketplace = "ozon"` и
цифровой артикул.

API не содержит учётных записей. В Compose его порт публикуется только на
`127.0.0.1`; этот режим рассчитан на локальный компьютер.
