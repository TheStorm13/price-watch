# Данные, очередь и API

[К содержанию](README.md)

## Таблицы PostgreSQL

| Таблица | Что хранит |
| --- | --- |
| `marketplace_cards` | Маркетплейс, внешний артикул, название, ссылку, изображение, теги, группу и флаг учёта в выгодных предложениях |
| `product_groups` | Название, теги и дату создания группы; участники ссылаются на неё из `marketplace_cards` |
| `collection_runs` | Очередь и результат запуска, владелец и heartbeat, полнота состава, связь с исходным запуском, счётчики, ошибки и состояние проверки |
| `collection_run_targets` | Фиксированные цели запуска с порядком и результатом pending/succeeded/failed/unknown |
| `price_history` | Наблюдения цены и наличия, время и снимок в `JSONB`; новый сбор пропускает неизменное состояние |

Пара `(marketplace, external_id)` уникальна. Удаление карточки удаляет и её
историю. Ссылки запуска на удалённую карточку обнуляются. Исключённая из выгодных предложений
карточка остаётся в базе и истории и участвует в новом сборе. Состав уже
созданного запуска не меняется. Удаление карточки из незавершённого запуска
возвращает `409`.

Миграции выполняются Alembic; цепочка ревизий в коде идёт от `0001_initial`
до `0014_run_target_results`. В неё входят, среди прочего, таблица групп, теги,
изображение, первоначальное 12-часовое расписание (текущий интервал задан кодом) и переход от `is_active` к
`deals_enabled`. Ревизия `0004_compact_price_plateaus` сокращает старые
повторы состояний в истории, сохраняя первую и последнюю точки каждого
участка. Удалённые ею наблюдения нельзя восстановить через `downgrade`.
Прежняя версия руководства также сообщала об отдельной ручной очистке рабочей
базы 27 сентября 2026 года; это сообщение нельзя подтвердить по репозиторию.
API применяет
миграции при старте; перед исполнением на существующей базе нужно изучить
конкретные ревизии и резервную копию.

## Модели и денежный контракт

`MarketplaceCard` — общий результат получения товара из коннектора.
`TrackedCard` — локальная запись отслеживания, соответствующая существующей
таблице `marketplace_cards`; модели связаны парой marketplace/external_id.
Получение товара не перезаписывает группу, теги и настройки. Непустое локальное
название сохраняется; пустое заполняется из товара.

Все денежные поля API (`price`, `currentPrice`, `minimumPrice`, `maximumPrice`,
`averagePrice`, `savings`) и CLI передаются десятичными строками либо null.
Цена наблюдения содержит два знака, например `"199.90"`. В Python используется
Decimal, в истории — NUMERIC(14,2); округление цены ROUND_HALF_UP, допустимы
конечные неотрицательные значения меньше 10^12 после округления. Средние и
выгода не округляются до проверки выгодности; показ округляется до двух знаков.

Нормализованный товар имеет schema_version `2.0`; `--raw` выводит исходный
ответ без пересериализации. Импорт/экспорт документа v2 сохраняет структуру
и строковые цены; числовая цена в запросе импорта отклоняется валидацией.
Существующие v2-экспорты со строками не требуют изменения. Старые исторические
JSONB-снимки и пустые snapshots импорта не переписываются. Новая схема БД
для разделения моделей не требуется. API, worker, CLI и UI обновляются вместе;
старые Python-импорты и числовые денежные JSON-ответы больше не поддерживаются.

## Статусы запуска

| Статус | Значение |
| --- | --- |
| `queued` | Запрос записан, worker ещё его не взял |
| `running` | Исполнитель CLI или worker обрабатывает карточки |
| `waiting_for_user` | Ozon требует проверки в Chrome |
| `completed` | Все карточки обработаны без ошибок |
| `completed_with_errors` | Хотя бы одна карточка не обработана |
| `failed` | Выполнить сам запуск не удалось |

Работа через UI использует очередь БД. Прямой `main.py collect` создаёт запуск
сразу в состоянии `running` и не ждёт worker. Ошибки отдельных карточек
отражаются в `failure_count`, логах и поле `errors` запуска. Каждый элемент
содержит товар, сообщение и полный traceback. Список запусков не передаёт
traceback; подробности загружаются через `GET /api/runs/{id}`. При частом опросе
UI использует `includeErrors=false`, чтобы не передавать traceback каждую секунду. Результаты целей сохраняются в `collection_run_targets`, включая успех без новой точки истории. Worker проверяет необходимость автоматического сбора раз в минуту:
если с начала последнего полного запуска прошло не менее 6 часов, нет незавершённого
запуска и
есть поддерживаемые карточки, он создаёт полный запуск. При отсутствии предыдущего
полного запуска сбор создаётся сразу; после долгого простоя создаётся только один
просроченный запуск. Общий `RunExecutor` CLI и worker обновляет heartbeat
каждые пять секунд, в том числе в ожидании пользователя. Worker восстанавливает
устаревшие запуски до проверки расписания, direct collect — до собственного старта.
Порог `RUN_STALE_SECONDS` по умолчанию 30 секунд, минимум 15. Восстановление
проверяет последнюю активность независимо от наличия владельца; уже сохранённая
история остаётся. Старый владелец больше не может менять данные запуска.

Повтор доступен для `failed`/`completed_with_errors` и создаётся один раз для
каждого источника. Успешные цели исключаются, удалённые карточки не возвращаются.
API сообщает `retryableCount` и `retryScopeIncomplete`: при неполных старых
данных UI предупреждает о повторе только известных карточек. После создания
повтора источник сообщает нулевой `retryableCount`. Повтор не переносит срок
полного сбора.

Ревизия 0014 переносит все известные цели из прежнего массива, requested ID,
ошибок и истории, затем удаляет `target_card_ids`. Недоказанные результаты
помечаются `unknown`; неполный состав не дополняется текущим каталогом.
Существующие карточки, история и ошибки сохраняются. Идентичность цели после
удаления карточки остаётся; удаление запуска удаляет его цели каскадно.
Переход forward-only: остановить старые процессы перед upgrade, использовать
только новую версию. Возврат прежней модели через downgrade не поддерживается.

Каталог читается в одной read-only транзакции `REPEATABLE READ`; cards, groups
и deals строятся из общих исходных данных. `PostgresCatalogReader` материализует
эти данные, а `CatalogService` применяет чистые правила выгодности и представителя
после закрытия транзакции. SQL-агрегации и денежные значения сохраняются;
дополнительного чтения для отдельных проекций нет. UI заменяет снимок целиком после
мутаций, импорта, завершения сбора и восстановления API. При ошибке refetch
сохраняется предыдущий целый снимок. Заменённые GET списков `/api/cards`,
`/api/groups`, `/api/cards/deals` удалены; отдельные мутации, details/history/chart
и import/export сохранены.

## История и статистика

«Текущая» цена и доступность на карточке берутся из самого нового по времени
наблюдения. История возвращается с новейшего наблюдения и ограничена периодом.
API истории принимает `days` только `7`, `30` или `90`, а `pageSize` — от 1 до
200. CLI `history` использует положительное число дней без этого ограничения.

Средняя цена за период вычисляется как среднее дневных средних. В расчёт
входят только наблюдения с `availability = in_stock` и ненулевой ценой.
`minimumPrice` и `maximumPrice` также относятся к таким наблюдениям.
Интерфейс показывает между ними середину диапазона `(minimumPrice +
maximumPrice) / 2` и разницу `maximumPrice - minimumPrice`.

В списке карточек `minimumPrice` считается за всё время наблюдений. Поле
`averagePrice` — среднее дневных средних предыдущих цен; последнее наблюдение
исключено, как и при отборе выгодных предложений. «Выгода» появляется только
для карточек, прошедших условия отбора.

Группа берёт все товарные показатели у одной карточки с минимальной известной
текущей ценой: исторический минимум, среднюю, выгоду, наличие, даты,
маркетплейс и товарные теги. Наличие не ограничивает выбор; используется цена
последнего сохранённого состояния. При равных ценах выбирается меньший ID.
Если цен нет, выбирается участник с меньшим ID; пустая группа не имеет
представителя. Поля без данных остаются `null`. Исторический минимум группы
относится именно к выбранной карточке, а не к историям всех участников.

Фильтры и сортировка применяются к группам и отдельным карточкам одинаково,
после выбора представителя. Фильтр не подбирает другого участника; раскрытая
группа показывает весь состав. Поиск также учитывает собственное имя группы.
Её ID, имя, состав и редактируемые теги сохраняются как собственные данные;
товарный фильтр тегов использует теги представителя.

Выгодность и численная выгода группы совпадают с представителем. Выгодный
вложенный товар дополнительно повышает приоритет группы, но не меняет её
показатели и прохождение фильтра «Выгодные предложения». Список и плитка
используют один порядок: сначала выгодные объекты, затем выбранное поле;
отсутствующие значения внутри одного приоритета идут в конце при обоих
направлениях сортировки.

Ответы API групп содержат `representativeCardId`, обычную проекцию
`representativeCard`, `savings`, `baselineDays`, `isDeal` и `hasMemberDeals`.
Поля `currentPrice` и `minimumPrice` верхнего уровня совпадают с представителем.
У пустой группы представитель и цены равны `null`, число дней базы — 0,
признаки выгодности — `false`. Даты группы принадлежат представителю;
обновление другого участника не освежает их, пока он не стал представителем.

При сохранении наблюдения цена и наличие сравниваются с последним
сохранённым состоянием карточки. Если оба значения совпадают, новая точка
не добавляется; пустое название заполняется с площадки, а ссылка обновляется,
если площадка её вернула. При статусе
`out_of_stock` цена равна `null`, даже если в ответе магазина осталась прежняя
цена. Переходы «в наличии → нет в наличии → в наличии» сохраняются в истории.
Поле `updatedAt` обновляется при каждом успешном сборе. Интерфейс показывает
его в колонке «Обновлено» и в деталях карточки; `lastObservedAt` остаётся
временем последней сохранённой точки истории. Для карточки без измерений дата
обновления в интерфейсе не показывается.
Обычный сбор не пересматривает уже записанную историю. График получает сохранённые точки через
отдельный маршрут; вертикальная ось имеет отступ 10% от диапазона видимых цен,
не опускаясь ниже нуля. Таблица измерений
остаётся постраничной, по 50 строк. Счётчик измерений и средняя дневная цена
рассчитываются по сохранённым точкам, а число успешных запусков сохраняет
число фактических успешных запросов.

Выгодное предложение появляется для карточки, участвующей в отборе, как только
у неё есть хотя бы одно предыдущее наблюдение с ценой товара в наличии, а
последняя цена товара в наличии ниже средней дневных средних предыдущих
наблюдений. Возраст карточки не учитывается; предыдущая и последняя цены могут
быть сохранены в один день. Последняя точка не входит в базу сравнения.
Список вычисляется при запросе из истории цен, поэтому после очередного сбора
цена может добавить или убрать товар из списка.

## Экспорт и импорт

«Экспорт» на странице карточек выгружает один JSON-файл версии 2 со всеми
карточками, группами и всей сохранённой историей. У карточки сохраняются `marketplace`,
`externalId`, `title`, `url`, `imageUrl`, `tags`, `dealsEnabled`, `createdAt` и `history`. Каждая запись
истории содержит только `price`, `availability` и `observedAt`. Внутренние ID,
запуски сбора и снимки ответа маркетплейса не экспортируются.

«Импорт» сначала рассчитывает результат без записи. Карточки сопоставляются по
маркетплейсу и артикулу; у совпавших карточек название, ссылка и состояние показа в выгодных предложениях
остаются местными. Наблюдения объединяются по времени, совпадающие по времени
и цене не повторяются, а подряд идущие одинаковые числовые цены сворачиваются
в первую точку серии. Пустая цена обозначает отдельное состояние доступности.
Разные цены с одинаковым временем для одной карточки вызывают ошибку; весь
импорт выполняется одной транзакцией. Пока сбор не завершён, импорт недоступен.
Импорт принимает только файлы версии 2 с полем `dealsEnabled`.

## HTTP API

Все маршруты имеют префикс `/api`. Поля JSON используют `camelCase`:
`externalId`, `currentPrice`, `cardId`, `pageSize` и так далее. При прямом запуске
API с портом по умолчанию интерактивная схема находится на
`http://127.0.0.1:8000/docs`. В desktop порт выбирается при запуске.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/health` | Готовность API |
| `GET /api/catalog` | Единый снимок `{cards, groups, deals}` с ценами, метриками и представителями групп |
| `GET /api/cards/export` | Все карточки и вся сохранённая история в JSON |
| `POST /api/cards/import/preview` | Проверить файл и рассчитать результат без записи |
| `POST /api/cards/import` | Объединить карточки и историю |
| `POST /api/cards` | Добавить карточку поддерживаемого маркетплейса, даже если сбор для него пока недоступен |
| `GET /api/cards/{id}` | Одна карточка с последним наблюдением |
| `PATCH /api/cards/{id}` | Изменить название, ссылку, группу, теги или учёт в выгодных предложениях |
| `DELETE /api/cards/{id}` | Удалить карточку и её историю |
| `GET /api/cards/{id}/history` | История и статистика |
| `GET /api/cards/{id}/chart?days=30` | Сохранённые изменения цены за период |
| `POST /api/groups` | Создать группу |
| `PUT /api/groups/{id}` | Изменить группу |
| `DELETE /api/groups/{id}` | Удалить группу, сохранив карточки |
| `GET /api/runs` | Список запусков |
| `POST /api/runs` | Поставить сбор в очередь; `{}` — все карточки, `{"cardId": 1}` — одна |
| `GET /api/runs/{id}` | Статус, счётчики, текущая карточка и ошибки запуска |
| `POST /api/runs/{id}/continue` | Продолжить после проверки Ozon |
| `POST /api/runs/{id}/retry` | Повторить существующие поддерживаемые цели failed/pending/unknown |

Создание запуска возвращает HTTP `202`, создание карточки — `201`, удаление —
`204`. Если карточек нет, `POST /api/runs` возвращает `409`.
Ошибки API имеют структурированный объект `error` с кодом и сообщением.
Публичное создание карточки принимает `marketplace = "ozon"`, `"wildberries"`,
`"aliexpress"` или `"yandex-market"` и цифровой артикул. Сбор цен доступен
только для Ozon; остальные карточки не попадают в очередь сбора.

API не содержит учётных записей. Desktop запускает его на свободном порту
`127.0.0.1` и передаёт интерфейсу секрет для запросов.
