# Работа над задачами

Проект использует [vibe-flow из agent-kit](../../.agents/skills/vibe-flow/SKILL.md).
Навык и схема OpenSpec подключены ссылками на каталоги в `~/DevProjects/agent-kit`.
Для работы на другой машине нужны оба репозитория; сохраняй их расположение либо
переподключи ссылки через agent-kit. RTK наследуется глобально, второй локальный
hook не нужен.

## Два согласования

1. **Исследование и решение.** Агент выясняет цель, проверяет текущую реализацию,
   критически оценивает предложенный способ, уточняет существенные детали и
   готовит техническую спеку с планом. Реализация начинается после одобрения.
2. **Приёмка.** Агент предъявляет проверенный и закоммиченный результат с
   доказательствами выполнения критериев, ограничениями и состоянием индексов.
   Исправления по замечаниям тоже проверяются и коммитятся до повторной приёмки.

Между согласованиями реализация самостоятельна. При необходимом решении
пользователя агент останавливает всю задачу и задаёт вопросы обычным текстом.

## Техническая память задачи

Новая задача использует схему `vibe-flow` и один файл
`openspec/changes/<name>/spec.md`: цель и критерии, текущее устройство с
подтверждениями, согласованное решение, план проверяемых шагов и состояние работы.
Спека хранит необходимые контракты, нюансы и ограничения; она не является журналом
всех сообщений. Существующие задачи сохраняют свои схемы и формат материалов.
[Их планы и отчёты](../tasks/README.md) не требуют перевода в новый шаблон.

Постоянная документация обновляется вместе с реализацией до приёмки. После
явного принятия агент архивирует задачу, заменяет рабочую спеку кратким итогом
с важными решениями, проверками и ссылками, затем коммитит завершение.
Полная рабочая версия остаётся в Git. Схема одного файла не синхронизирует
постоянные спецификации автоматически: их агент обновляет явно.

После каждого коммита задачи обновляются существующие индексы CodeGraph и
Repowise. Перед приёмкой и после завершения также обновляются настроенные страницы
Repowise. Ошибки обновления сообщаются; они не считаются успешным завершением.

## Backlog вне жизненного цикла задачи

[docs/BACKLOG.md](../BACKLOG.md) — проектный список будущих работ. Агент читает
относящиеся пункты, но запись не разрешает начать реализацию. После приёмки
актуализируется только связанный пункт; новые идеи добавляются по запросу
пользователя. Backlog не превращается в план выполнения, не архивируется вместе
с задачей, посторонние пользовательские правки не включаются в её коммиты.
