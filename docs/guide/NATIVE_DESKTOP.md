# Локальные службы desktop

[К содержанию](README.md)

Приложение запускает PostgreSQL, API, Xvfb и worker от имени пользователя.

## Включение при запуске из репозитория

На Arch нужны системные `postgresql`, `xorg-server-xvfb`, `xorg-xauth` и Google
Chrome. Python-зависимости устанавливаются в `.venv` из инструкции
[запуска](RUNNING.md). Пересоберите Tauri и запустите `./price-watch`.
Для обычного запуска переменные `XDG_DATA_HOME`, `XDG_STATE_HOME` и
`XDG_CONFIG_HOME` задавать не нужно.

## Открытие окна

При обычном запуске окно создаётся скрытым и появляется после запуска служб
и подготовки основного интерфейса. Заставки нет. При ошибке запуска доступны
причина, «Повторить» и «Завершить работу». Если сам WebView не смог подготовиться
за 120 секунд, приложение показывает нативное сообщение для запрошенного открытия.
Фоновый запуск остаётся скрытым; явное открытие через ярлык или tray ожидает
готовности. Восстановление служб само по себе окно не раскрывает.

«Настройки» открывают компактное окно справа от нижней части левого меню,
с отступами 12 px от меню и 16 px от нижнего края. В ней находятся
импорт, экспорт и фоновое обновление. Успешный импорт или экспорт закрывает
настройки и показывает результат; отмена импорта возвращает в настройки.

## Частота интерфейса

Для Linux нужен WebKitGTK (`webkit2gtk-4.1`) версии не ниже 2.42.
При создании главного WebView приложение отключает
`PreferPageRenderingUpdatesNear60FPS`, позволяя использовать частоту экрана
выше 60 Гц. Принудительного таймера на 120 FPS нет. На высокочастотном экране
может вырасти расход CPU/энергии; фактический FPS зависит от нагрузки.
Если применить настройку не удалось, причина выводится в stderr.
После обновления пакета полностью завершите старый процесс (через «Завершить работу»),
затем откройте приложение снова: повторное открытие фонового процесса не
пересоздаёт WebView и не применяет новый код.

## Колесико мыши

В Linux desktop вертикальная прокрутка колесиком мыши ускорена вдвое.
События обрабатывает сам WebKit, включая прокрутку вложенных областей.
Тачпад, горизонтальная прокрутка и сочетания с Ctrl/Shift/Alt/Super/Meta
сохраняют штатное поведение. Системные настройки мыши не меняются.

## Данные и процессы

При запуске из репозитория код Python берётся из каталога проекта, а при
установке пакета `price-watch-bin` — из `/usr/lib/price-watch`.
Пользовательские настройки читаются из
`$XDG_CONFIG_HOME/price-watch/config.env` раньше корневого `.env`. Явные
переменные окружения имеют приоритет.

PostgreSQL хранит данные в `$XDG_DATA_HOME/price-watch/postgres` и принимает
подключения только через Unix-сокет в `$XDG_RUNTIME_DIR/price-watch` (или в
каталоге состояния, если `XDG_RUNTIME_DIR` отсутствует). База не использует
порт 5432 и не требует системной службы PostgreSQL. API получает свободный
локальный TCP-порт и случайный секрет на время запуска. Интерфейс получает
адрес и секрет от Tauri. API отвергает запросы без секрета.

Xvfb запускается на свободном дисплее с отдельным файлом Xauthority. Worker
работает на этом дисплее и использует тот же профиль Chrome, который
открывается по кнопке. При запуске приложения Chrome не открывается. Перед
ручным и автоматическим сбором открытый через приложение Chrome закрывается.
При включённом фоновом режиме закрытие окна оставляет службы работающими.
Повторный запуск ярлыка или `./price-watch` показывает существующее окно.
При выключенном режиме закрытие окна завершает приложение. «Завершить работу» в
интерфейсе или tray всегда останавливает worker и ручной Chrome, затем API,
Xvfb и PostgreSQL; настройка автозапуска при этом сохраняется.

В GNOME значок price-watch появляется справа на верхней панели при включённом
расширении [AppIndicator and KStatusNotifierItem Support](https://extensions.gnome.org/extension/615/appindicator-support/).
Если значка нет, проверьте, что расширение активно и запущена актуальная
сборка приложения. При сборке из репозитория после изменения кода выполните
`npm --prefix frontend run desktop:build`, закройте старый процесс и снова
запустите `./price-watch`.

Фоновый режим регистрирует скрытый запуск после входа пользователя в
графическую сессию. До входа и при выключенном ПК сбор не работает. Полный
сбор проверяется каждые 6 часов от начала последнего полного запуска. Если
срок истёк во время простоя, при следующем запуске ставится один просроченный
сбор. Rust-монитор проверяет службы каждые пять секунд и повторяет запуск
после сбоя. Текущая ошибка видна в интерфейсе; при смене адреса или секрета
API интерфейс получает новую конфигурацию через Tauri IPC.

## Резервные копии и обновление PostgreSQL

При запуске и штатном закрытии нативного режима создаётся архив
`$XDG_DATA_HOME/price-watch/backups/native-*.dump`; сохраняются десять последних
локальных архивов. Сбой создания копии при
старте не позволяет начать сбор. При изменении основной версии системного
PostgreSQL приложение откажется открывать старый кластер и сообщит версии:
до обновления кластера нужно сохранить его каталог и воспользоваться
`pg_upgrade` со старой версией PostgreSQL или восстановить последний архив
в новый кластер. Автоматического обновления файлов кластера нет.

Логи находятся в `$XDG_STATE_HOME/price-watch/`: `postgres.log`, `api.log`,
`xvfb.log`, `desktop-worker.log`. Если сервер не поднялся, сообщение запуска
указывает соответствующий файл. Профиль Chrome и база остаются в каталоге
данных пользователя и не входят в пакет.

## Обновление до модели результатов целей

Перед первым запуском версии с миграцией `0014_run_target_results` полностью
остановить прежние desktop/API/worker и прямой collect. Проверить резервную
копию по описанному выше порядку. API применяет миграцию при старте; CLI может
применить её командой `db migrate`. После обновления запускать только новую
версию: старый массив целей и GET списков удалены, смешанные версии не
поддерживаются. Карточки, история цен и ошибки сохраняются; известные цели
переносятся с явным обозначением неполных данных. Downgrade к прежней модели
не реализован; исправления схемы выпускаются следующей миграцией.

## Кэш подготовленных фото

API создаёт миниатюры по первому запросу и хранит их в
`$XDG_CACHE_HOME/price-watch/thumbnails` (обычно `~/.cache/price-watch/thumbnails`).
Это восстанавливаемые PNG, JSON и сжатые исходники (`sources/`), отдельно от
PostgreSQL и резервных копий. Два независимых LRU бюджета по 128 МиБ: исходники
и подготовленные PNG; общий предел 256 МиБ с метаданными. Удаляются только файлы
этого кэша. Для очистки остановите приложение и удалите только `thumbnails`:
фотографии восстановятся по запросу.

Три роли: list/SKU 51×68, tile 276×368, detail 384×512 CSS px — все 3:4.
Плитка целиком 280×654; рамка detail адаптируется к левой колонке и сохраняет 3:4. Размер PNG = round(размер × DPR),
коэффициент ×1, scale 0.25..8. Прозрачное поле занимает точную область, фото
вписано Lanczos без увеличения и кадрирования. Общий слушатель resolution/resize
переключает размер при смене монитора/масштаба; старый Blob освобождается.

Исходник кэшируется по URL, производная — по URL, физическим сторонам и версии
рецепта. Роли создаются лениво из общего оригинала; повторные запросы объединяются
как для загрузки, так и для обработки. После вытеснения исходника готовый свежий
PNG продолжает работать; новый профиль может потребовать повторной загрузки.
Старые рецепты не читаются и вытесняются общим LRU. Через 24 часа источник
проверяется условным HTTP-запросом (ETag/Last-Modified); неизменное содержимое
повторно не обрабатывается. Новая digest исходника инвалидирует производные при
следующем запросе. Максимум две загрузки/обработки, ошибка кэшируется на 30 секунд.
Только HTTPS, с проверкой каждого редиректа и привязкой соединения к проверенному
IP с исходным TLS-именем и проверкой сертификата. По умолчанию разрешены только
публичные IP. Для `ozone.ru`, `wbbasket.ru`, `aliexpress-media.com` и их поддоменов
также разрешён диапазон `198.18.0.0/15`: локальный DNS может выдавать эти
синтетические Fake-IP для маршрутизации рабочих CDN. Исключение не разрешает
localhost, приватные адреса или Fake-IP посторонних доменов; домен повторно
проверяется при каждом редиректе. Лимиты: 15 секунд на загрузку,
20 МиБ входного тела, 40 мегапикселей. Сессионный API-токен CDN не передаётся.

Frontend кэширует Blob до 24 часов; неиспользуемые записи удаляются через пять
минут. Смена URL/главного фото или конфигурации API переключает ключ запроса;
object URL освобождаются при смене изображения и размонтировании строки.
Фото плиток, деталей и таблицы вариантов используют исходники.
