# Локальные службы desktop

[К содержанию](README.md)

Нативный режим запускает PostgreSQL, API, Xvfb и worker от имени пользователя,
без Docker. Он используется по умолчанию при запуске из проекта.

## Включение при запуске из репозитория

На Arch нужны системные `postgresql`, `xorg-server-xvfb`, `xorg-xauth` и Google
Chrome. Python-зависимости пока можно оставить в `.venv` из инструкции
[запуска](RUNNING.md). Пересоберите Tauri и запустите `./price-watch`.
Для запуска старого режима закройте приложение и выполните
`PRICE_WATCH_RUNTIME=compose ./price-watch` либо запишите
`PRICE_WATCH_RUNTIME=compose` в `~/.config/price-watch/config.env`.
После возврата к Compose изменения, сделанные в локальной базе, автоматически
не появятся в Docker-базе: это два отдельных набора данных.

Проверку нового режима выполняйте сначала с отдельными `XDG_DATA_HOME`,
`XDG_STATE_HOME` и `XDG_CONFIG_HOME`. Для обычного запуска эти переменные
задавать не нужно.

## Данные и процессы

Код Python пока берётся из каталога проекта. В будущем пакет сможет установить
его в `/usr/lib/price-watch`. Пользовательские настройки читаются из
`$XDG_CONFIG_HOME/price-watch/config.env` раньше корневого `.env`. Явные
переменные окружения имеют приоритет.

PostgreSQL хранит данные в `$XDG_DATA_HOME/price-watch/postgres` и принимает
подключения только через Unix-сокет в `$XDG_RUNTIME_DIR/price-watch` (или в
каталоге состояния, если `XDG_RUNTIME_DIR` отсутствует). База не использует
порт 5432 и не требует системной службы PostgreSQL. API получает свободный
локальный TCP-порт и случайный секрет на время запуска. Интерфейс получает
адрес и секрет от Tauri. API отвергает запросы без секрета; web и Compose
режимы сохраняют прежний контракт без обязательного секрета.

Xvfb запускается на свободном дисплее с отдельным файлом Xauthority. Worker
работает на этом дисплее и использует тот же профиль Chrome, который
открывается по кнопке. При запуске приложения Chrome не открывается. Перед
ручным и автоматическим сбором открытый через приложение Chrome закрывается.
При штатном закрытии Tauri сначала останавливает worker и ручной Chrome,
затем локальные API, Xvfb и PostgreSQL. Автосбор выполняется только пока
приложение открыто.

## Перенос истории из Docker

Если локальной базы ещё нет, а контейнер старой базы найден, приложение не
создаёт пустую базу. Кнопка «Перенести историю цен» останавливает старые API
и worker, сохраняет полный архив `pg_dump` в
`$XDG_DATA_HOME/price-watch/backups/docker-*.dump`, восстанавливает его в
новую локальную базу и запускает службы. Docker-база и её volume сохраняются.
Если `pg_restore` завершится ошибкой, незавершённая локальная база удаляется,
архив и исходная база остаются. Повторное восстановление поверх существующей
локальной базы запрещено.

При запуске из исходного проекта Compose-файл находится автоматически. Если
код уже установлен отдельно, укажите в `config.env`
`PRICE_WATCH_LEGACY_PROJECT_DIR=/путь/к/старому/проекту` до переноса. Приложение
не станет создавать контейнеры по новому Compose-файлу вместо старой базы.

После переноса не запускайте сбор одновременно в старом и новом режимах:
истории разойдутся. Не удаляйте Docker volume до проверки карточек и истории
в новом режиме. Для отката сохраните Docker volume и переключите режим на
`compose`; данные, записанные после переноса только в локальную базу, в
старом режиме не будут видны.

## Резервные копии и обновление PostgreSQL

При запуске и штатном закрытии нативного режима создаётся архив
`$XDG_DATA_HOME/price-watch/backups/native-*.dump`; сохраняются десять последних
локальных архивов и все архивы переноса из Docker. Сбой создания копии при
старте не позволяет начать сбор. При изменении основной версии системного
PostgreSQL приложение откажется открывать старый кластер и сообщит версии:
до обновления кластера нужно сохранить его каталог и воспользоваться
`pg_upgrade` со старой версией PostgreSQL или восстановить последний архив
в новый кластер. Автоматического обновления файлов кластера нет.

Логи находятся в `$XDG_STATE_HOME/price-watch/`: `postgres.log`, `api.log`,
`xvfb.log`, `desktop-worker.log`. Если сервер не поднялся, сообщение запуска
указывает соответствующий файл. Профиль Chrome и база остаются в каталоге
данных пользователя и не входят в будущий пакет.
