# Ozon: все связанные варианты в одной карточке

Добавьте артикул любого варианта или полную ссылку `https://www.ozon.ru/product/…/`.
При добавлении автоматически запускается первоначальное обновление всех вариантов. Оно обходит связи SKU из ответов Ozon: другой цвет может открывать
дополнительные размеры. Цена каждого SKU берётся из его точного ответа;
сочетания без подтверждённого артикула не создаются.

Например, для `2936650207` 2026-11-04 найдено 12 SKU: два цвета и размеры 40–45.
Первый ответ содержит только 7 уникальных артикулов. Ассортимент зависит от
текущей витрины, региона и профиля Chrome.

В деталях доступны параметры, фото, цена, наличие и история каждого варианта.
«Сделать главным» переключает данные каталога и статистику без переноса историй.
Исходный артикул карточки сохраняется; редактируемая ссылка должна соответствовать
выбранному главному SKU. Главный вариант отслеживается всегда. Остальные по умолчанию выключены,
включая варианты существующих карточек после миграции. На странице товара можно
включать их отдельно или кнопками «Включить все» / «Выключить все».
Обычный сбор обновляет главный и включённые SKU. Новые найденные варианты
сохраняются с выключенным отслеживанием. Выключение не удаляет данные и историю.
При смене главного прежний отслеживается только при явном включении.

Если SKU закончился, сбор сохраняет доступные фото, параметры и связи
вариантов. Запрос с `oos_search=false` оставляет карточку товара вместо
перенаправления на поиск. Для отсутствующего SKU наличие — `out_of_stock`,
цена — `null`; старая отображаемая цена не становится текущей.
При первоначальном обходе цена каждого доступного связанного SKU получается
отдельно. При последующих обновлениях действуют настройки отслеживания выше.
Получить метаданные можно только пока Ozon возвращает их в ответе карточки.

## Ошибки и повтор

После ошибки получения данных приложение один раз повторяет обновление варианта
в том же запуске через 1 секунду (либо после более долгого `Retry-After`).
Внутренние попытки Ozon сохраняются. До завершения повтора окончательная ошибка
не показывается; успешно обновлённые варианты повторно не запрашиваются.
То же правило действует для числового JSON-режима и `--raw`.

Один SKU принадлежит одной карточке Ozon. Повторное добавление отклоняется;
обнаружение SKU другой карточки сообщает конфликт с ID обеих карточек.
PostgreSQL дополнительно запрещает одинаковый SKU в разных карточках Ozon:
индекс `ozon_sku_unique` и составной FK проверяют также площадку владельца.
Миграция `0021_ozon_sku_ownership` заполняет площадку существующих вариантов;
при уже имеющихся дубликатах она останавливается без удаления данных.
Автоматического объединения или переноса истории нет. Не удаляйте старую карточку
ради обхода конфликта: удаление каскадно удаляет историю. Объединение данных
требует отдельного решения.

Если `webAspects` содержит `aspectModalInfo.link`, нормализованное получение
догружает `webAspectsModal` через ту же Chrome-сессию и транспортные ограничения.
Проверяются принадлежность ссылки товару, аспект, число и идентичность SKU.
Объект только с `trackingInfo` не означает продолжения. Данные списка дополняют
варианты, не заменяя цену и метаданные точного товара. Ошибка загрузки продолжения
оставляет валидную цену и явный `variant_discovery_error`.

Предел обнаружения — 500 вариантов карточки. Превышение или неизвестное
продолжение списка даёт `VariantDiscoveryIncomplete`, а не усечённый успешный
результат. Валидная цена текущего SKU и успешные результаты остальных сохраняются.
Retry включает только failed/pending/unknown цели без расширения связей.
Для получения цен остальных известных вариантов включите их отслеживание и запустите сбор.
Retry повторяет ошибочные цели, сохраняя успешные данные.
Ошибки доступа Ozon не означают отсутствие товара; при запросе проверки откройте
Chrome приложения и выполните обычную проверку площадки.

## CLI и JSON без БД

Нормализованный JSON включает варианты из модальных списков. `--raw` возвращает
неизменённый ответ страницы SKU и не загружает дополнительные модальные списки.

```bash
.venv/bin/python main.py card add --marketplace ozon --external-id 2936650207
.venv/bin/python main.py card list
.venv/bin/python main.py collect --card-id <локальный_ID_карточки>
```

Эти команды требуют `DATABASE_URL`. В `card list` поле `external_id` — исходный
артикул карточки, `primary_external_id` — выбранный SKU, `primary_variant_id` —
его локальный ID.

Числовой режим `.venv/bin/python main.py 2936650207` не требует БД и возвращает
один точный снимок с полными параметрами текущего SKU и непосредственно найденными
соседями. Полный обход он не запускает. Флаг `--raw` возвращает исходный ответ.

## Хранение и перенос

Числовые префиксы и названия не определяют членство Ozon. Его подтверждают ссылки
вариантов витрины; связь сохраняется в `card_variants`.
Экспорт v3 хранит разные артикулы внутри карточки, главный SKU, параметры, фото и
раздельные истории. Импорт/preview проверяет владельца относительно файла и БД;
конфликт с БД возвращает HTTP 409 `variant_ownership_conflict` без частичных
изменений. Перенос сохранённого членства не требует сетевых запросов.

Миграция `0020_variant_tracking` добавляет выключенные предпочтения вариантов
и признак первоначального сбора. Локальные ID, главный и история сохраняются.
Перед обновлением приложения остановите прежние writers.

## Параллельность HTTP

Ozon использует свой request pool `max_in_flight_requests=100` без лимита стартов
в секунду и без card semaphore. Product/modal и retries получают отдельные слоты;
слот занят до полного тела или подтверждённого abort. Очередь исключена из HTTP
timeout. В смешанном run Ozon → Ali → WB выполняются последовательно, Chrome
остаётся общим. Политика: [ADR0015](../adr/0015-shared-request-dispatcher.md).
