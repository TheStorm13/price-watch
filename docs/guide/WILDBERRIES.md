# Wildberries: вариант товара и цена

[К содержанию](README.md)

## Добавление товара

В форме выберите Wildberries и укажите только артикул товара. Код размера
вводить не нужно: первый сбор найдёт все варианты этого артикула. Ссылка в URL
заполняет артикул, параметр `size` необязателен:

```text
https://www.wildberries.ru/catalog/179224846/detail.aspx
```

Одна карточка содержит все обнаруженные размеры с независимыми ценами и
историей. Главный вариант выбирается в деталях и задаёт цену каталога.
Начальный главный — первый обнаруженный вариант; минимальная цена не выбирается
автоматически. Внутренние варианты используют `nmId:optionId`, например
`179224846:296499716`. Каждый размер получает собственное точное наблюдение.
ID — положительные ASCII-числа в безопасном диапазоне JavaScript без ведущих
нулей; повторяющийся или некорректный size отклоняется.

```bash
.venv/bin/python main.py card add --marketplace wildberries \
  --external-id '179224846'
```

API/CLI принимают nmId, а также точные пары для внутренних вариантов.
Числовой `main.py <артикул>` остаётся одиночным режимом Ozon. WB доступен
без БД через ProductService и WildberriesConnector.

## Одна цена

Показывается и хранится одна цена: с WB Кошельком, а при подтверждённой
неприменимости кошелька — без него. Процент, округление и лимиты рассчитывает
текущая витрина с условиями профиля Chrome приложения. Ошибка загрузки условий
не допускает записи обычной цены. Цена другого варианта или стороннего банка
не заменяет выбранную. Нулевой остаток выбранного варианта означает
out_of_stock и price=null; неизвестное наличие остаётся unknown.

При исследовании цена была 1024 ₽ с кошельком и 1056 ₽ без; при итоговой
проверке — 1015 ₽ и 1047 ₽ соответственно. Это наблюдения, а не фиксированные
цены или скидка 3%. Другие цены не попадают в JSON, snapshot или историю.

## Сбор и ограничения

Direct CLI, очередь desktop/API/worker, расписание и повтор ошибок используют
общий builder. Ozon, AliExpress и WB совместно используют один Chrome и профиль,
с отдельной страницей каждой площадки. WB запрашивает данные с главной через
runtime витрины; навигация на каждый товар не требуется. Регион берётся из
профиля. Для WB запросы выполняются последовательно внутри страницы, чтобы
инициализация условий и восстановление доступа не прерывали соседний запрос.
Общий предел сбора — пять карточек одновременно.

В видимом Chrome пройдите ручную проверку WB и подтвердите продолжение.
При скрытом сборе после завершения запуска откройте Chrome приложения,
пройдите проверку и повторите сбор. Блокировка, таймаут, неизвестная схема
и неготовность условий завершаются ошибкой без фиктивной цены.

Получаются название, продавец, рейтинг отзывов и их число, варианты,
наличие, цена и доступный цвет из компактных static-данных. Полное описание,
изображение и остальные характеристики могут оставаться пустыми. Внутренний
runtime WB может измениться. Авторизованный lifecycle проверен синтетически;
живая проверка выполнялась в неавторизованном WB-контексте.

## Существующие данные

Миграция `0016_wildberries_size` преобразует числовой WB ID только при
однозначном `size` в соответствующей сохранённой ссылке. Локальные ID, история
и snapshots, группы, теги, настройки и цели запусков сохраняются. Активный сбор
или конфликт преобразованных идентичностей останавливает миграцию до UPDATE.
Перед обновлением завершите сбор и закройте старые службы; API применяет
миграции при старте.

Карточки без однозначного размера автоматически обнаруживают варианты по nmId
при следующем сборе. Старые ID и наблюдения сохраняются отдельно и не
приписываются произвольному размеру. Пустая запись обнаружения скрыта из списка
при появлении точных SKU; запись с историей остаётся доступной. Повтор ошибки
обнаружения также найдёт все размеры; повтор ошибки конкретного размера
собирает только его. Удалять и добавлять старую карточку заново не требуется.

Миграция 0018 создаёт товарный уровень и отдельные варианты с сохранением
истории. Исправление начального обнаружения не требует новой миграции.
Transfer v3 сохраняет варианты и независимые истории; товарный JSON остаётся 2.0.
