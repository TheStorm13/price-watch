# Нюансы и известные ограничения

[К содержанию](README.md)

## Desktop зависит от каталога проекта

`./price-watch` запускает уже собранный Tauri бинарник из дерева репозитория.
Сам бинарник ищет корневой `.env`, `.venv/bin/python`, `main.py` и Docker Compose
рядом с исходниками. Путь можно переопределить переменной
`PRICE_ANALYZER_PROJECT_DIR`. Это запуск из проекта, а не переносимый
установочный пакет. AppImage не собирается.

Desktop код жёстко проверяет API на `127.0.0.1:8000`, а локальный worker по
умолчанию подключается к PostgreSQL на `127.0.0.1:5432`. Настройки `API_PORT`
и `POSTGRES_PORT` в `.env` меняют публикацию контейнерных портов, но не эти
адреса внутри Tauri. Для desktop оставляйте стандартные порты. Если меняете
логин, пароль или имя БД, согласуйте `DATABASE_URL` для локального worker.

Release запуск не пересобирает Docker образ API после изменений Python кода.
Нужная команда приведена в [инструкции запуска](RUNNING.md#разработка-desktop-приложения).

## Браузер и режимы

При запуске desktop приложения Chrome не открывается. Кнопка «Открыть Chrome»
запускает системный Google Chrome на X11/XWayland с вкладками Ozon, Wildberries
и AliExpress. Его профиль хранится в `.playwright-profile`. При нажатии
«Обновить» приложение закрывает Chrome, открытый этой кнопкой, и только затем
запускает сбор. Worker использует тот же профиль, но запускает отдельный Chrome
на скрытом дисплее. Поэтому вход в Ozon, сохранённый в профиле, доступен при
сборе, а окна браузера сбора не появляются на рабочем столе.

Если Chrome не установлен, desktop сбор сообщает об ошибке. Профиль нельзя
одновременно использовать в двух процессах Chrome; перед автоматическим сбором
worker также закрывает открытый Chrome приложения через CDP. Контейнерный web
worker использует Chromium и отдельный профиль в Docker volume, доступный через
noVNC.

## Данные маркетплейсов

Коннектор реализован только для Ozon. Типы интерфейса уже упоминают
Wildberries и AliExpress, но API не позволяет добавить их карточки и сбор для
них отсутствует. Для Ozon цена берётся строго из `cardPrice`: обычная цена или
цена без карты не подставляется вместо неё.

Если товар пропал из продажи и Ozon перенаправил артикул на страницу поиска с
предложениями, ответ не содержит виджетов исходной карточки. Сейчас это ошибка
сбора, а не новое наблюдение `out_of_stock`; прежняя цена в истории остаётся
последним успешным наблюдением. Это подтверждено на артикуле `1604900984`.
Желаемое поведение записано в [будущих доработках](../FUTURE_CHANGES.md).

Сбой одной карточки не останавливает сбор других. Подробная причина есть в
логах и деталях запуска в интерфейсе. Ошибочные карточки можно повторить
отдельным запуском. Пока worker работает, он проверяет необходимость полного
автоматического сбора раз в минуту; отсчёт составляет 12 часов от последнего
полного запуска. Сбор одной карточки и повтор ошибок срок не сдвигают.
Выгодные предложения доступны в отдельной вкладке, а уведомление о
новой выгодной цене показывается в открытом интерфейсе. Отдельной таблицы
попыток пока нет.

## Поведение очереди при аварии

Worker выбирает только строки со статусом `queued`. Если worker аварийно
завершился, при следующем запуске устаревший `running` или `waiting_for_user`
переходит в `failed` с диагностической записью. Автоматического повторного сбора
нет. При обычном закрытии Tauri worker завершается вместе с приложением.
