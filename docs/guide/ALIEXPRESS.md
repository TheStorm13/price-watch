# AliExpress.ru: SKU и цена

[К содержанию](README.md)

## Добавление

В форме выберите AliExpress и укажите только ID товара. SKU вводить не нужно:
первый сбор автоматически найдёт все варианты. Товарная ссылка в URL заполняет
ID, параметр `sku_id` необязателен:

```text
https://aliexpress.ru/item/1005009868651525.html
```

Одна карточка хранит товар и все обнаруженные SKU с независимой историей.
Главный вариант выбирается в деталях и определяет цену в каталоге. Начальный
главный — первый обнаруженный вариант; его цена не подменяется минимальной.
Каждая цена проверяется отдельным точным запросом `productId:skuId`; изменение
URL не меняет идентичность варианта. ID остаются строками.

```bash
.venv/bin/python main.py card add --marketplace aliexpress \
  --external-id '1005009868651525'
```

API/CLI принимают productId, а также точные пары для внутренних вариантов.
Поддерживается российская витрина aliexpress.ru; повторяющийся или нечисловой
sku_id отклоняется. Короткие ali.click, .com и Choice channel не поддерживаются.
Числовой `main.py <артикул>` остаётся режимом Ozon; AliExpress доступен
без БД через ProductService и AliExpressConnector.

## Единственная цена

Для выбранного SKU берётся `priceWithCoupon.amount`, иначе `activityAmount`,
иначе `amount`. Отсутствие или null допускает следующий источник. Корректный
ноль сохраняется; повреждённая выбранная сумма или валюта кроме RUB — ошибка.
Сумма вычисляется точно из cents. isCouponAssigned=false не исключает цену с
купоном; приложение не получает и не применяет купон. Доставка и таможня к цене
не прибавляются. Другие цены не добавляются в общий JSON, snapshot или историю.

Наличие определяется остатком выбранного SKU: 0 означает out_of_stock и
price=null. Отсутствующий SKU или несовпадение идентификаторов в ответе — ошибка
сбора. Если ручка не даёт имя продавца, seller остаётся null.

## Сбор и ручная проверка

Direct collect, очередь desktop/API, расписание и повтор ошибок используют
один builder. Смешанный запуск Ozon/Ali/WB использует один процесс Chrome и профиль,
отдельные страницы площадок и общий лимит пяти собираемых карточек. Ali делает
fetch к productData с главной страницы, не открывая карточку каждого товара.

После неуспешного получения варианта общий слой один раз заново вызывает
коннектор через 1 секунду, сохраняя его внутренние попытки. Более долгий
`Retry-After` соблюдается, включая ответ 429 с CAPTCHA. Окончательная ошибка
и число неудачных обновлений появляются только после неуспешного повтора;
успешные варианты повторно не собираются. Временный сбой первоначальной
подготовки страницы допускает новую подготовку при следующем вызове.

В видимом Chrome пользователь проходит CAPTCHA и подтверждает продолжение
(в CLI — в терминале, при waiting_for_user — кнопкой «Проверка пройдена»).
Доступ затем проверяется снова. При скрытом/headless сборе цель получает ошибку:
после завершения запуска откройте Chrome приложения, пройдите проверку и
повторите сбор. Одновременные ручные проверки площадок обслуживаются по очереди.
Цены и схема ответа зависят от сессии и недокументированной ручки площадки.

## Существующие данные и импорт

Миграция `0015_aliexpress_sku` меняет только external_id старых числовых Ali
карточек с однозначным SKU в соответствующем URL. ID карточки, группы, теги,
настройки, updated_at и история сохраняются; snapshots не переписываются.
Карточки без однозначного SKU сохраняют историю и при следующем сборе
автоматически обнаруживают варианты по productId. Старые наблюдения без SKU
остаются отдельно: они не приписываются первому найденному варианту.
Повтор ошибки обнаружения запускает его снова; повтор ошибки конкретного SKU
обновляет только этот SKU. После успешного обнаружения пустая служебная запись
не показывается среди вариантов; запись со старой историей остаётся доступной.

Перед обновлением завершите активный сбор и закройте старые службы приложения.
Миграция 0018 переводит данные в товарные карточки и варианты; конфликт общих
настроек останавливает перенос до записи. Исправление начального обнаружения
не требует дополнительной миграции. Transfer v3 сохраняет варианты, главный
SKU и раздельные истории, включая старые наблюдения без SKU. Товарный JSON
остаётся версии 2.0.


При добавлении первоначальное обновление всех вариантов ставится в очередь
автоматически. Главный отслеживается всегда; остальные по умолчанию выключены.
На странице товара можно включить отдельные размеры/цвета или все известные
варианты сразу. Выключение сохраняет прежние данные и историю.
