# AliExpress.ru: SKU и цена

[К содержанию](README.md)

## Добавление

В форме выберите AliExpress и укажите ID товара и SKU варианта. Полная ссылка
в поле URL заполняет оба поля, например:

```text
https://aliexpress.ru/item/1005009868651525.html?sku_id=12000061135122688
```

В API, CLI и импорте `externalId`/`external_id` имеет строковый формат
`productId:skuId`. Два SKU одного товара — независимые карточки с отдельной
историей. SKU обязателен; приложение не выбирает первый или самый дешёвый
вариант. Изменение URL не может менять идентичность карточки. Без URL
сохраняется каноническая ссылка. ID не преобразуются в JavaScript number.

```bash
.venv/bin/python main.py card add --marketplace aliexpress \
  --external-id '1005009868651525:12000061135122688'
```

Поддерживается российская витрина aliexpress.ru с единственным числовым
параметром sku_id. Короткие ali.click, .com и Choice channel не поддерживаются.
Числовой одиночный `main.py <артикул>` остаётся режимом Ozon; AliExpress можно
получить без БД через общий ProductService и AliExpressConnector.

## Единственная цена

Для выбранного SKU берётся `priceWithCoupon.amount`, иначе `activityAmount`,
иначе `amount`. Отсутствие или null допускает следующий источник. Корректный
ноль сохраняется; повреждённая выбранная сумма или валюта кроме RUB — ошибка.
Сумма вычисляется точно из cents. isCouponAssigned=false не исключает цену с
купоном; приложение не получает и не применяет купон. Доставка и таможня к цене
не прибавляются. Другие цены не добавляются в общий JSON, snapshot или историю.

Наличие определяется остатком выбранного SKU: 0 означает out_of_stock и
price=null. Отсутствующий SKU или несовпадение идентификаторов в ответе — ошибка
сбора. Если ручка не даёт имя продавца, seller остаётся null.

## Сбор и ручная проверка

Direct collect, очередь desktop/API, расписание и повтор ошибок используют
один builder. Смешанный запуск Ozon/Ali/WB использует один процесс Chrome и профиль,
отдельные страницы площадок и общий лимит пяти собираемых карточек. Ali делает
fetch к productData с главной страницы, не открывая карточку каждого товара.

В видимом Chrome пользователь проходит CAPTCHA и подтверждает продолжение
(в CLI — в терминале, при waiting_for_user — кнопкой «Проверка пройдена»).
Доступ затем проверяется снова. При скрытом/headless сборе цель получает ошибку:
после завершения запуска откройте Chrome приложения, пройдите проверку и
повторите сбор. Одновременные ручные проверки площадок обслуживаются по очереди.
Цены и схема ответа зависят от сессии и недокументированной ручки площадки.

## Существующие данные и импорт

Миграция `0015_aliexpress_sku` меняет только external_id старых числовых Ali
карточек с однозначным SKU в соответствующем URL. ID карточки, группы, теги,
настройки, updated_at и история сохраняются; snapshots не переписываются.
Карточки без однозначного SKU пропускаются без изменений. При сборе они получают
ошибку «Не указан SKU» только в данных запуска, без товарного запроса или записи
цены; соседние корректные карточки продолжают собираться.

Перед обновлением завершите активный сбор и закройте старые службы приложения.
API применяет миграции при старте. Активный запуск или конфликт преобразуемых
идентичностей останавливает миграцию до изменения данных; автоматического
объединения карточек и историй нет. Необходимо разрешить конфликт отдельно.

Экспорт v2 сохраняет все исторические идентичности, включая старые карточки без
SKU. Новый импорт v2 требует пару и соответствующий URL: product-only записи
нужно явно подготовить перед импортом. Версии transfer v2 и товарного JSON 2.0
не менялись. Проверки миграции выполнялись только в отдельной временной БД.
