| Ozon | `marketplace_connector/connectors/ozon` | Composer JSON и нормализация |
| AliExpress | `marketplace_connector/connectors/aliexpress` | SKU identity, productData и нормализация одной цены |

| Одиночный CLI | `marketplace_connector/connectors/ozon/cli.py`, `main.py` | Получить JSON товара без БД |

Рабочий интерфейс запускается только в Tauri. Браузерный `dev:e2e` использует
mock API для проверки UI и не подключается к живым службам.

```mermaid
flowchart LR
    UI[React в Tauri] --> API[FastAPI]
    API --> DB[(PostgreSQL)]
    Worker[Локальный Python worker] --> DB
    Worker --> Connector[Коннекторы Ozon, AliExpress, WB и Маркета]
    Connector --> Chrome[Системный Google Chrome]
    Chrome --> Ozon[Ozon]
    Chrome --> Ali[AliExpress.ru]
    Chrome --> WB[Wildberries]
    Chrome --> YM[Яндекс Маркет]
```

## UI-слой

Интерфейс использует shadcn/ui из официального `@shadcn`, Radix, Tailwind 4
и Lucide. Локальные примитивы находятся в `frontend/src/components/ui`,
предметные композиции — в `frontend/src/components/product`, логика экранов —
в feature-компонентах и hooks. Recharts отвечает за графики истории цен.
Тема задана в `src/styles/tokens.css`, семантические Tailwind mappings и
порядок CSS layers — в `src/styles/global.css` относительно `frontend/`.

Меню, панели и подтверждения используют DropdownMenu, Sheet, Dialog и
AlertDialog; выпадающие списки — Select с общей темой. При изменениях
сохраняются клавиатурная навигация и восстановление фокуса.
Правила сопровождения: `frontend/AGENTS.md`; решение и альтернативы:
[ADR 0003](../adr/0003-shadcn-ui-primitives.md).

## Модели товара и отслеживания

`marketplace_connector.domain.models.MarketplaceCard` — общий результат любого
коннектора: ProductRef, данные товара, Decimal-цена, наличие и collected_at.
`price_watch.domain.models.TrackedCard` — локальная запись отслеживания с ID,
ref, отображаемыми полями, группой, тегами и настройками. Она собирается из настроек товара `marketplace_cards` и данных выбранного
варианта `card_variants`: название, ссылка, фото, параметры и время сбора.
Цена, наличие и метрики читаются из истории этого же варианта. Смена главного
не требует нового сбора и не копирует данные между вариантами.

Ozon использует самостоятельные артикулы вариантов. Исходный SKU остаётся
артикулом локальной карточки; остальные члены подтверждаются связями витрины.
Первоначальный сбор расширяет pending-цели до исчерпания связей; обычный сохраняет
новые варианты с выключенным отслеживанием. Add, discovery и import
берут общий advisory lock владения Ozon перед блокировками запуска/карточки;
конфликт владельца не переносит историю автоматически.
Площадка хранится также в `card_variants`: составной FK к владельцу запрещает
подмену площадки, частичный unique index гарантирует одного владельца SKU Ozon.
См. [ADR 0012](../adr/0012-ozon-variant-family.md) и [Ozon](OZON.md).
`TrackedCardOverview` и frontend `TrackedCardView` — проекции записи и метрик.

У каждой площадки собственные модель входных данных и mapper. Потребители
общего товара не разбирают Ozon-структуры. Числовой CLI получает товар без БД.
Деньги передаются в JSON строками; формат описан в [контракте данных](DATA_AND_API.md).
Мотивы и альтернативы: [ADR 0005](../adr/0005-marketplace-card-and-tracking-record.md).

## Сбор через интерфейс

1. При ручном сборе React просит Tauri закрыть вручную открытый Chrome, затем
   отправляет `POST /api/runs` для одной карточки или всех карточек с
   подключённым коннектором. Исключение из выгодных предложений не исключает
   карточку из сбора.
2. API создаёт строку запуска со статусом `queued` и фиксирует цели в `collection_run_targets`.
3. Worker раз в секунду ищет очередь и атомарно забирает один запуск через
   `FOR UPDATE SKIP LOCKED`. Статус становится `running`, исполнение получает отдельный токен владельца.
   Раз в минуту worker также проверяет 6-часовой срок и при необходимости
   создаёт полный запуск без дублирования активной очереди.
4. Общий `RunExecutor` запускает heartbeat и создаёт коннекторы внутри lifecycle. Worker открывает системный Chrome с профилем из
   пользовательского каталога данных на скрытом дисплее и подключается через локальный CDP.
   Builder передаёт трём клиентам один `ChromeSession` с acquire/release;
   последний потребитель штатно закрывает браузер. Старый Ozon lifecycle удалён.
   Каждая площадка владеет своим транспортом и страницей.
5. Коннектор открывает одну страницу `https://www.ozon.ru/` на сеанс и выполняет
   до 100 параллельных `fetch` к `/api/composer-api.bx/page/json/v2` с
   `url=<закодированный /product/{sku}/>` и `credentials: "include"`.
   Навигации на карточки нет; авторизация и регион остаются в профиле Chrome.
   Транспорт проверяет HTTP-статус, тип ответа и структуру JSON, сохраняя исходный
   успешный текст для raw. Таймаут 30 секунд охватывает получение тела;
   отмена затрагивает только свой запрос. До трёх HTTP-попыток используют общий
   предел `max_in_flight_requests=100`, без планового лимита стартов.
   Отдельного ограничения целых карточек нет. Такой же HTTP-предел имеют Ali и WB;
   площадки идут последовательно, общий Chrome удерживается на весь run.
   Выбор политики: [ADR0015](../adr/0015-shared-request-dispatcher.md).
   `Retry-After` задерживает все новые отправки; ожидание свыше 30 секунд
   завершается `RateLimited` без раннего повтора. Восстановление общей страницы
   выполняется не более одного раза за сеанс после завершения активных запросов.
   Повторный отказ доступа блокирует новые отправки в этом сеансе.
   Parser создаёт `OzonProductData`, затем `OzonMapper` преобразует его в общий
   `MarketplaceCard`; цена берётся только из `cardPrice` и нормализуется как Decimal.
   Нормализованный Ozon client дополняет аспекты через наблюдаемые ссылки
   `/modal/aspectsNew` и `webAspectsModal`, сохраняя точную цену исходного SKU.
   Модальные запросы используют те же cooldown, ограничения и HTTP-попытки.
   Raw CLI сохраняет исходный ответ без дополнения.
   AliExpress открывает `https://aliexpress.ru/` и вызывает
   `/aer-jsonapi/v1/bx/pdp/web/productData` с productId/sourceId=0/sku_id.
   Parser проверяет точную пару и выбранную строку SKU, mapper возвращает одну
   Decimal-цену coupon → activity → regular. Политика ограничений такая же,
   transports независимы; общий challenge lock согласует только ручное участие.
   WB готовит контекст профиля и условия кошелька, затем получает detail JSON
   через runtime на главной. Проверяются точные nmId/optionId; возвращается одна
   Decimal-цена с приоритетом WB Кошелька. Повторы витрины ограничены транспортом.
   Общий validator идентичностей находится в application/card_identity.py.
   Подробности и перенос данных — [Wildberries](WILDBERRIES.md), [ADR 0009](../adr/0009-wildberries-size-and-wallet-price.md).
6. `RunRepository.save_result` заполняет пустое название выбранного варианта,
   сохраняет его фото, параметры и ссылку до проверки изменения цены; снимок в `price_history`
   добавляется при изменении цены или наличия. Ошибки по товарам сохраняются с traceback
   в запуске. Интерфейс опрашивает запуск примерно раз в секунду и обновляет
   карточки после завершения.

Площадки выполняются последовательно (Ozon → Ali → WB); внутри площадки
HTTP-запросы выполняются асинхронно вне транзакции БД. Результаты
сохраняются в PostgreSQL по одному по мере завершения запросов. Карточка,
история, результат цели и счётчики фиксируются атомарно под проверкой lease.
Повтор результата не дублирует историю или прогресс. Потеря владения отменяет
fetch-задачи и закрывает сеансы; старый исполнитель не может писать или завершить запуск. Ошибка одной
карточки увеличивает `failure_count`, но остальные карточки продолжают
обрабатываться.

Над внутренними ретраями транспортов `ProductService` выполняет один дополнительный
вызов коннектора для неуспешной цели того же запуска. Общий helper
`marketplace_connector/application/retry.py` ждёт 1 секунду либо больший оставшийся
`Retry-After` в пределах 30 секунд; backoff не удерживает HTTP-слот. Превышение
бюджета или `RateLimited.retry_allowed=False` прекращает получение цели без
нового запроса. `UnsafeBrowserTeardown`, включая Ozon discovery, прекращает весь
запуск и не является необязательной ошибкой вариантов. Подтверждённое
`ProductNotFound` обрабатывается как прежде, без повтора. До исчерпания внешней
попытки цель остаётся pending: первая ошибка попадает в лог, окончательная
диагностика при двух сбоях содержит обе причины. Успешные цели не повторяются;
ошибка записи результата не вызывает новый запрос площадки. Потеря lease и отмена
останавливают ожидание и запросы. Числовой JSON и raw CLI используют тот же helper
в одном браузерном сеансе, без БД. Для страницы товара и каждого модального
JSON-ресурса Ozon допускается до трёх HTTP-попыток на вызов; дополнительный
внешний вызов может повторить получение. AliExpress получает один JSON-ресурс,
до шести HTTP-попыток за два вызова. Ограничения восстановления сессии
сохраняются. После временного сбоя первоначальной подготовки Ozon/AliExpress
следующий вызов заново готовит страницу; неуспешная страница закрывается.

Контракт каждого коннектора требует `async get_product` и асинхронный
`collection_session`. API, worker и сервис сбора используют `await` для
обращений к PostgreSQL через SQLAlchemy `AsyncSession`. API, worker и исполнитель
получают отдельные порты; `bootstrap.py` собирает самостоятельные адаптеры
карточек, запусков, чтения истории, групп и импорта/экспорта без наследуемого фасада.
`PostgresCatalogReader` читает типизированные входы в одном read-only снимке
REPEATABLE READ, а `CatalogService` строит cards/groups/deals после закрытия
транзакции. UI публикует их одной записью кеша.
`useCatalogModel` готовит фильтры, порядок и состав групп; отдельные memo-компоненты
отображают строки, плитки и заголовки групп. Видимые строки списка/сетки, участники
больших групп и кандидаты редактора виртуализированы; полная модель снимка и выбор
ID сохраняются в памяти. Контекст команд сбора отделён от прогресса, поэтому
неизменившийся каталог не перерисовывается при каждом heartbeat.
История/график и экспорт выбирают только нужные поля без raw snapshot.
Диагностика хранится в существующем `collection_runs.errors`, максимум 20/128 KiB
только у последнего созданного запуска. Shared/exclusive advisory guard сериализует
очистку при создании с записью результатов; lease/цели/счётчики остаются атомарными.
Один Rust drain обслуживает stdout/stderr принадлежащего процесса; общий Python
ChromeSession использует тот же предел файла 10 MiB, очистку при заполнении/старте
и чтение фиксированными блоками без очереди. Решения и ограничения:
[ADR 0010](../adr/0010-bounded-ui-diagnostics-and-logs.md).
Миграции Alembic
выполняются через отдельное синхронное соединение при запуске API или командой CLI.

CLI перед запуском и worker до проверки расписания выполняют общее
восстановление устаревших running/waiting_for_user, включая записи без
владельца. Шестичасовой срок от начала последнего полного запуска сохраняется.
Ручной повтор выбирает только failed/pending/unknown известные цели.

Правила выгодности и представителя находятся в `domain/catalog_rules.py`,
шестичасовой срок и порог устаревания — в `domain/collection_policy.py`.
Они получают значения и время явно, без SQLAlchemy и HTTP. Решение о плановом
запуске применяется внутри транзакции `RunRepository` под advisory lock;
запись результата цели, карточки, истории и счётчиков также остаётся одной
операцией. Состав портов и альтернативы: [ADR 0007](../adr/0007-application-rules-and-persistence-boundaries.md).

Ограничения частоты — локальная политика приложения. Мотивы выбора транспорта:
[ADR 0006](../adr/0006-ozon-session-json-transport.md).

## Ручная проверка площадки

В desktop режиме worker использует скрытый дисплей. Если площадка требует ручную
проверку, запуск завершается с ошибкой; пользователь может открыть Chrome
кнопкой, пройти проверку и повторить сбор. При прямом CLI сборе подтверждение
принимается в терминале.

## Три способа использовать один коннектор

- UI и API создают запуск в очереди; его выполняет фоновый worker.
- `main.py collect` исполняется через тот же `RunExecutor`, создаёт owned
  запуск сразу в running и блокирует терминал до окончания, не требуя worker.
- `main.py <артикул>` получает один нормализованный JSON без PostgreSQL.

Общий формат снимка описан в
`marketplace_connector/serialization/product.schema.json`. Реальные
коннекторы реализованы для Ozon и AliExpress. Числовой одиночный CLI остаётся
режимом Ozon; AliExpress доступен без БД через ProductService. Идентичность SKU,
цена и миграция: [ADR 0008](../adr/0008-aliexpress-sku-and-shared-browser.md)
и [руководство AliExpress](ALIEXPRESS.md).

Ozon/Ali сохраняют отдельные транспорты. Они выполняют HTTP/access checks;
product parsing, строгая проверка и mapping принадлежат клиентскому pipeline.
Adapter response содержит исходный текст и готовую MarketplaceCard; connector
не разбирает ответ повторно. Raw API проверяет документ без изменения вывода.
WB сохраняет native SDK: поколения профиля удерживаются живыми потребителями,
а зависания bootstrap и renderer завершают сбор с подтверждённым teardown.

Маркет выполняется после WB в общем Chrome, с отдельным HTTP pool 100.
FamilySession объединяет параллельные обходы по проверенному parent product и кеширует точные
снимки SKU только до завершения collection_session. Владение SKU защищают
YANDEX_MEMBERSHIP_LOCK и `yandex_sku_unique` при add/import/discovery.
Неполный обход сохраняет точную цену, отмечая target как failed. См. [контракт Маркета](YANDEX_MARKET.md).
