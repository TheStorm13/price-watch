# Яндекс Маркет: SKU, карта и промокоды

[К содержанию](README.md)

Добавьте артикул выбранного товара из его полного адреса, например `5355099814`.
Приложение сохраняет этот артикул, даже если внутренние ID Маркета отличаются.
Необязательная ссылка должна иметь вид
`https://market.yandex.ru/card/<название>/<SKU>` и соответствовать выбранному варианту.
Для короткой ссылки `/cc/...` сначала откройте товар в Chrome и скопируйте полный адрес.

Сбор использует общий Chrome-профиль приложения. Войдите в Маркет кнопкой Chrome
перед сбором. Анонимный ответ не сохраняется как успешная цена: коннектор вернёт
ошибку авторизации. При CAPTCHA в скрытом Chrome откройте видимый Chrome приложения,
пройдите проверку и повторите запуск. Уже запущенный Chrome приложения закрывается
обычной подготовкой сбора; вручную запускать второй процесс с тем же профилем нельзя.

Первоначальный сбор обходит ссылки размеров и цветов до исчерпания связанного
графа и сохраняет отдельную цену каждого SKU. Независимые страницы вариантов
читаются параллельно через общий пул Маркета (до 100 активных запросов). Главным
остаётся введённый SKU,
остальные по умолчанию выключены для регулярного отслеживания. Включайте нужные
на странице товара. Последующие запуски записывают историю главного и включённых
вариантов; новые обнаруженные SKU получают начальные цены. Для проверки полного
состава семейства витрина читается и для соседних SKU; снимки кешируются только
внутри запуска, поэтому несколько целей одного семейства не повторяют обход.
Retry не расширяет сохранённый набор целей.

Цена одной единицы рассчитывается от цены с картой Яндекса. Если её действительно
нет, базой служит явно обозначенная обычная цена. Из привязанных к выбранному
предложению действующих промокодов выбирается **один** с минимальным итогом.
Промокоды не складываются между собой. Порог заказа проверяется без добавления
других товаров; учитываются максимум скидки и ограничения. Неизвестные условия,
непроверенное ограничение аккаунта и обрезанная API фиксированная скидка исключают
код с причиной в снимке. Необходимость оплачивать Яндекс картой сохраняется.

Пример: `2959 × (1 − 10 / 100) = 2663.10 RUB`. Используется Decimal и
ROUND_HALF_UP до двух знаков после вычисления. Поле витрины `withPromoCode` не
используется как итог: оно может быть рассчитано от обычной цены.
Это расчёт по данным предложения, не подтверждённая цена checkout. Коннектор
не меняет корзину и не оформляет заказ. Отображение промокода в UI не добавлено.

Основание цены доступно в JSON-снимке истории: `extensions.yandex_market` содержит
артикул (`sku_id`), внутренний SKU (`market_sku_id`), product/offer/business IDs,
обычную/карточную/базовую/итоговую цены, выбранный
код, параметры, срок и исключённые кандидаты. Денежные значения — строки.
`calculation_basis=card_plus_single_promo`, `verification=calculated`.
Cookies, данные пользователя и HTML в историю не попадают. Неизменная цена и
наличие не создают новый снимок только ради смены промокода.

Цены читаются из связанных Apiary-коллекций точного SKU и предложения. Ссылки
вариантов берутся из контролов витрины; декларированное число значений проверяется.
Поддерживаются HTML-контролы и структурированный список выбранной карточки
`jumpListShort`, когда его полный состав подтверждён числом значений контрола.
Все явно связанные варианты этого структурированного списка входят в карточку,
даже если у них разные внутренние productId. Главным остаётся введённый артикул.
Обход и снимки разделяются между запросами одного списка вариантов. Неожиданный
другой productId в обычном контроле
размеров/цветов по-прежнему означает ошибку discovery. Неизвестное продолжение
или сбой соседнего SKU означает неполный обход: подтверждённые цены сохраняются, цель отмечается ошибкой. Старые варианты
и историю по неполному списку не удаляем. Доступность определяется для точного
SKU и текущих настроек региона/аккаунта: есть остаток и доставка. Отсутствие
размеров у товара не означает отсутствие в продаже.

Миграция `0022_yandex_sku_ownership` добавляет уникального владельца SKU Маркета.
Она не переписывает цены и останавливается при конфликтующих существующих данных.
Автоматического объединения карточек нет. Старые карточки начинают собираться
без пересоздания; их исходная история сохраняется.

Проверки: `tests.test_yandex_market`, `tests.test_yandex_market_transport`,
`tests.test_request_pools_browser`; PostgreSQL — `tests.test_yandex_market_integration`
с отдельной disposable `TEST_DATABASE_URL`. E2E `yandex-market.spec.ts` проверяет
добавление и запуск на mock API, не живую площадку. Live smoke 2026-11-10 нашёл
64 SKU указанного товара; это не гарантия неизменности состава или акций.

Изображения Маркета загружаются с `avatars.mds.yandex.net`. Этот CDN разрешён
существующей политикой локального fake DNS; HTTPS, проверка адресов и сертификата
остаются обязательными. HTTP 200 с оборванным HTML повторяется как временная
ошибка конкретного запроса, а не как потеря авторизации. Запросы карточек используют
HTML Accept и `cache: no-store`, чтобы не получать устаревшие цены или обрывки
документа из HTTP-кеша. Подтверждённый анонимный ответ по-прежнему требует входа.
