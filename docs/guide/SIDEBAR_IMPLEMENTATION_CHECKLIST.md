# Перенос согласованной боковой панели в приложение

Согласованный вариант демо перенесён в основной интерфейс изменением `adopt-catalog-sidebar`.
Этот документ служит чеклистом приёмки; результаты проверок и ограничения записаны в
`docs/workflow-runs/adopt-catalog-sidebar.md`. Прежнее демо `demo-sidebar-layouts` сохраняет историю согласования.

## Зафиксированный интерфейс

| Область | Что сохранить при внедрении |
| --- | --- |
| Название | **Price watch** в пользовательском интерфейсе, окне, загрузке и трее. `price-watch` остаётся техническим именем репозитория, пакетов и бинарника. Переименование пользовательских надписей уже попало в обычное приложение. Само название — обычный текст без клика и сброса фильтров; реализовано в основном интерфейсе. |
| Каталог | Один общий каталог. Не разделять выгодные и остальные товары по разным страницам. Использовать выбранный второй вариант панели; переключателя вариантов больше нет. |
| Шапка каталога | «Карточки товаров», справа один счётчик «Показано n из m товаров». Старые «Карточки» и подзаголовок отсутствуют. Считать отдельные карточки, включая участников групп: n — совпадения с фильтрами, m — весь каталог; галочки массового выбора не влияют. |
| Поиск | Над результатами, в основной области. «Название или артикул», поиск по названию и внешнему артикулу маркетплейса; внутренний ID базы не используется. |
| Переключатель вида | Список/сетка слева над результатами, не справа. Переключение не сбрасывает фильтры. |
| Боковая панель | Постоянная слева, 260 px. Середина прокручивается независимо; служебные действия остаются внизу. |
| Действия | «Добавить карточку», «Обновить все цены», «Создать группу»; ниже фильтры; внизу Chrome, импорт/экспорт, настройки. Сохранить массовые действия над отмеченными карточками. |
| Добавление | Панель появляется слева, ширина 420 px. Работает из каталога, пустого каталога и деталей товара. Сохранить валидацию, блокировку закрытия при сохранении и возврат фокуса. Изменение стороны редактирования карточки не согласовывалось: сейчас редактирование справа. |
| Прогресс | Появляется в правом нижнем углу окна: ширина 490 px, отступы справа/снизу 28 px, максимальная высота calc(100dvh - 56px). Используется существующая модель сбора, включая проверку пользователя, продолжение и завершение. |

## Фильтры: порядок и точная семантика

| Порядок | Контрол | Поведение |
| --- | --- | --- |
| 1 | Наличие | Один чекбокс «Только в наличии». Выключен — все товары; включён — только `in_stock`. Отсутствие данных исключается вместе с отсутствующими товарами. Подпись «Нет данных» в самой карточке сохранена: её переименование отдельно не выполнялось. |
| 2 | Сортировка | «Сначала выгодные» по умолчанию; «Сначала дешёвые»; «Сначала дорогие». Без сортировки по обновлению. Заголовки всех столбцов переключают сортировку по возрастанию и убыванию; активный порядок отражается в панели и URL. Явная сортировка цены применяется ко всем результатам без отдельного приоритета выгодных; неизвестная цена в конце в обоих направлениях. |
| 3 | Выгодность | «Все предложения» / «Выгодные» / «Невыгодные». |
| 4 | Маркетплейсы | Множественный выбор, по умолчанию все. Обязательно хотя бы один. Последний выбранный чекбокс недоступен для снятия, пока не выбран другой. В демо: Ozon, Wildberries, AliExpress, Яндекс Маркет. |
| 5 | Теги | Множественный выбор, по умолчанию все, включая товары без тегов. При выборе нескольких достаточно хотя бы одного совпавшего тега. Пустой выбор — «Без тегов», показывает только товары без тегов. |

- Закрытые поля показывают «Все маркетплейсы» / «Все теги» при полном выборе; один выбранный — его название, несколько — «Выбрано: n».
- В выпадающем списке только отдельные чекбоксы и кнопка общего действия. Не дублировать название «Теги» и не добавлять общий чекбокс «Все».
- Кнопка общего действия компактная, слева, с обводкой, по ширине текста. Не растягивать на весь список. При частичном выборе — «Выбрать все»; при полном — «Снять выбор» у тегов, «Оставить один» у маркетплейсов.
- Выпадающий список равен ширине поля и помещается в боковой панели. В демо фактическая ширина 212 px, кнопка высотой 28 px.
- Пустой/невалидный выбор маркетплейсов в URL нормализуется до всех. Пустой выбор тегов отличается от отсутствующего параметра.
- Комбинации фильтров и вид сохраняются при перезагрузке и возврате из деталей. «Сбросить» появляется справа от переключателя списка/плиток и очищает фильтры, сохраняя вид. Производственный URL не должен зависеть от `sidebar=2`.

## Таблица и плитки

- Все строки товаров и групп имеют одинаковую ширину в пределах текущего размера окна; заголовки и значения выровнены по общей сетке. Не растягивать колонки на всё широкое окно.
- Чекбокс находится между левым краем строки и фотографией; не накладывается на фотографию. В плитке её существующий чекбокс сверху сохранён.
- В колонке маркетплейса только значок, без дублирующей подписи Ozon/Wildberries. Доступное имя и подсказка с названием сохраняются. В плитках название маркетплейса не убиралось.
- Начиная с «Выгода», **заголовки и содержимое** колонок центрированы. Проверять обе части: utility-класс заголовка может перекрыть общее CSS-правило.
- После последней правки таблица в демо: 1060 px; при ширине окна <=1200 px — 980 px. Ширина колонки товара 300/220 px соответственно. Внутренние горизонтальные отступы ячеек 8 px.
- Колонки: выбор 32, товар 300/220, выгода 156, цена 88, минимум 96, средняя 88, маркетплейс 100, наличие 144, действия 56 px.
- Наличие и действия закреплены справа при прокрутке. Отступ закреплённого наличия — 56 px, согласован с шириной действий. Три точки должны целиком помещаться в ячейке с отступом от края (в измеренном демо около 13 px).
- «Нет в наличии» должно целиком помещаться с отступами с обеих сторон; его надпись длиннее «В наличии». Не возвращать прежнюю узкую колонку.
- В плитках все числовые цены, включая выгоду, имеют размер 14 px. «Сейчас не выгодно» — 13 px, обычное начертание 400, приглушённый серый цвет. Положительная выгода остаётся выделенной.
- Последняя проверенная типографика: в списке цены и наличие 14 px; в плитке цены 14 px, наличие 12 px. Вопрос о размерах был уточнением: требования сделать наличие в плитке 14 px не было.
- Горизонтальная прокрутка ограничена таблицей, не всей страницей. Поддерживаемый текущим приложением минимум — 1024 px. Сохранять виртуализацию и измерения строк при смене вида/ширины окна.

## Согласованные группы, счётчик и навигация

Решение пользователя от 2026-11-06 заменяет прежние открытые вопросы. **Ниже поведение, перенесённое в основной интерфейс.**

1. Группа — объединение товаров, а не один фиксированный «лучший товар». Все активные условия проверяются у каждого товара. Один и тот же товар должен соответствовать всей комбинации условий; нельзя собрать совпадение из свойств разных участников.
2. Группа показывается, если есть хотя бы один подходящий участник. При раскрытии видны только подходящие товары. В резюме группы — «n из m товаров», например «2 из 5 товаров»: совпадения внутри этой группы / все её участники. При отсутствии совпадений группа скрывается.
3. Представитель свёрнутой группы — первый подходящий товар по текущей сортировке. При дешёвых сначала это самый дешёвый, при дорогих — самый дорогой с известной ценой, при выгодных — первый по выбранному правилу выгодности. Он меняется вместе с фильтрами/сортировкой. Доступные теги собираются из всех карточек, включая остальных участников групп.
4. Общий счётчик считает каждую карточку один раз, включая товары в группах. Пример: из 20 карточек 8 подходят — «Показано 8 из 20 товаров». Сворачивание групп и галочки массового выбора не меняют этот показатель. Счётчик отмеченных галочками карточек остаётся в панели массовых действий.
5. Price watch — обычный текст без роли ссылки/кнопки. Возврат из деталей — явная ссылка «К карточкам», сохраняющая поиск, фильтры и список/плитки. Закрытие форм/настроек возвращает на прежний экран.

Демо проверяет каждого участника целиком, собирает теги всех карточек, считает отдельные товары и выводит название обычным текстом. Редактор группы получает полный исходный состав, даже когда фильтры оставили видимой только его часть. В сетке числовые цены резюме группы также имеют размер 14 px, а «Сейчас не выгодно» — приглушённый текст 13 px / 400.

## Проверки и ограничения

Точные команды, результаты и исправления записаны в `docs/workflow-runs/adopt-catalog-sidebar.md`.
Проверки охватывают типы, unit, mock E2E, production desktop-сборку, список/сетку
при 1440×900 и 1024×768, группы, фильтры, массовые действия, возврат из деталей,
импорт/экспорт, прогресс и виртуализацию больших каталогов.

Настройки и Chrome подключены к настоящим командам. Браузерные E2E работают с mock API;
нативные вызовы проверяются с mocked invoke. Запуск реальных Chrome, фонового режима,
сбора и выхода в нативном WebView не подтверждён этими проверками и остаётся отдельным
smoke-сценарием на изолированных данных. Рабочие службы и пользовательская база не запускались.

`dev:demo` открывает тот же постоянный интерфейс с mock API, без отдельной компоновки.
Принято пользователем 2026-11-06. Основные спецификации синхронизированы; изменение архивировано в `openspec/changes/archive/2026-11-06-adopt-catalog-sidebar/`.
