## Зафиксированный интерфейс

| Область | Что сохранить при внедрении |
| --- | --- |
| Название | **Price watch** в пользовательском интерфейсе, окне, загрузке и трее. `price-watch` остаётся техническим именем репозитория, пакетов и бинарника. Переименование пользовательских надписей уже попало в обычное приложение. |
| Каталог | Один общий каталог. Не разделять выгодные и остальные товары по разным страницам. Использовать выбранный второй вариант панели; переключателя вариантов больше нет. |
| Шапка каталога | «Карточки товаров», справа один счётчик «Выбрано n из m товаров». Старые «Карточки» и подзаголовок отсутствуют. Отдельно учесть семантику счётчика ниже. |
| Поиск | Над результатами, в основной области. «Название или артикул», поиск по названию и внешнему артикулу маркетплейса; внутренний ID базы не используется. |
| Переключатель вида | Список/сетка слева над результатами, не справа. Переключение не сбрасывает фильтры. |

| Действия | «Добавить карточку», «Обновить все цены», «Создать группу»; ниже фильтры; внизу Chrome, импорт/экспорт, настройки. Сохранить массовые действия над отмеченными карточками. |
| Добавление | Панель появляется слева, ширина 420 px. Работает из каталога, пустого каталога и деталей товара. Сохранить валидацию, блокировку закрытия при сохранении и возврат фокуса. Изменение стороны редактирования карточки не согласовывалось: сейчас редактирование справа. |

## Фильтры: порядок и точная семантика

| Порядок | Контрол | Поведение |
| --- | --- | --- |
| 1 | Сортировка | «Сначала выгодные» по умолчанию; «Сначала дешёвые»; «Сначала дорогие». Без сортировки по обновлению и дополнительных сортировок по заголовкам таблицы. Явная сортировка цены применяется ко всем результатам без отдельного приоритета выгодных; неизвестная цена в конце в обоих направлениях. |
| 2 | Маркетплейсы | Множественный выбор, по умолчанию все. Обязательно хотя бы один. Последний выбранный чекбокс недоступен для снятия, пока не выбран другой. В демо: Ozon, Wildberries, AliExpress, Яндекс Маркет. |
| 3 | Наличие | Один чекбокс «Только в наличии». Выключен — все товары; включён — только `in_stock`. Отсутствие данных исключается вместе с отсутствующими товарами. Подпись «Нет данных» в самой карточке сохранена: её переименование отдельно не выполнялось. |
| 4 | Теги | Множественный выбор, по умолчанию все, включая товары без тегов. При выборе нескольких достаточно хотя бы одного совпавшего тега. Пустой выбор — «Без тегов», показывает только товары без тегов. |
| 5 | Выгодность | «Все предложения» / «Выгодные» / «Невыгодные». |

- Закрытые поля показывают «Все маркетплейсы» / «Все теги» при полном выборе; один выбранный — его название, несколько — «Выбрано: n».
- В выпадающем списке только отдельные чекбоксы и кнопка общего действия. Не дублировать название «Теги» и не добавлять общий чекбокс «Все».
- Кнопка общего действия компактная, слева, с обводкой, по ширине текста. Не растягивать на весь список. При частичном выборе — «Выбрать все»; при полном — «Снять выбор» у тегов, «Оставить один» у маркетплейсов.
- Выпадающий список равен ширине поля и помещается в боковой панели. В демо фактическая ширина 212 px, кнопка высотой 28 px.
- Пустой/невалидный выбор маркетплейсов в URL нормализуется до всех. Пустой выбор тегов отличается от отсутствующего параметра.
- Комбинации фильтров и вид сохраняются при перезагрузке и возврате из деталей. «Сбросить» очищает фильтры, сохраняя вид. Производственный URL не должен зависеть от `sidebar=2`.

## Таблица и плитки

- Все строки товаров и групп имеют одинаковую ширину в пределах текущего размера окна; заголовки и значения выровнены по общей сетке. Не растягивать колонки на всё широкое окно.
- Чекбокс находится между левым краем строки и фотографией; не накладывается на фотографию. В плитке её существующий чекбокс сверху сохранён.
- В колонке маркетплейса только значок, без дублирующей подписи Ozon/Wildberries. Доступное имя и подсказка с названием сохраняются. В плитках название маркетплейса не убиралось.
- Начиная с «Маркетплейс», **заголовки и содержимое** колонок центрированы. Проверять обе части: utility-класс заголовка может перекрыть общее CSS-правило.
- После последней правки таблица в демо: 1060 px; при ширине окна <=1200 px — 980 px. Ширина колонки товара 300/220 px соответственно. Внутренние горизонтальные отступы ячеек 8 px.
- Колонки: выбор 32, товар 300/220, маркетплейс 100, цена 88, минимум 96, средняя 88, выгода 156, наличие 144, действия 56 px.
- Наличие и действия закреплены справа при прокрутке. Отступ закреплённого наличия — 56 px, согласован с шириной действий. Три точки должны целиком помещаться в ячейке с отступом от края (в измеренном демо около 13 px).
- «Нет в наличии» должно целиком помещаться с отступами с обеих сторон; его надпись длиннее «В наличии». Не возвращать прежнюю узкую колонку.
- В плитках все числовые цены, включая выгоду, имеют размер 14 px. «Сейчас не выгодно» — 13 px, обычное начертание 400, приглушённый серый цвет. Положительная выгода остаётся выделенной.
- Последняя проверенная типографика: в списке цены и наличие 14 px; в плитке цены 14 px, наличие 12 px. Вопрос о размерах был уточнением: требования сделать наличие в плитке 14 px не было.
- Горизонтальная прокрутка ограничена таблицей, не всей страницей. Поддерживаемый текущим приложением минимум — 1024 px. Сохранять виртуализацию и измерения строк при смене вида/ширины окна.

## Неоднозначности и ограничения, которые нельзя потерять

1. **Счётчик.** Текст согласован, но текущий код берёт `orderedItems.length / allItems.length`. Это позиции каталога: группа считается за одну, входящие в неё карточки отдельно не считаются. Галочки массового выбора на этот счётчик не влияют. Перед production-внедрением определить ожидаемую единицу подсчёта; не выдавать позиции каталога за проверенный подсчёт всех товаров.
2. **Группы и теги.** Демо наследует фильтрацию группы по её представителю. Остальные участники не фильтруются отдельно; доступные теги также собираются по верхним позициям/представителям. Сортировка участников меняется вместе с общей сортировкой. Изменение поиска/фильтрации на «любой участник группы» не согласовывалось; проверить явно в production-плане.
3. **Переход по бренду.** Возврат из деталей по ссылке «К карточкам» сохраняет контекст. Нажатие бренда сейчас ведёт на чистый каталог (в демо с `sidebar=2`), поэтому оно сбрасывает URL-фильтры. Отдельного требования сохранять их на этом переходе нет.
4. **Макет не равен нативной интеграции.** Прогресс тестируется mock-сбором; Chrome/настройки имитируются. Нативная сборка подтверждает компиляцию, но не поведение окна, системного трея, автозапуска и реального сборщика.
5. **План демо отстаёт от последних мелких правок.** В `tasks.md` остались исторические формулировки про сравнение вариантов/удаление заголовка; актуальный итог — один выбранный вариант и заголовок «Карточки товаров». `design.md`/`proposal.md` не перечисляют всю финальную геометрию/типографику. Для переноса брать итоговые требования выше и delta-spec, не выполнять ранние формулировки буквально.
