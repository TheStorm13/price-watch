# UI-спецификация анализатора цен

## 1. Назначение

Локальное desktop-приложение позволяет управлять карточками маркетплейсов,
запускать сбор актуальных цен и анализировать историю. Интерфейс реализован как
SPA на React, TypeScript и Vite внутри Tauri и работает поверх локального HTTP API.

Первая версия ориентирована на одного локального пользователя. Авторизация,
уведомления, автоматическое расписание, сопоставление одинаковых товаров разных
маркетплейсов и управление пользователями не входят в UI MVP.

## 2. Продуктовые принципы

1. Одна карточка соответствует одному маркетплейсу.
2. Основной объект интерфейса — `MarketplaceCard`, а не абстрактный товар.
3. Главный экран отвечает на три вопроса: что отслеживается, какова текущая
   цена и когда данные обновлялись.
4. История никогда не скрывается за «текущим значением»: из строки карточки
   должен быть прямой переход к графику и измерениям.
5. Ошибка одной карточки не останавливает общий сбор.
6. Интерактивная проверка площадки является явным состоянием процесса, а не
   зависшим запросом.
7. Интерфейс не показывает несуществующие возможности. WB и Яндекс Маркет могут
   отображаться как недоступные варианты до появления коннекторов.

## 3. Основные пользовательские сценарии

### 3.1 Добавление карточки

1. Пользователь нажимает «Добавить карточку».
2. Выбирает маркетплейс.
3. Вводит внешний ID карточки.
4. При желании вводит временное название и URL.
5. После сохранения новая строка появляется в списке со статусом «Нет данных».

### 3.2 Сбор всех цен

1. Пользователь нажимает «Обновить цены».
2. Backend создаёт запуск и сразу возвращает его ID.
3. UI открывает панель прогресса и опрашивает состояние запуска.
4. Когда Ozon требует участия, Chrome открывается на локальной машине, а UI
   показывает состояние «Требуется проверка».
5. Пользователь проходит проверку в Chrome и нажимает в UI «Проверка пройдена».
6. После завершения UI обновляет таблицу и показывает итоговые счётчики.

### 3.3 Сбор одной карточки

Запускается из строки таблицы или экрана карточки. Процесс идентичен общему
сбору, но содержит одну карточку.

### 3.4 Анализ истории

1. Пользователь открывает карточку.
2. Видит последнюю цену и состояние наличия.
3. Выбирает период 7, 30 или 90 дней.
4. Сравнивает текущую, минимальную, максимальную цену и середину диапазона.
5. Просматривает график и таблицу отдельных измерений.

## 4. Информационная архитектура

```text
Приложение
└── Карточки                 /cards
    └── Детали карточки      /cards/:cardId
```

Отдельный dashboard в MVP не нужен: список карточек уже является рабочим
центром приложения. Настройки также не выделяются в отдельный экран, пока у них
нет реального содержимого.

## 5. App shell

### Desktop, от 1024 px

- постоянная боковая панель слева шириной 260 px с названием **Price watch**; название — обычный текст;
- вверху панели добавление карточки, обновление всех цен и создание группы; далее фильтры;
- середина панели прокручивается независимо, внизу доступны Chrome и реальные настройки фонового сбора в desktop-режиме, импорт/экспорт;
- одна панель прогресса появляется в правом нижнем углу окна: ширина 490 px, отступы справа и снизу 28 px, максимальная высота calc(100dvh - 56px); ошибки служб и действие повтора остаются в основной области;
- добавление открывает панель слева (420 px) из каталога, пустого состояния и деталей. Редактирование остаётся справа;
- глобальные действия доступны и в деталях. Закрытие форм/настроек оставляет текущую страницу; изменение фильтра в деталях открывает каталог с сохранённым контекстом и новым условием.

### Поддерживаемые размеры

Приложение предназначено только для ПК и ноутбуков. Минимальная поддерживаемая
ширина viewport — 1024 px. Фильтры находятся в боковой панели; таблица прокручивается горизонтально внутри основной области. Mobile-композиция и нижняя навигация не
входят в область поддержки.

## 6. Экран «Карточки»

### Заголовок

- H1: «Карточки товаров»;
- только справа от него «Показано n из m товаров»: число совпавших отдельных карточек и всех карточек, включая участников групп по одному разу;
- сворачивание групп и массовый выбор галочками не меняют этот счётчик;
- ниже поиск «Название или артикул», затем слева переключатель списка/сетки;
- основные действия и меню «Импорт / экспорт» находятся в боковой панели.

Импорт открывает выбор JSON-файла и показывает до подтверждения число новых и
объединяемых карточек, добавляемых и пропускаемых наблюдений. Ошибочный файл
не меняет данные. В desktop режиме экспорт открывает системный выбор места
сохранения.

### Панель фильтров

Поиск над результатами проверяет название и внешний артикул, без внутреннего ID базы.
В боковой панели, в указанном порядке:

1. Наличие: один чекбокс «Только в наличии»; исключает отсутствие и неизвестные данные.
2. Чекбокс «Сначала товары, участвующие в выгодных предложениях» включён по умолчанию; ставит участвующих первыми перед выбранной сортировкой.
3. Сортировка: «Сначала выгодные» (по умолчанию), «Сначала дешёвые», «Сначала дорогие».
4. Выгодность: «Все предложения», «Участвуют в выгодных предложениях», «Выгодные», «Невыгодные». Участие означает включение товара в расчёт выгодных, независимо от текущей выгодности.
5. Маркетплейсы: несколько чекбоксов, по умолчанию все, обязательно хотя бы один.
6. Теги: несколько чекбоксов, достаточно одного совпадения. По умолчанию все товары, включая нетегированные; пустой выбор означает «Без тегов».

Заголовки всех столбцов таблицы переключают сортировку по возрастанию и убыванию. Направление отмечено стрелкой; порядок отражается в панели и URL. Явная сортировка не добавляет приоритет текущей выгодности. При включённом чекбоксе сначала сравнивается участие, затем выбранная колонка; при выключенном — колонка для всех товаров вместе. Неизвестные денежные значения остаются в конце каждого блока участия либо общего списка при выключенном чекбоксе. Для наличия неизвестные данные равны отсутствию.

Закрытые поля показывают «Все маркетплейсы» / «Все теги», одно название или «Выбрано: n».
В выпадающем списке только отдельные чекбоксы и компактная кнопка слева по ширине текста:
«Выбрать все», а при полном выборе — «Снять выбор» для тегов / «Оставить один» для площадок.
Список совпадает по ширине с полем и помещается внутри панели, заголовок «Теги» не повторяется.
Фильтры и вид отражаются в query string (`markets`, `tags`, `stock`, `deals`, `participationFirst`, `sort`, `q`, `view`), сохраняются при перезагрузке и возврате из деталей.
Настройки каталога автоматически сохраняются при изменениях и восстанавливаются после полного
закрытия и открытия приложения: текст поиска, все фильтры и флаги панели, сортировка
(включая колонку и направление), список/сетка и свёрнутые группы.
Хранение локальное для профиля приложения, без синхронизации между устройствами;
очистка данных приложения удаляет эти настройки. Demo использует отдельное хранилище.
При первом открытии каталога без параметров отображения восстанавливается сохранённый набор.
Ссылка хотя бы с одним явным параметром отображения задаёт весь набор: отсутствующие
параметры принимают значения по умолчанию. Назад/вперёд и последующие переходы сохраняют
смысл URL; восстановление не подменяет пользовательский сброс. Служебные параметры не сохраняются.
Повреждение или недоступность локального хранилища не мешают пользоваться каталогом;
при недоступном хранилище сохранение между запусками не гарантируется.
Выделение товаров для массовых действий и открытые диалоги временные. Период графика,
вариант и страница измерений в деталях, а также последняя открытая страница не восстанавливаются.
«Сбросить» появляется справа от переключателя списка/плиток при активных условиях и сохраняет вид. Сортировка по обновлению удалена.
Сброс условий тоже сохраняется между запусками; вид и свёрнутые группы остаются выбранными.

### Таблица

Колонки:

1. чекбокс выбора карточки;
2. `Карточка` — фото, название, теги и статусы, без артикула;
3. `Выгода`;
4. `Цена`;
5. `Минимальная`;
6. `Средняя`;
7. `Маркетплейс` — только значок с доступным названием и подсказкой;
8. `Наличие`;
9. меню действий.

Правила отображения:

- цена форматируется в российских рублях без копеек, если значение целое;
- `null` отображается как «—», а не `0`;
- `in_stock` — «В наличии»;
- `out_of_stock` — «Нет в наличии»;
- `unknown` — «Неизвестно»;
- отсутствие истории — «Нет данных»;
- в обычной плитке относительное время («5 минут назад») сопровождается точной датой в tooltip; в строках списка и заголовках групп время не показывается;
- вся строка кликабельна и открывает детали;
- действие «Обновить» доступно из меню строки;
- действие «Не учитывать в выгодных предложениях» меняет `deals_enabled`, но не удаляет историю.
- исключённая карточка участвует в сборе, но не показывается в выгодных предложениях;

### Визуальное оформление карточек и групп

Группа обозначается иконкой папки, подписью «Группа» и числом товаров.
Название, теги представителя и статусы занимают отдельные области заголовка.
Длинное название переносится, теги ограничены шириной своей области;
полный текст тега доступен в tooltip.

У раскрытой группы общий скруглённый контур: верхние углы у заголовка,
нижние — у последнего участника. Синий маркер слева и лёгкая подложка
объединяют состав. Нижняя граница нейтральная. У свёрнутой или пустой группы
скруглены все внешние углы заголовка. Редактирование и раскрытие доступны
отдельными кнопками, включая управление клавиатурой.

Между самостоятельными карточками и группами одинаковый интервал 8 px,
радиус внешних углов — 10 px. В списке фон между строками совпадает с фоном
страницы. Вложенные строки группы соединены; между рядами её плиток — 8 px.
Границы определяются по полному составу отображаемых строк и сохраняются
при виртуальной прокрутке.

Фото в списке и сетке скруглены с радиусом 8 px и сохраняют пропорции.
В списке область превью — 68 × 68 px, вертикальные отступы ячеек — 4 px.
Высота строки зависит от содержимого, поэтому длинные теги и статусы
не обрезаются ради фиксированной высоты.

### Большие каталоги

Список, сетка и раскрытые группы показывают видимое окно элементов с запасом;
все результаты доступны прокруткой. Поиск и сортировка работают с полным снимком.
Выбор вне окна сохраняется; клавиатура, меню и подтверждения удерживают владельца
фокуса, а возврат из деталей восстанавливает контекст и позицию. Редактор групп
также ограничивает видимые кандидаты и сохраняет полный состав после поиска.
Прогресс сбора обновляет свою панель, не перерисовывая неизменившиеся карточки.

### Массовые действия

В режиме списка чекбокс слева от каждой карточки, в том числе внутри группы,
позволяет выбрать несколько карточек. Выбор сохраняется при поиске, фильтрации,
сортировке и сворачивании группы. Панель показывает число выбранных карточек и
позволяет снять выбор.

Для выбранных карточек доступны создание новой группы, добавление в существующую
группу, включение и исключение из выгодных предложений, удаление. При добавлении
в существующую группу её прежние карточки и теги сохраняются. Карточки из других
групп переносятся в выбранную группу с сохранением истории цен.

Массовое удаление требует отдельного подтверждения с предупреждением, что вся
история выбранных карточек будет удалена без восстановления. При частичной
ошибке панель сообщает, какие карточки не обработаны, и оставляет их выбранными
для повторной попытки.

В диалоге создания и редактирования группы можно искать карточки по названию
или внешнему ID и сортировать по названию в обоих направлениях. Поиск и
сортировка меняют только показанный список: выбранные карточки остаются в
составе группы, даже если скрыты поиском. Диалог показывает число выбранных и
предупреждает о переносе карточек из других групп.

### Показатели групп, фильтры и сортировка

Группа объединяет товары. Каждый участник проверяется на всю комбинацию фильтров;
совпадения разных участников не складываются. Группа видна при хотя бы одном совпадении,
раскрываются только подходящие участники. Резюме показывает «n из m товаров».

Представитель — первый подходящий товар по текущей сортировке. Его цена, минимум,
средняя, выгода, наличие, маркетплейс и теги используются вместе. При изменении
фильтров или сортировки представитель меняется. Редактор получает полный исходный
состав, поэтому сохранение не удаляет скрытых участников. Теги для фильтра берутся
из всех карточек; собственные теги группы остаются отдельными метаданными.

По умолчанию сначала сравнивается участие в выгодных, затем выгода по убыванию,
затем наличие и цена. Чекбокс приоритета участия действует перед любой выбранной
сортировкой; после отключения все товары сортируются вместе. Неизвестные цены
идут в конце каждого блока участия или общего списка при отключённом чекбоксе. Список, плитка и участники группы используют один порядок.
Серверные поля представителя в API остаются снимком по существующему контракту;
UI выбирает представителя по полному каталогу локально, не изменяя сохранённые данные.

Таблица фиксирована: 1060 px (980 px при окне <=1200 px), строки одинаковой ширины,
отступы ячеек 8 px, колонка товара 300/220 px. Выбор 32 px перед фото, маркетплейс 100,
цены 88/96/88, выгода 156, наличие 144, действия 56 px. Наличие и меню закреплены справа.
Начиная с маркетплейса заголовки и значения центрированы. В плитках числовые цены,
включая резюме группы, 14 px; «Сейчас не выгодно» — серый текст 13 px / 400.

### Состояния

#### Loading

Скелетон сохраняет геометрию заголовка, фильтров и 6 строк таблицы. Не
используется полноэкранный spinner.

#### Empty

Текст: «Карточек пока нет».

Подсказка: «Добавьте первую карточку маркетплейса, чтобы начать собирать
историю цены».

Действие: «Добавить карточку».

#### Filtered empty

Текст: «По выбранным условиям ничего не найдено».

Действие: «Сбросить фильтры».

#### Error

Короткое сообщение об ошибке загрузки и кнопка «Повторить». Технический stack
trace пользователю не показывается.

## 7. Добавление карточки

Форма открывается в правой drawer-панели.

Поля:

1. `Маркетплейс` — обязательный select;
2. `ID карточки` — обязательное текстовое поле;
3. `Название` — необязательное поле;
4. `URL` — необязательное поле.

Сбор доступен для Ozon и AliExpress. AliExpress использует отдельные поля ID
товара и SKU; полная .ru-ссылка с sku_id заполняет оба поля. SKU обязателен,
пара передаётся строкой productId:skuId. Остальные площадки можно добавить с
подписью «Сбор цен пока недоступен».

Валидация:

- marketplace и external ID не могут быть пустыми;
- Ozon ID состоит из ASCII-цифр;
- AliExpress ID товара и SKU состоят из ASCII-цифр; URL должен соответствовать
  обоим ID и содержать единственный sku_id;
- URL, если задан, должен быть абсолютным HTTP(S) URL;
- конфликт `(marketplace, external_id)` отображается как ошибка поля, а не
  общее уведомление.

Состояния кнопки: «Добавить», «Добавление…», disabled при невалидной форме.
После успеха drawer закрывается, строка появляется в списке и получает короткое
неблокирующее подтверждение.

## 8. Экран карточки

### Верхняя область

- возврат к списку;
- название карточки;
- маркетплейс и внешний ID;
- действия «Обновить» и меню настройки выгодных предложений.

### Текущее состояние

Открытая горизонтальная область, не набор вложенных карточек:

- текущая цена — главный визуальный акцент;
- наличие;
- время последнего измерения;
- середина диапазона `(минимум + максимум) / 2` за выбранный период;
- минимум и максимум вторичным рядом.

### График цены

- линейный график `observed_at → price`;
- периоды 7 / 30 / 90 дней;
- разрывы при `price = null`, без подстановки нуля;
- tooltip показывает дату, цену и наличие;
- линия середины диапазона отображается пунктиром;
- ось Y охватывает видимый диапазон цен с отступом 10%; подряд идущие
  одинаковые цены представлены только первой точкой;
- при одном измерении показывается точка и объясняющий текст;
- при отсутствии данных отображается спокойное пустое состояние.

### История измерений

Таблица под графиком:

- дата и время;
- цена;
- наличие.

Показываются первые 50 строк с постраничной загрузкой. График использует
все изменения цены за период, независимо от текущей страницы таблицы.

## 9. Ошибки сбора

Отдельного экрана запусков нет. После сбора с ошибками панель состояния показывает
точное число ошибок и до 20 примеров только последнего созданного запуска.
Технические подробности ограничены и раскрываются отдельно. При `limited` UI
поясняет сокращение; при `expired` сообщает, что подробности очищены после нового
запуска. Очистка не означает отсутствие сбоев. Кнопка «Повторить ошибки и оставшиеся»
использует сохранённые результаты целей независимо от примеров. Сами запуски и
их счётчики сохраняются во внутренней базе.

## 10. Панель активного сбора

Панель отображается поверх текущего экрана, но не блокирует навигацию.

### `queued` / `running`

- заголовок «Обновление цен»;
- обработано `N из M`;
- progress bar;
- текущий маркетплейс и внешний ID, если backend их сообщает.

### `waiting_for_user`

Этот статус возможен у worker, запущенного без скрытого дисплея. Desktop
сбор при проверке завершается с ошибкой; после ручной проверки в Chrome
пользователь повторяет сбор.

- заметный, но не тревожный статус «Требуется проверка в Chrome»;
- инструкция: «Завершите проверку в открывшемся Chrome, затем продолжите»;
- основная кнопка «Проверка пройдена»;
- вторичная кнопка «Отменить запуск» появится только после поддержки отмены на
  backend; в MVP она не отображается.

### Завершение

- успешный итог: «Цены обновлены»;
- частичный итог: «Обновление завершено с ошибками»;
- счётчики успешных и неуспешных карточек;
- при ошибках — раскрываемые подробности и кнопка «Повторить ошибки»;
- кнопка «Закрыть».

UI обновляет данные карточек после завершения через invalidation server-state
кэша, а не вручную изменяет отдельные строки.

## 11. Визуальное направление

Характер: спокойный аналитический инструмент, а не маркетинговый dashboard.

- фон приложения: светло-серый `#F6F7F9`;
- основные поверхности: настоящий белый `#FFFFFF`;
- основной текст: графитовый `#17191C`;
- вторичный текст: `#667085`;
- границы: `#E4E7EC`;
- основной action: насыщенный синий `#2563EB`;
- наличие/успех: зелёный `#16803C`;
- предупреждение: янтарный `#B54708`;
- ошибка: красный `#B42318`;
- sidebar: глубокий графит `#15171A` без градиента;
- табличные числа используют tabular numerals;
- радиусы: 8 px для контролов, 12 px для drawer и крупных областей;
- тени применяются только для overlay-поверхностей;
- декоративные badges, bento-сетка, glassmorphism и лишние градиенты не
  используются.

Типографика:

- UI: Inter или совместимый локальный sans-serif fallback;
- H1: 28/34, 650;
- H2: 20/28, 650;
- основной текст: 14/20, 400;
- controls: 14/20, 550;
- подписи и таблица: 13/18;
- цена на detail: 36/42, 650, tabular numerals.

Иконки — единое outline-семейство со stroke 1.75 px. Они используются только
для навигации и понятных действий, всегда имеют текстовый `aria-label` или
видимую подпись.

## 12. Motion

- drawer: 180–220 ms ease-out;
- изменение progress bar: 200 ms linear;
- обновлённая строка может получить одно мягкое фоновое выделение на 600 ms;
- график появляется без декоративной длинной анимации;
- `prefers-reduced-motion` отключает все необязательные переходы.

## 13. Доступность

- WCAG 2.2 AA по контрасту и клавиатурной навигации;
- видимый `focus-visible` для всех интерактивных элементов;
- drawer удерживает фокус и возвращает его инициатору после закрытия;
- статусы не кодируются только цветом;
- прогресс активного запуска имеет `aria-live="polite"`;
- ошибки формы связаны с полями через `aria-describedby`;
- таблицы имеют корректные заголовки и подпись;
- основные интерактивные controls имеют область не меньше 40×40 px.

Принципы React:

- `App` содержит только композицию providers и router;
- server state не копируется в глобальный client state;
- локальное состояние формы и drawer остаётся рядом с компонентом;
- загрузка карточек, истории и запусков оформляется отдельными query hooks;
- мутации инвалидируют связанные queries;
- тяжёлый модуль графика загружается только на detail route;
- компоненты не объявляются внутри других компонентов;
- derived values вычисляются во время render, а не синхронизируются через
  `useEffect`;
- фильтры URL являются единственным источником состояния списка.

## 15. Технический стек

- React + TypeScript;
- Vite;
- React Router для client-side маршрутов;
- библиотека server-state запросов с дедупликацией и invalidation;
- CSS Modules и общие CSS tokens, без тяжёлого UI-kit;
- библиотека доступных headless-примитивов только для dialog/drawer/menu;
- SVG chart library, загружаемая лениво;
- Vitest + React Testing Library;
- Playwright для основных пользовательских сценариев.

В desktop-разработке Vite обслуживает интерфейс Tauri на порту 1420. Адрес и
токен локального API передаются через Tauri; браузерный E2E-стенд использует
mock API. В клиентский bundle могут попадать только переменные с префиксом
`VITE_`; `DATABASE_URL` и другие секреты остаются исключительно на backend.

## 17. Требуемый HTTP API

### Карточки

```text
GET    /api/cards
GET    /api/cards/export
POST   /api/cards/import/preview
POST   /api/cards/import
POST   /api/cards
GET    /api/cards/{cardId}
PATCH  /api/cards/{cardId}
DELETE /api/cards/{cardId}
GET    /api/cards/{cardId}/history?days=30&page=1&pageSize=50
GET    /api/cards/{cardId}/chart?days=30
```

`PATCH` используется для `dealsEnabled`, названия и URL. Удаление карточки требует
подтверждения; карточку незавершённого запуска удалить нельзя.

### Запуски

```text
GET   /api/runs?page=1&pageSize=50
GET   /api/runs/{runId}
POST  /api/runs                  body: { cardId?: number }
POST  /api/runs/{runId}/continue
```

`POST /api/runs` отвечает `202 Accepted` и не удерживает HTTP-соединение до
завершения браузерного сбора. UI опрашивает `GET /api/runs/{runId}` раз в одну
секунду во время активного процесса и прекращает polling после terminal status.

Пример состояния запуска:

```json

  "successCount": 1,
  "failureCount": 0,
  "current": {
    "cardId": 2,

    "externalId": "1604900984"
  },
  "challenge": {
    "type": "browser_verification",
    "message": "Завершите проверку в открывшемся Chrome"

```

## 18. Реализация backend

Backend реализован на FastAPI, SQLAlchemy 2, Alembic и PostgreSQL. Сбор выполняет
отдельный локальный worker, а Ozon открывается через Playwright. API использует
camelCase DTO, структурированные ошибки и не передаёт в браузер `DATABASE_URL`,
путь профиля Chrome. Traceback ошибок сбора доступен в панели состояния обновления.

## 19. Формат ошибок API

```json
{
  "error": {
    "code": "card_already_exists",
    "message": "Такая карточка уже добавлена",
    "field": "externalId",
    "requestId": "..."
  }
}
```

UI принимает решения по `code`, а не разбирает текст сообщения.

## 20. Критерии готовности UI MVP

1. Пользователь может добавить Ozon-карточку или конкретный SKU AliExpress без терминала.
2. Список показывает последнюю цену и корректно различает `0`, `null` и
   отсутствие истории.
3. Можно запустить сбор всех карточек и одной карточки.
4. Состояние проверки площадки явно отображается и продолжается из UI.
5. Ошибка одной карточки не ломает весь экран и не скрывает успешные результаты.
6. Detail screen показывает статистику, график и историю 7/30/90 дней.
7. Фильтры и сортировка сохраняются в URL.
8. Интерфейс полностью управляется клавиатурой и проходит базовые проверки
   accessibility.
9. Desktop viewport от 1024 px не имеет горизонтального overflow всей страницы.
10. Unit, component и ключевые Playwright-сценарии проходят стабильно.

## 21. Статус реализации

Desktop UI, HTTP API, PostgreSQL-очередь, worker и Playwright-коннектор
реализованы. Tauri запускает локальные службы и подключает интерфейс к API.
Vite dev server используется внутри desktop-разработки и отдельно для
браузерных E2E с mock API.
